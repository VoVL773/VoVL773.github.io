> 一道面试高频送命题。这篇文章要做的，是帮你把那种“说不清但能感觉到”的直觉，变成一句能说清楚的话。

面试官：“递归和回溯有什么区别？”

你：“回溯……就是用递归去试错吧？”

面试官点点头，没说话。你也不知道自己说对了没有。

这个场景太常见了。大多数人并不是不知道它们不一样——你心里其实清楚：归并排序和全排列虽然都用了递归，写起来的感觉却完全不同。一个顺顺当当往下拆，一个总在小心翼翼地“改回去”。

可一旦要你用一句话说清楚，就卡住了。

卡住的原因很简单：几乎所有教程都在告诉你“回溯用递归实现”，却很少有人告诉你——**递归只是骨架，真正让回溯成为回溯的，是那个看起来最不起眼的动作：撤销。**

递归是**实现手段**，回答的是“代码怎么写”；回溯是**算法思想**，回答的是“问题怎么解”。归并排序是纯递归，全排列才是回溯：前者没有任何“撤销”动作，后者少写一行 `pop()`，答案就全乱了。

## 0. 先把概念摆正：递归和回溯不在一个层次上

初学者的最大混淆点，是把它们当成两个并列的、“二选一”的东西。其实它们回答的是两个完全不同的问题：

| 维度 | 递归（Recursion） | 回溯（Backtracking） |
| --- | --- | --- |
| 是什么 | 一种**编程手段**：函数调用自身 | 一种**搜索策略**：在解空间里试探，走不通就退 |
| 层次 | 语法 / 结构层 | 算法思想层 |
| 关系 | 是**实现工具** | **用递归来实现** |
| 类比 | 像“循环” | 像“枚举 + 剪枝” |

放到同一张图里看，它们根本不在同一层：

```text
算法思想层（回答“问题怎么解”）
├─ 暴力枚举 / 搜索
│     └─ 回溯 = 决策树 + DFS + 撤销 + 剪枝
├─ 分治
└─ 动态规划
        │
        │ 都可以用递归落地（DP 也常用递推 / 记忆化搜索）
        ▼
程序实现层（回答“代码怎么写”）
├─ 递归：函数调用自身 + 调用栈
└─ 迭代 + 显式栈（递归的等价改写）
```

一句话记住：

> **回溯 = 递归 + 撤销选择（状态恢复）**

纯递归不一定要撤销（求阶乘、斐波那契、树的前序遍历都不需要）；**需要“撤销”的递归，才是回溯。**

> 光看定义不好体会。下面用两道真题做对照：LeetCode 695（纯递归）与 LeetCode 46 全排列（回溯）。

## 1. 递归：把问题交给小一号的自己

### 1.1 递归的本质：把问题缩小成同类子问题

递归能成立，靠的是一个信念：

> **如果子问题解决了，那么当前问题就解决了。**

以 `n!` 为例：

- 大问题：`3!` 是多少？
- 小一号的同类问题：`2!` 是多少？
- 关系：`3! = 3 × 2!`

只要 `2!` 能被算出来，`3!` 就出来了。而 `2!` 又依赖于 `1!`……一直退到 `0! = 1`（到这一层不用再缩了，答案直接就知道）。

于是递归自然成形：

```python
def factorial(n):
    if n == 0:          # 终止条件：不用再缩了
        return 1
    return n * factorial(n - 1)    # 递推关系：把 n 的问题变成 n-1 的问题
```

### 1.2 递归三要素

写任何递归之前，先回答这三个问题：

| 要素 | 问自己 | 全排列里对应什么 |
| --- | --- | --- |
| **终止条件** | 什么时候不用再递归了？ | `len(path) == len(nums)` |
| **递推关系** | 当前问题怎么靠子问题解决？ | 选一个数，再递归填下一个位置 |
| **本层做什么** | 这一层需要处理的、不交给子问题的事 | 遍历候选、做选择、撤销选择 |

**新手最常犯的错：写递归时试图在脑子里跑完整棵树。** 那是徒劳的，原因见 1.4。

### 1.3 执行模型：调用栈

递归的真实执行，是运行时替你维护了一个“调用栈”。以 `factorial(3)` 为例：

```text
【递】压栈：一层层往下调用
factorial(3)
└─ 3 * factorial(2)
   └─ 2 * factorial(1)
      └─ 1 * factorial(0)
         └─ return 1      ← 触底（终止条件）

【归】弹栈：触底后一层层返回，逐层算结果
         ┌─ 1 * 1 = 1
      ┌─ 2 * 1 = 2
   ┌─ 3 * 2 = 6
└─ factorial(3) = 6
```

也就是说，递归有**两个阶段**，一定要分清：

| 阶段 | 动作 | 类比 |
| --- | --- | --- |
| **递** | 一层层往下调用，压栈 | 往下走 |
| **归** | 触底后一层层返回，弹栈 | 往回退 |

### 1.4 为什么人脑模拟递归会晕——以及“递归信条”

因为你在用**串行思维**去模拟一个**栈结构**。心理学上的估计是：人一次只能稳稳握住 4 个左右的“组块”（Miller 的经典说法是 7±2），而递归树很快就超出这个量级。

正确的姿势是**信任递归**（编程界叫 “recursion fairy” / 递归信条）：

> **写 `backtrack()` 的时候，就假设“它的子调用一定能正确完成它该做的事”。**
> 你只负责两件事：
>
> 1. 这一层该做什么（做选择、撤销选择）；
> 2. 什么时候停（终止条件）。
>
> **不要去展开子调用内部是怎么跑的。**

这就像写 `for` 循环时你不会去想“第 3 次迭代时 CPU 寄存器是什么”——你相信循环会按语义执行。递归也一样。

### 1.5 递归的两种思维模式

| 模式 | 怎么想 | 典型题 |
| --- | --- | --- |
| **分解式**（自顶向下） | 大问题 = 小问题 + 一步 | 阶乘、斐波那契、归并排序 |
| **遍历式**（搜索） | 在一棵树上走，每到一个节点做判断 | **回溯**、DFS、树的遍历 |

**回溯属于“遍历式”**：你不是在“计算一个值”，而是在“遍历一棵决策树，收集符合条件的节点”。这个视角转换非常重要——用“求值”的思路去做回溯，必然卡住。

### 1.6 纯递归实例：LeetCode 695 岛屿的最大面积

先看一个**不需要撤销**的递归，作为后面回溯的对照：

```python
class Solution:
    def maxAreaOfIsland(self, grid: list[list[int]]) -> int:
        """LeetCode 695：纯递归（DFS 洪水填充）"""
        if not grid or not grid[0]:
            return 0

        rows, cols = len(grid), len(grid[0])
        sign_map = {}          # 记录“这个格子已经访问过”，避免重复计数和死循环

        def dfs(i, j):
            # 越界、是水(0)、或已经访问过 → 这一格不贡献面积，返回 0
            if (i < 0 or i >= rows or j < 0 or j >= cols
                    or grid[i][j] == 0
                    or sign_map.get((i, j))):
                return 0

            sign_map[(i, j)] = True     # 标记已访问（这里不需要撤销）
            # 自己算 1 格，再加上下左右四个方向递归回来的面积
            return 1 + dfs(i+1, j) + dfs(i-1, j) + dfs(i, j+1) + dfs(i, j-1)

        max_area = 0
        for i in range(rows):
            for j in range(cols):
                # 遇到“没访问过的陆地”，就从这里出发把整块量一遍
                if grid[i][j] == 1 and not sign_map.get((i, j)):
                    max_area = max(max_area, dfs(i, j))
        return max_area
```

注意 `sign_map` **故意不撤销**：一个格子只需要被统计一次，撤销标记反而会导致重复计数、指数级回溯。

对比一下就清楚了：`sign_map` 是“**全局只允许用一次**”的标记；而下一节全排列里的 `used` 是“**每条路径各允许用一次**”，所以必须撤销。这条判别口诀在 2.7 和最后的总结里还会各出现一次。

> 顺带一提：朴素斐波那契也是纯递归，只是存在大量重复计算——那是动态规划要解决的问题，与回溯无关。

## 2. 回溯：在决策树上试错

### 2.1 回溯解决什么问题

一句话：**在一棵“决策树”上，找出所有满足条件的路径（或节点）。**

典型特征：

- 答案是**一组**，不是一个数；
- 需要**枚举所有可能**；
- 每一步有**多个候选**，且选了一个会影响后面的候选；
- 规模不大（通常 n ≤ 20 左右，因为复杂度是指数级的）。

常见题型：全排列、子集、组合、分割字符串、N 皇后、解数独、复原 IP、单词搜索。

### 2.2 解空间树（决策树）

把“每一步的选择”画成一棵树：根是初始状态，每条边是一个选择，叶子是最终状态（有些题里中间节点也是答案）。

**这棵树的大小，决定了算法的复杂度上限。** 回溯的本质就是**遍历这棵树**，边走边记录路径。

以全排列（`nums = [1,2,3]`）为例，决策树长这样：

```text
path = []
├─ 选 1 → [1]
│   ├─ 选 2 → [1,2]
│   │   └─ 选 3 → [1,2,3]   ✅
│   └─ 选 3 → [1,3]
│       └─ 选 2 → [1,3,2]   ✅
├─ 选 2 → [2]
│   ├─ 选 1 → [2,1]
│   │   └─ 选 3 → [2,1,3]   ✅
│   └─ 选 3 → [2,3]
│       └─ 选 1 → [2,3,1]   ✅
└─ 选 3 → [3]
    ├─ 选 1 → [3,1]
    │   └─ 选 2 → [3,1,2]   ✅
    └─ 选 2 → [3,2]
        └─ 选 1 → [3,2,1]   ✅

（同一层缩进 = 同一次选择；共 6 个叶子，就是 6 个排列）
```

想要拿到全部 6 个叶子，就必须在“走完一条分支”之后**退回分叉点**，再换下一个候选。这个动作就是回溯。

### 2.3 回溯 = 递归 + 撤销选择

我们盯着 `path = [1]` 这一层看。它下面的 `for` 循环要做两件事：先探索“选 2”的分支，回来后探索“选 3”的分支。

```text
depth1 的 for 循环（此时 path=[1]，1 已经定下来了）：

  ┌─ i=1 取 2 ─→ path=[1,2] ─→ 递归走完 ─→ pop() 撤销 2 ─→ path=[1]
  └─ i=2 取 3 ─→ path=[1,3] ─→ 递归走完 ─→ pop() 撤销 3 ─→ path=[1]
       ↑
       这就是“换候选 3”：i=1 那条分支（[1,2,3]）走完并撤销后，同一层取下一个候选
```

所以从 `[1,2]` 到 `[1,3]` 是**两步**，不是一步：

```text
[1,2]  --pop()-->  [1]  --push(3)-->  [1,3]
       撤销 2           换候选
```

把 `for` 循环体看成“一回合”，它的节拍是固定的三步：

```text
① 做选择   used[i] = True、path.append(nums[i])
      │
      ▼
② 递归     backtrack()：把这条分支的全部后续走完
      │
      ▼
③ 撤销     path.pop()、used[i] = False
      │
      ├─ 还有候选 ─→ 回到 ①（for 进入下一轮）
      └─ 候选用尽 ─→ return，回到上一层
```

> **关键结论：`path.pop()` 写在 `for` 循环体的末尾，作用是“把本轮的选择清掉”，好让下一轮从干净的状态重新开始。**

对应到代码里，就是这三行：

```python
for i in range(n):
    if used[i]: continue
    used[i] = True           # ① 出手：做选择
    path.append(nums[i])
    backtrack()              # ② 打完：递归探索所有后续
    path.pop()               # ③ 收手：撤销，把位置还回去
    used[i] = False
    # ── 回合结束，下一轮从这里带着干净的状态重新开始 ──
```

#### 少写一行 `pop()`，会发生什么？

**下一轮就不是“替换”，而是“追加”。** 两种情况的差别一图可见：

```text
写了 pop()：替换
  [1,2] ──pop() 撤销 2──▶ [1] ──push(3)──▶ [1,3]            ✅

没写 pop()：追加
  [1,2] ──直接接上 3──▶ [1,2,3,3] ──再往下──▶ [1,2,3,3,2,…]  ❌
```

实测（`nums = [1,2,3]`，只删掉 `path.pop()`，其余不变），`path` 的变化是这样的：

```text
path=[]
选 1 → path=[1]                  ← 第 1 次 append
选 2 → path=[1,2]                ← 第 2 次
选 3 → path=[1,2,3]              ← 第 3 次：收集到答案后返回
选 3 → path=[1,2,3,3]            ← 第 4 次：不是“替换”，而是“追加”
选 2 → path=[1,2,3,3,2]
选 2 → path=[1,2,3,3,2,2]
选 1 → path=[1,2,3,3,2,2,1]
……  path 只增不减，递归一路加深，直到 RecursionError
```

后果有两条，而且都很致命：

1. **结果集里只剩 `[1,2,3]` 一个答案**——因为此后 `path` 只增不减，长度再也不会等于 n，`len(path) == n` 这个终止条件彻底失效；
2. **递归一路加深**，`path` 无限制膨胀，最终以 `RecursionError`（栈溢出）收场。

> **所以“回溯”这个动作的本质是：每探索完一个分支，就把状态恢复到进入该分支之前的样子。**
> 恢复得越干净，各分支之间就越互不干扰——这正是“回溯”这个名字的来源。

**而 `path.pop()`，正是状态恢复的命根子。**

### 2.4 全排列：完整代码

```python
class Solution:
    def permute(self, nums: list[int]) -> list[list[int]]:
        n = len(nums)
        res = []
        path = []
        used = [False] * n

        def backtrack():
            # ① 终止条件：路径长度够了 → 拼出一个完整答案
            if len(path) == n:
                res.append(path[:])     # 必须拷贝，否则最后全是空列表
                return

            # ② 在候选集合里逐个尝试
            for i in range(n):
                if used[i]:             # 这个数已在本路径里，跳过（剪枝）
                    continue

                # ③ 做选择
                used[i] = True
                path.append(nums[i])

                # ④ 递归：带着刚才的选择，去填下一个位置
                backtrack()

                # ⑤ 撤销选择（回溯！）—— 撤回到进入 ③ 之前的状态
                path.pop()
                used[i] = False

        backtrack()
        return res
```

两个容易写错的地方：`res.append(path[:])` 一定要切片拷贝，否则结果里全是同一个列表的引用；`path.pop()` 与 `used[i] = False` 必须同时出现，缺一个都会让状态在分支之间“串味”。

### 2.5 回溯通用模板

所有回溯题，都是这个骨架（伪代码，中文标识符只为好记）。**背下来。**

```text
def solve(题目参数):
    结果集 = []
    路径 = []

    def backtrack(路径, 选择列表相关参数):
        if 满足结束条件:
            结果集.append(路径[:])          # 记得拷贝
            return

        for 选择 in 选择列表:
            if 需要剪枝(选择):              # 可选
                continue

            做选择(路径, 选择)              # ① 修改状态
            backtrack(路径, 下一层的参数)   # ② 递归
            撤销选择(路径, 选择)            # ③ 恢复状态  ← 与 ① 严格对称

    backtrack(初始路径, 初始参数)
    return 结果集
```

做题时，逐个填空四要素：

| 要素 | 问自己 |
| --- | --- |
| **路径** | 我要收集的是什么？（组合、排列、切割方案……） |
| **选择列表** | 当前这一步有哪些候选？ |
| **结束条件** | 什么时候算一个完整答案？ |
| **剪枝** | 哪些分支明显不可能，可以提前砍掉？ |

套到常见题型上，差异其实只在几个细节：

| 题型 | 候选集合 | 结束条件 | 是否用 `used` | 关键差异 |
| --- | --- | --- | --- | --- |
| **排列**（46） | 所有未使用的数 | `len(path) == n` | ✅ 用 | 顺序有关，`[1,2]` 和 `[2,1]` 不同 |
| **组合**（77） | `start` 之后的数 | `len(path) == k` | ❌ 不用 | 顺序无关，靠 `start` 保证不回头 |
| **子集**（78） | `start` 之后的数 | **无**（每个节点都是答案） | ❌ 不用 | 边遍历边收集，不用等到叶子 |
| **分割**（131） | 从 `start` 起的切点 | `start == len(s)` | ❌ 不用 | 边切边判断合法性 |
| **棋盘**（51 N 皇后） | 当前行的每一列 | `row == n` | ✅ 用（列 / 对角线） | 二维选择 + 合法性校验 |

> 复杂度心里要有数：全排列约 `O(n·n!)`，子集约 `O(n·2ⁿ)`；另外别忘了 `path[:]` 拷贝本身的开销，它常常是复杂度里的主导项之一。

### 2.6 什么时候该想到回溯？（判据清单）

出现下列信号，基本就该上回溯：

- 要求**枚举所有方案 / 所有可行解 / 所有组合方式**（“请返回所有……”）；
- 求解过程可以表示成**一串选择**，且每个选择会缩小后续可选范围；
- 需要**试错**：某个选择可能导致后面走不通，必须能“退回来换一个”；
- 问题规模不大但组合爆炸（n ≤ 10~20 的排列 / 子集类），暴力 + 剪枝刚好够用；
- 要求最优解，但没法用 DP（状态无法压缩，或需要输出具体方案而不仅是数值）。

反过来：“能用递推关系描述、子问题答案可以直接合并”→ 用普通递归 / 分治；“子问题大量重叠且有最优子结构”→ 上动态规划。

### 2.7 最容易踩的几个坑

| 坑 | 错误写法 | 修正 |
| --- | --- | --- |
| 忘了撤销，或撤销位置错 | 改了状态就 `return`，跳过 `pop()` | 让“做选择”和“撤销”严格对称地待在递归调用两侧 |
| 结果全是空列表 | `res.append(path)` | `res.append(path[:])` |
| `continue` 跳过了撤销 | 状态已改，才在 `if` 里 `continue` | `continue` 必须发生在做选择**之前** |
| 终止条件忘了收集答案 | `if 结束: return` | 先 `append` 再 `return` |
| 该撤销的和不该撤销的搞混 | 图 DFS 里撤销了 `visited` | 全局只用一次的不撤销（`visited`），每条路径各用一次的必须撤销（`used`） |
| 去重漏解 / 多解（如 47） | 只判 `nums[i] == nums[i-1]` | 先排序，再加 `and not used[i-1]` |

---

## 3. 总结

- **递归**是机制：靠调用栈把问题分解为同类子问题，信息通过**返回值**向上流动，对应数学归纳法。
- **回溯**是策略：把求解变成决策树上的 DFS，靠**做选择 → 递归 → 撤销选择**在共享状态上系统化地试错，靠**剪枝**把暴力变得可用。
- 二者是“手段”与“思想”的关系：**回溯通常由递归承载，但递归远不止于回溯**。

判断一段代码到底是不是回溯，只需要问一句：**它有没有一份“所有分支共享、改完必须改回去”的状态？**

```text
有没有一份“所有分支共享、改完必须改回去”的状态？
├─ 有 ──────────────────────→ 回溯（used 必须撤销）
├─ 没有，只有参数和返回值 ──→ 纯递归（如归并排序）
└─ 有，但故意不撤销 ────────→ 遍历（如图 DFS 的 visited）
```

最后用一句最朴素的话收尾：

> **递归是把问题变小，回溯是把选择试遍；前者要“相信子问题”，后者要“记得擦脚印”。**
