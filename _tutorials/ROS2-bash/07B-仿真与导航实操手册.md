> **这份文档解决什么问题**
>
> 你照着《ROS2机器人开发：从入门到实践》做第七章，会发现书里的仿真命令**一条都跑不通**：
> 书基于 **ROS 2 Humble + Gazebo Classic**，而你的系统是 **Ubuntu 24.04 + ROS 2 Jazzy**，
> 官方搭配的仿真器变成了 **Gazebo Harmonic**（命令是 `gz sim`），

> 按顺序照着做就能把第七章的**全部实例**跑起来（仿真 → ros2_control → SLAM 建图 → Nav2 导航 → 代码发目标）。

## 0. 开始之前

### 0.1 环境确认

```bash
# 系统与 ROS
lsb_release -d          # 期望：Ubuntu 24.04.x LTS
echo $ROS_DISTRO        # 期望：jazzy（没输出就先 source，见 0.2）

# 仿真器
source /opt/ros/jazzy/setup.bash
gz sim --version        # 期望：Gazebo Sim, version 8.15.0
```


### 0.2 每开一个新终端，第一件事

```bash
source /opt/ros/jazzy/setup.bash
```


> ⚠️ **这一步不能省。** 不 source 的话，`gz` 只会列出 `help` 和 `sdf` 两个子命令，
> 敲 `gz sim` 会吐一段帮助文本，看起来像"没装 sim"——其实只是 `GZ_CONFIG_PATH` 没被补全。
>
> 嫌麻烦就把这行写进 `~/.bashrc` 末尾。

### 0.3 装齐依赖（一次就够）

```bash
# 第 1~7 步（仿真）需要的：本机已全部具备，这条只是确认

                 ros-jazzy-robot-state-publisher ros-jazzy-joint-state-publisher-gui \
                 ros-jazzy-rviz2 ros-jazzy-teleop-twist-keyboard

# 第 8 步（ros2_control）——本机还没装

# 第 9~12 步（SLAM + 导航）——本机还没装
sudo apt install ros-jazzy-slam-toolbox ros-jazzy-navigation2 ros-jazzy-nav2-bringup
```


### 0.4 和原教程（Gazebo Classic）的对应关系

全书命令的"翻译表"，做的时候对不上就来这里查：

| 书里（Humble + Classic） | **你这里（Jazzy + Harmonic）** |
|---|---|
| `sudo apt install gazebo` | `sudo apt install ros-jazzy-ros-gz` |
| `gazebo 世界.world` | `gz sim -r 世界.sdf` |
| `gazebo --verbose -s libgazebo_ros_init.so -s libgazebo_ros_factory.so` | **不需要**（改成显式桥接） |
| `ros2 run gazebo_ros spawn_entity.py -entity X -file Y` | `ros2 run ros_gz_sim create -world default -topic robot_description -name X` |
| `libgazebo_ros_diff_drive.so` + `<ros><remapping>` | `gz-sim-diff-drive-system` + `parameter_bridge` |
| `libgazebo_ros_ray_sensor.so` | `<sensor type="gpu_lidar">` + 桥 `/scan` |
| `wheel_diameter` | **`wheel_radius`**（半径，填错里程计差一倍） |
| `libgazebo_ros2_control.so` | `libgz_ros2_control-system.so` |
| `gazebo_ros2_control/GazeboSystem` | `gz_ros2_control/GazeboSimSystem` |

## 第 2 步：写模型文件

> 这一步是第七章 §1~§8 的产物。如果你已经跟着笔记做过建模，可以直接把已有的文件
> 拷进来（但**务必补上 `<collision>` 和 `<inertial>`**，不然进 Gazebo 会穿模/乱飞）。
>
> 下面给的是一套**能直接跑通的完整版**，可直接照抄。
> 与你 `笔记/var/` 里那几份草稿相比，修正了：`parame` 拼写、`imu_link` 名字对不上、

### 2.1 `urdf/fishbot/common_inertia.xacro`

惯量公式统一放这里，其它文件 include 它。

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

    <!-- 长方体：x/y/z 是三条边长，m 是质量 -->
    <xacro:macro name="box_inertia" params="m x y z">
        <inertial>
            <origin xyz="0 0 0" rpy="0 0 0"/>
            <mass value="${m}"/>
            <inertia ixx="${m*(y*y+z*z)/12}" ixy="0" ixz="0"
                     iyy="${m*(x*x+z*z)/12}" iyz="0"
                     izz="${m*(x*x+y*y)/12}"/>
        </inertial>
    </xacro:macro>

    <!-- 圆柱：默认轴沿 Z；如果模型里把圆柱转了，用 rpy 把惯量一起转 -->
    <xacro:macro name="cylinder_inertia" params="m r h rpy:='0 0 0'">
        <inertial>
            <origin xyz="0 0 0" rpy="${rpy}"/>
            <mass value="${m}"/>
            <inertia ixx="${m*(3*r*r+h*h)/12}" ixy="0" ixz="0"
                     iyy="${m*(3*r*r+h*h)/12}" iyz="0"
                     izz="${m*r*r/2}"/>
        </inertial>
    </xacro:macro>

    <!-- 球 -->
    <xacro:macro name="sphere_inertia" params="m r">
        <inertial>
            <origin xyz="0 0 0" rpy="0 0 0"/>
            <mass value="${m}"/>
            <inertia ixx="${2*m*r*r/5}" ixy="0" ixz="0"
                     iyy="${2*m*r*r/5}" iyz="0"
                     izz="${2*m*r*r/5}"/>
        </inertial>
    </xacro:macro>

</robot>
```


> 💡 `rpy:='0 0 0'` 是 xacro 宏参数的**默认值**写法（`:=` 后面跟默认值）。
> 不传就用默认，传了就用传的。

### 2.2 `urdf/fishbot/base.urdf.xacro`

车身 + 导航用的虚拟根 `base_footprint`。

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:include filename="common_inertia.xacro"/>

    <xacro:macro name="base_xacro" params="length radius">

        <!-- ① 导航用的"贴地虚拟根"：Nav2 要求机器人有一个 z=0 的根坐标系 -->
        <link name="base_footprint"/>

        <!-- ② 车身本体 -->
        <link name="base_link">
            <visual>
                <origin xyz="0 0 0" rpy="0 0 0"/>
                <geometry>
                    <cylinder radius="${radius}" length="${length}"/>
                </geometry>
                <material name="white">
                    <color rgba="1.0 1.0 1.0 0.8"/>
                </material>
            </visual>

            <!-- 仿真必须有 collision，否则会直接穿过地面 -->
            <collision>
                <origin xyz="0 0 0" rpy="0 0 0"/>
                <geometry>
                    <cylinder radius="${radius}" length="${length}"/>
                </geometry>
            </collision>

            <!-- 仿真必须有 inertial，否则物理引擎会警告并给个乱猜的质量 -->
            <xacro:cylinder_inertia m="1.0" r="${radius}" h="${length}"/>
        </link>

        <joint name="base_joint" type="fixed">
            <parent link="base_footprint"/>
            <child link="base_link"/>
            <!-- 车身抬高到 ${length/2 + 0.01}，让轮子刚好着地 -->
            <origin xyz="0 0 ${length/2 + 0.01}" rpy="0 0 0"/>
        </joint>

    </xacro:macro>
</robot>
```


> 💡 **`base_footprint` 是干嘛的**
>
> 它是机器人在地面上的"投影点"，z 恒为 0。
> 里程计、SLAM、Nav2 全都以它为基准，TF 链是 `map → odom → base_footprint → base_link`。
> 少了它，Nav2 会报坐标系找不到（笔记 §16.2 第 20 条）。

### 2.3 `urdf/fishbot/wheel.urdf.xacro`

驱动轮。**两个地方最容易写错**：圆柱要转 90°、要有 collision/inertial。

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:include filename="common_inertia.xacro"/>

    <xacro:macro name="wheel_xacro" params="wheel_name xyz">
        <link name="${wheel_name}_wheel_link">
            <visual>
                <!-- 圆柱默认轴沿 Z；绕 X 转 90° 后轴变成 Y，才能绕 Y 滚动 -->
                <origin xyz="0 0 0" rpy="1.5707963 0 0"/>
                <geometry>
                    <cylinder radius="0.032" length="0.02"/>
                </geometry>
                <material name="yellow">
                    <color rgba="1.0 1.0 0.0 1.0"/>
                </material>
            </visual>

            <collision>
                <origin xyz="0 0 0" rpy="1.5707963 0 0"/>
                <geometry>
                    <cylinder radius="0.032" length="0.02"/>
                </geometry>
            </collision>

            <!-- rpy 要和上面一致，惯量才跟着转过去 -->
            <xacro:cylinder_inertia m="0.05" r="0.032" h="0.02" rpy="1.5707963 0 0"/>
        </link>

        <joint name="${wheel_name}_wheel_joint" type="continuous">
            <origin xyz="${xyz}"/>
            <parent link="base_link"/>
            <child link="${wheel_name}_wheel_link"/>
            <axis xyz="0 1 0"/>
        </joint>

        <!-- 橡胶胎要有抓地力，不然原地打滑、里程计乱飘 -->
        <gazebo reference="${wheel_name}_wheel_link">
            <mu1 value="20.0"/>
            <mu2 value="20.0"/>
            <kp value="1000000000.0"/>
            <kd value="1.0"/>
        </gazebo>
    </xacro:macro>
</robot>
```

                <geometry>
                    <box size="0.02 0.10 0.02"/>
                </geometry>
                <material name="green">
                    <color rgba="0.0 1.0 0.0 0.8"/>

### 2.8 `urdf/fishbot/plugins/gazebo_control_plugin.xacro`

差速驱动插件（Harmonic 的写法，**不再有 `<ros><remapping>`**）。

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:macro name="gazebo_control_plugin">
        <gazebo>
            <plugin filename="gz-sim-diff-drive-system"
                    name="gz::sim::systems::DiffDrive">
                <left_joint>left_wheel_joint</left_joint>
                <right_joint>right_wheel_joint</right_joint>

                <!-- 运动学：轮距与轮半径，正逆解和里程计都靠它俩 -->
                <wheel_separation>0.20</wheel_separation>
                <wheel_radius>0.032</wheel_radius>

                <odom_publish_frequency>30</odom_publish_frequency>

                <!-- ★ 必须显式写！默认是 "<模型名>/base_footprint"，
                     也就是 fishbot/base_footprint，而 URDF 里机器人根是 base_footprint
                     —— 两段接不上，TF 会变成两棵独立的树。 -->
                <child_frame_id>base_footprint</child_frame_id>

                <max_linear_acceleration>1.0</max_linear_acceleration>
                <min_linear_acceleration>-1.0</min_linear_acceleration>
                <max_angular_acceleration>2.0</max_angular_acceleration>
                <min_angular_acceleration>-2.0</min_angular_acceleration>
                <max_linear_velocity>0.5</max_linear_velocity>
                <min_linear_velocity>-0.5</min_linear_velocity>
                <max_angular_velocity>1.0</max_angular_velocity>
                <min_angular_velocity>-1.0</min_angular_velocity>
            </plugin>
        </gazebo>
    </xacro:macro>
</robot>
```


> ⚠️ **`wheel_radius` 是半径，不是直径。**
> 书里（Classic）写的是 `wheel_diameter`，这里换了名字也换了含义。
> 填错的话里程计直接差一倍——机器人"自信地"走错位置，但看起来一切正常。

> ⚠️ **`child_frame_id` 为什么必须写**（Harmonic 最容易踩的坑之一）
>
> Harmonic 的 DiffDrive 插件默认给 TF 坐标系加**模型名前缀**，
> 发出来的是 `fishbot/odom → fishbot/base_footprint`。
> 而 URDF 里机器人根是 `base_footprint`，robot_state_publisher 发的是**不带前缀**的。
> 结果 TF 变成**两棵互不相连的树**：
>
> ```
> fishbot/odom → fishbot/base_footprint     ← 差速插件发的（悬空，没有下游）
> base_footprint → base_link → ...          ← URDF 发的（没有上游 odom）
> ```
>
> **症状**：`ros2 topic list` 里 `/tf` 明明有数据，但
> - RViz 里 `LaserScan` 一直刷 `No transform from [fishbot/base_footprint/laser_sensor]`
> - `Odometry` 显示画不出来
> - `tf2_echo odom base_footprint` 报 **"not part of the same tree"**
>
> **修法**：加 `<child_frame_id>base_footprint</child_frame_id>`。
>
> ★ 注意 `odom` 帧名在 Harmonic 里**改不了**——插件根本没有这个参数，
> 写死成 `<模型名>/odom`。所以 RViz 的 `Fixed Frame` 要填 **`fishbot/odom`**，
> 不是 `odom`。这一点和第 7.4 节配套看。

> ⚠️ **传感器的 `gz_frame_id` 同理。**
> 不写的话 `/scan` 的 `frame_id` 是 `fishbot/base_footprint/laser_sensor`
> （模型名 + 父链 + 传感器名拼起来的），和 URDF 里的 `laser_link` 对不上，
> RViz 里点云/扫描永远画不出来。三个传感器都要写：
>
> ```xml
> <sensor name="laser_sensor" type="gpu_lidar">
>     <gz_frame_id>laser_link</gz_frame_id>     <!-- ★ 让它等于 URDF 里的 link 名 -->
>     ...
> ```
>
> 验证：`ros2 topic echo /scan --once | grep frame_id` 应该打出 `laser_link`。

>

> 然后开始怀疑人生。
>
> **验证改动到底有没有生效**（这一步很重要）：
>
> ```bash

> # 能 grep 到 → 生效了；grep 不到 → 没同步
> ```
>
> **强制重建这个包**：
>
> ```bash
> rm -rf build/fishbot_description install/fishbot_description
> colcon build --packages-select fishbot_description
> ```
>
> 💡 记一条经验：**"编译成功"不等于"改动生效"**。
> 改完配置文件/模型文件，永远去 `install/` 里确认一眼。

## 第 6 步：写仿真总启动文件

### 6.1 `launch/gazebo_sim.launch.py`

这一个文件把"启动 Gazebo + 生成机器人 + 发状态 + 桥接话题 + 开 RViz"全串起来。

```python
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription, RegisterEventHandler
from launch.event_handlers import OnProcessExit
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import Command
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg_share = get_package_share_directory('fishbot_description')

    xacro_file = os.path.join(pkg_share, 'urdf', 'fishbot', 'fishbot.urdf.xacro')
    world_file = os.path.join(pkg_share, 'world', 'fishbot.sdf')
    robot_description = ParameterValue(Command(['xacro ', xacro_file]), value_type=str)

    model_name = 'fishbot'

    # ① 启动 Gazebo Harmonic
    #    注意：gz_sim.launch.py 没有 world 参数，世界是通过 gz_args 传的
    gz_sim = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(get_package_share_directory('ros_gz_sim'),
                         'launch', 'gz_sim.launch.py')),
        launch_arguments={'gz_args': '-r ' + world_file}.items())

    # ② URDF -> /robot_description
    robot_state_publisher = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        parameters=[{'robot_description': robot_description,
                     'use_sim_time': True}],
        output='screen')

    # ③ 从 /robot_description 把机器人生成到世界里
    spawn_entity = Node(
        package='ros_gz_sim',
        executable='create',
        arguments=['-world', 'default',
                   '-topic', 'robot_description',
                   '-name', model_name,
                   '-z', '0.3'],
        output='screen')

    # ④ 桥接：gz 话题 <-> ROS 话题
    #    方向符： [ = gz→ROS    ] = ROS→gz    @ = 双向
    bridge = Node(
        package='ros_gz_bridge',
        executable='parameter_bridge',
        arguments=[
            # 仿真时钟（Gazebo 出，ROS 收）
            '/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock',

            # 差速驱动：速度指令 ROS→gz，里程计和 TF 是 gz→ROS
            f'/model/{model_name}/cmd_vel@geometry_msgs/msg/Twist]gz.msgs.Twist',
            f'/model/{model_name}/odometry@nav_msgs/msg/Odometry[gz.msgs.Odometry',
            f'/model/{model_name}/tf@tf2_msgs/msg/TFMessage[gz.msgs.Pose_V',

            # 传感器
            '/scan@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan',
            '/imu@sensor_msgs/msg/Imu[gz.msgs.IMU',
        ],
        remappings=[
            # 把 gz 那套名字映射成 ROS 里通用的名字
            (f'/model/{model_name}/cmd_vel',  '/cmd_vel'),
            (f'/model/{model_name}/odometry', '/odom'),
            (f'/model/{model_name}/tf',       '/tf'),
        ],
        parameters=[{'use_sim_time': True}],
        output='screen')

    # ⑤ ★ 给 odom 起个别名，把 `odom` 接到 `fishbot/odom` 上
    #
    #   为什么需要：
    #     Harmonic 的 DiffDrive 插件把 odom 帧写死成 "<模型名>/odom"，
    #     没有参数能改（只有 child_frame_id 能改）。
    #     但 slam_toolbox（第 9 步）默认 odom_frame = "odom"，
    #     它找不到 odom 帧就永远等不到变换 ——
    #     结果是【每一帧 /scan 都被丢掉、/map 一帧都不发】。
    #     表面看 slam_toolbox 正常启动、/map 话题也在，就是没有地图。
    #
    #   加这个恒等变换后 TF 链变成：
    #     map → odom → fishbot/odom → base_footprint → base_link → laser_link
    odom_alias = Node(
        package='tf2_ros',
        executable='static_transform_publisher',
        name='odom_alias',
        arguments=['--frame-id', 'odom',
                   '--child-frame-id', f'{model_name}/odom'],
        parameters=[{'use_sim_time': True}],
        output='screen')

    # ⑥ RViz
    rviz = Node(
        package='rviz2',
        executable='rviz2',
        parameters=[{'use_sim_time': True}],
        output='screen')

    return LaunchDescription([
        gz_sim,
        robot_state_publisher,
        spawn_entity,
        bridge,
        odom_alias,
        rviz,
    ])
```


> 💡 **为什么 gz 话题要 remap**
>
> DiffDrive 插件天然发的是 `/model/fishbot/odometry`、`/model/fishbot/tf`，
> 但 ROS 生态（RViz、SLAM、Nav2）**只认 `/odom` 和 `/tf`**。
> 不做 remap 的典型症状：`ros2 topic list` 里明明有数据，RViz 里就是一个坐标系都没有。
>
> ⚠️ **`/model/fishbot/tf` 的 gz 类型是 `gz.msgs.Pose_V`**（不是 `TFMessage`），
> 这是最容易抄错的一个。

    load_joint_state_broadcaster = Node(

        executable='spawner',
        arguments=['fishbot_joint_state_broadcaster', '--controller-manager-timeout', '30'],
        output='screen')

    load_diff_drive_controller = Node(
        package='controller_manager',
        executable='spawner',
        arguments=['fishbot_diff_drive_controller', '--controller-manager-timeout', '30'],

        gz_sim,

                target_action=spawn_entity,
                on_exit=[load_joint_state_broadcaster])),
        # 等第一个控制器加载完 → 再加载第二个
        RegisterEventHandler(
            event_handler=OnProcessExit(
                target_action=load_joint_state_broadcaster,
                on_exit=[load_diff_drive_controller])),
    ])
```

> 否则会互相抢服务接口导致启动异常。`RegisterEventHandler` + `OnProcessExit` 就是官方的串行化手段。

```

> 因为 Harmonic 的 DiffDrive 插件**根本没有 odom 帧名的参数**
> （只有 `child_frame_id` 能改），写死成 `<模型名>/odom`。
> 加一个恒等静态变换 `odom → fishbot/odom` 最省事，
> 而且顺带让 RViz 的 Fixed Frame 可以直接填 `odom`。

> 💡 **地图画歪了 / 糊了，查这三条**
> 1. **里程计**：`odom → base_footprint` 准不准（轮距轮半径填错，地图必歪）

**`fishbot_nav_client/fishbot_nav_client/nav_to_pose.py`**：

```python
import rclpy
from geometry_msgs.msg import PoseStamped
from nav2_simple_commander.robot_navigator import BasicNavigator, TaskResult


def make_pose(navigator, x, y, yaw_w=1.0):
    """造一个 map 坐标系下的目标点"""
    pose = PoseStamped()
    pose.header.frame_id = 'map'
    pose.header.stamp = navigator.get_clock().now().to_msg()
    pose.pose.position.x = x
    pose.pose.position.y = y
    pose.pose.orientation.w = yaw_w
    return pose


def main():
    rclpy.init()
    navigator = BasicNavigator()

    # ① 给初始位姿（等价于 RViz 里的 2D Pose Estimate）
    initial = make_pose(navigator, 0.0, 0.0)
    navigator.setInitialPose(initial)

    # ② 等 Nav2 完全就绪（这一步不能省，否则第一个目标会失败）
    navigator.waitUntilNav2Active()

    # ③ 单点导航
    goal = make_pose(navigator, 2.0, 0.5)
    navigator.goToPose(goal)

    while not navigator.isTaskComplete():
        feedback = navigator.getFeedback()
        if feedback:
            print(f'剩余距离 {feedback.distance_remaining:.2f} m')

    result = navigator.getResult()
    if result == TaskResult.SUCCEEDED:
        print('到达目标点')
    elif result == TaskResult.CANCELED:
        print('被取消')
    else:
        print('导航失败')

    # ④ 路点巡航（巡检的基础）
    waypoints = [
        make_pose(navigator, 2.0,  0.5),
        make_pose(navigator, 2.0, -0.5),
        make_pose(navigator, 0.0,  0.0),
    ]
    navigator.followWaypoints(waypoints)
    while not navigator.isTaskComplete():
        pass
    print('路点巡航结束')

    navigator.lifecycleShutdown()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

## 附录 B：一键自查脚本

```bash
#!/usr/bin/env bash
# 仿真链路逐层自查
source /opt/ros/jazzy/setup.bash >/dev/null 2>&1

echo "===== 1. gz 侧话题（仿真器自己有没有在动）====="
gz topic -l 2>/dev/null | grep -E 'clock|fishbot|scan|imu' | sort || echo "  ❌ 一个都没有"

echo

timeout 5 gz topic -e -t /clock -n 1 2>/dev/null | head -3 || echo "  ❌ /clock 读不到"

echo
echo "===== 3. ROS 侧话题（桥起来了没）====="
ros2 topic list 2>/dev/null | grep -E 'cmd_vel|odom|tf|scan|imu' | sort || echo "  ❌ 桥没起"

echo
echo "===== 4. 数据频率 ====="
for t in /scan /odom /imu; do
  printf '  %-8s ' "$t"
  timeout 5 ros2 topic hz "$t" 2>/dev/null | grep -m1 'average rate' || echo "无数据"
done

echo
echo "===== 5. TF 链 ====="
timeout 5 ros2 run tf2_ros tf2_echo fishbot/odom base_footprint --ros-args -p use_sim_time:=true 2>&1 | grep -m1 -A1 'Translation' \
  || echo "  ❌ odom → base_footprint 不通"
timeout 5 ros2 run tf2_ros tf2_echo base_footprint base_link 2>&1 | grep -m1 -A1 'Translation' \
  || echo "  ❌ base_footprint → base_link 不通"

echo
echo "===== 6. 仿真时间 ====="
ros2 param get /robot_state_publisher use_sim_time 2>/dev/null || echo "  ⚠️ 查不到，确认节点名"
```


**判读方法**：哪一层开始报 ❌，问题就在那里——
第 1 层是模型/世界，第 3 层是桥接，第 4~5 层是桥接参数或 `use_sim_time`。

## 附录 C：`ros2 node list` 是空的（共享内存坑）

### 症状

程序明明在跑（turtlesim 打印了 "Spawning turtle"，仿真窗口也开着），
但另一个终端里：

```bash
ros2 node list      # 什么都不输出
ros2 topic list     # 只有 /parameter_events /rosout
```


终端里还刷这种错：

```
[RTPS_TRANSPORT_SHM Error] Failed init_port fastrtps_port7002:
    open_and_lock_file failed -> Function open_port_internal
```


### 原因

Fast DDS 用 `/dev/shm/fastrtps_*` 这些**共享内存段**做本机进程间通信。
进程被**强杀**（`kill -9` / `pkill -9` / 任务管理器结束进程）时，
共享内存段**不会被清理**，就一直堆在 `/dev/shm` 里。

攒多了之后，新进程建不出段、也协商不出可用传输，
**DDS 发现就断了** —— 表现就是"节点在跑，但谁也看不见谁"。

> ⚠️ **这就是为什么不要随便 `kill -9`。**
> `Ctrl+C`（SIGINT）和 `kill`（SIGTERM）会给进程执行清理代码的机会，
> `kill -9`（SIGKILL）不给 —— 快是快，但会留垃圾。

### 确认

```bash
ls /dev/shm/ | grep -c '^fastrtps_'     # 堆了几十个就中招了
```


### 解决

**用现成的脚本**（本手册配套，放在 `~/dsh工作区/ros-clean.sh`）：

```bash
bash ~/dsh工作区/ros-clean.sh          # 安全模式：只删没被占用的
bash ~/dsh工作区/ros-clean.sh --all    # 彻底模式：先杀 ROS 进程再全清
```


**或者手动**（只删没被占用的，不会影响正在跑的程序）：

```bash
for f in /dev/shm/fastrtps_*; do
    [ -e "$f" ] || continue
    fuser "$f" >/dev/null 2>&1 || rm -f "$f"
done
pkill -f "[r]os2-daemon"      # 顺手重启 daemon，它缓存了旧的图信息
```


> 💡 `pkill -f "[r]os2-daemon"` 里的方括号是必须的：
> `pkill -f` 会匹配**自己的命令行**，写 `ros2-daemon` 的话它会把自己也杀掉。
> 写成 `[r]os2-daemon` 后，自己的 cmdline 里是字面量 `[r]os2-daemon`，
> 正则匹配不到，就安全了。

### 预防

1. **停程序用 `Ctrl+C`**，不要直接关终端窗口、不要 `kill -9`
2. 实在要强杀，杀完跑一次 `bash ~/dsh工作区/ros-clean.sh`
3. 万一手头没脚本，最快的绕过办法是**关掉共享内存传输**：

   ```bash
   export FASTDDS_BUILTIN_TRANSPORTS=UDPv4     # 只用 UDP，发现立刻正常
   ```

   缺点是本机通信性能差一点（UDP 比共享内存慢），
   临时救急用，别写进 `~/.bashrc`。
