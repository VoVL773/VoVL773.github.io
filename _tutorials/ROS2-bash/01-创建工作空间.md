### 1、创建 ROS 2 包

先了解创建包的命令：

```bash
ros2 pkg create [-h] [--package-format {2,3}] [--description DESCRIPTION] [--license LICENSE]
                       [--destination-directory DESTINATION_DIRECTORY] [--build-type {cmake,ament_cmake,ament_cargo,ament_python}]
                       [--dependencies DEPENDENCIES [DEPENDENCIES ...]] [--maintainer-email MAINTAINER_EMAIL]
                       [--maintainer-name MAINTAINER_NAME] [--node-name NODE_NAME] [--library-name LIBRARY_NAME]
                       package_name
```


其中：

- **方括号 `[]` 中的是可选参数**；
- **`package_name` 是必需的参数**，即要创建的包名。

示例：

```bash
ros2 pkg create --build-type ament_python --license Apache-2.0 demo_python_pkg
```


参数说明：

- `--build-type ament_python`：以 Python 的形式创建该包；
- `--license Apache-2.0`：使用 Apache-2.0 开源许可证。

> 💡 **知识点：`--build-type` 的三种取值**
>
> | 取值 | 用途 |
> |---|---|
> | `ament_python` | 纯 Python 包，用 `setup.py` 描述构建 |
> | `ament_cmake` | C++ 包，用 `CMakeLists.txt` 描述构建 |
> | `cmake` | 纯 CMake 包（不依赖 ament），很少用 |
>
> **不写 `--build-type` 时默认是 `ament_cmake`**。这一点很重要：后面自定义消息接口必须用 `ament_cmake`，所以创建接口包时可以省略该参数，但**显式写出来更不容易搞混**。
>
> ⚠️ **注意**：Python 包和 C++ 包**不能混着建**，一个包只能是其中一种。

> 💡 **知识点：`--dependencies` 一次帮你改三个文件**
>
> 加上 `--dependencies rclpy std_msgs` 后，`ros2 pkg create` 会自动：
> 1. 在 `package.xml` 里写入 `<depend>rclpy</depend>` 等依赖声明；
> 2. 在 `setup.py`（Python 包）或 `CMakeLists.txt`（C++ 包）里写入对应的查找/安装语句；
> 3. 于是你就不用手工补了。
>
> 但如果**事后**才发现少写了依赖，就得自己改这两个文件，缺一不可。

> 这里只介绍使用过程中会用到的部分，其余内容之后可能会补充。

### 2、编写节点代码并配置

**1. 编写代码**

在 `demo_python_pkg` 目录下编写节点代码。

示例：

```python
import rclpy
from rclpy.node import Node

def main():
    rclpy.init()          # 初始化 rclpy 客户端库（管理通信、分配资源），注意：这不是"创建节点"
    node = Node("python_node")   # 真正创建节点对象，名字叫 python_node

    # 日志分五个级别：debug / info / warn / error / fatal
    # 默认终端只显示 info 及以上；warn 也可以用 .warning（推荐写法，.warn 是旧别名）
    node.get_logger().info("这是一个普通信息")
    node.get_logger().warn("这是一个警告信息")
    node.get_logger().error("这是一个错误信息")

    rclpy.spin(node)      # 阻塞在这里，循环处理该节点的所有回调（订阅、定时器、服务……）
                          # 直到 Ctrl+C 或节点被关闭才会往下走
    rclpy.shutdown()      # 关闭 rclpy，释放通信资源（正常退出和异常退出都会走到这里）

if __name__ == "__main__":
    main()
```


> 💡 **知识点：`rclpy.init()` 和 `Node()` 是两件事**
>
> - `rclpy.init()` 初始化的是 **rclpy 这个客户端库**（加载 DDS、创建上下文），整个进程调用**一次**即可；
> - `Node("名字")` 才是创建**节点对象**。一个进程里可以有多个节点（比如后面 Qt 那个例子里就有）。
>
> 原笔记把 `rclpy.init()` 注释成"初始化节点"是不准确的，容易和 `Node()` 混淆。

> ⚠️ **注意**：上面补了 `if __name__ == "__main__": main()`。
> 原笔记漏了这句。虽然通过 `setup.py` 的入口点启动时会直接调用 `main`，但如果你想**直接 `python 文件名.py` 调试**，没这句什么都不会发生。

> 💡 **知识点：`rclpy.spin()` 到底在干什么**
>
> 它是**阻塞式的事件循环**。节点不是"自动运行"的——你注册的每个回调（订阅收到消息、定时器到点、服务被调用）都排队等着，`spin()` 就是那个不断取出并执行它们的循环。
>
> 这也解释了一个后面会踩的坑：**`spin()` 是单线程的**，如果你在某个回调里写了个耗时/阻塞的操作，其它所有回调都会被卡住。详见 [四.3 客户端](#3客户端定时请求目标点) 里的分析。

**2. 声明依赖**

在 `package.xml` 中写入所需的依赖库，例如：

```xml
<depend>rclpy</depend>
```


**3. 配置入口点**

在 `setup.py` 中写入入口点信息，指定可执行文件与要运行的函数：

```python
entry_points={
    'console_scripts': [
        'python_node = demo_python_pkg.python_node:main'
    ],
},
```


格式说明：

```
可执行文件名 = 包名.文件名:函数名
```


- `python_node`：生成的可执行文件名；
- `demo_python_pkg.python_node`：模块路径（包名.文件名）；
- `main`：要运行的函数名。

即：指明该可执行文件运行的是哪个函数。

> 💡 **知识点：`package.xml` 和 `setup.py` 各管什么**
>
> | 文件 | 管什么 | 不写会怎样 |
> |---|---|---|
> | `package.xml` | **依赖声明**（给 ROS 的构建/运行系统看） | 依赖装不上，`import` 失败 |
> | `setup.py` | **构建与安装规则**（入口点、资源文件放哪） | `ros2 run` 找不到可执行文件 |
>
> 两者是**配合关系**，不是二选一。新手最常见的报错 `Package 'xxx' not found` 或 `No executable found`，基本都出在这两个文件上。

### 3、编译与运行

**1. 编译**

```bash
colcon build
```


编译完成后会生成 `install` 产物目录，`build` 为中间产物目录，`log` 为日志目录。

> 💡 **知识点：`colcon build` 的三个目录**
>
> - `build/`：编译中间产物（CMake 缓存等），**可以删**，删了要重新编译；
> - `install/`：最终产物，`ros2 run` 真正去找东西的地方；
> - `log/`：每次构建的日志，**编译报错时先来这里翻**，比终端刷屏的报错完整得多。
>
> **调试期建议用 `colcon build --symlink-install`**：它让 `install/` 里的文件软链回源码。这样改了 Python 代码**不用重新编译**，直接重跑节点就生效，能省下大量时间。C++ 包仍然需要重新编译。

**2. 配置环境变量**

运行 `install` 目录下的 `setup.bash` 完成一键环境变量配置：

```bash
source install/setup.bash
```


> ⚠️ **注意：`source` 只在当前终端有效**
>
> 每开一个**新终端**都要重新 `source` 一次，否则 `ros2 run` 会找不到你的包。嫌麻烦可以把下面这行加到 `~/.bashrc`（通常在文件末尾）：
>
> ```bash
> source ~/你的工作空间路径/install/setup.bash
> ```
>
> 另外，工作空间**换了位置或改了目录名**后必须重新 `colcon build` + 重新 source，因为 `setup.bash` 里写的是绝对路径。

**3. 运行节点**

```bash
ros2 run demo_python_pkg python_node
```


即运行 `demo_python_pkg` 包下的 `python_node` 节点。

## 流程小结

```
创建包 → 写代码 → 声明依赖(package.xml) → 配置入口(setup.py)
      → colcon build → source setup.bash → ros2 run
```
