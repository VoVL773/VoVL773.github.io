## A. 勘误清单

### A.1 会直接导致报错的问题（14 处，均已在正文修正）

| # | 位置 | 原文 | 修正 | 不修的后果 |
|---|---|---|---|---|
| 1 | 人脸检测服务端 | `self.get_patamete(...)` | `self.get_parameter(...)` | `AttributeError`，节点起不来 |
| 2 | 第一个 Qt 界面 | `label.setText = ('Hello Qt!')` | `label.setText('Hello Qt!')` | 方法被覆盖成字符串，界面空白 |
| 3 | 第一个 Qt 界面 | `from pyQt5.QtWidgets` | `from PyQt5.QtWidgets` | Linux 下 `ModuleNotFoundError` |
| 4 | CMakeLists.txt | `find_package(ament_camke ...)` | `ament_cmake` | CMake 配置失败 |
| 5 | Patrol.srv | `int8 FALL = 0` | `int8 FAIL = 0` | 代码用 `Patrol.Response.FAIL` → `AttributeError` |
| 6 | demo.launch.py | `package='demo_python_service1'` | `demo_python_service` | launch 找不到包 |
| 7 | 加载参数文件 | `--ros-arg --params-file` | `--ros-args --params-file` | 参数不生效 |
| 8 | 创建发布包 | `--dependencies ... status_interface` | `status_interfaces` | 依赖解析失败 |
| 9 | 验证接口 | `chapt4_interface/srv/...` | `chapt4_interfaces` | 查不到接口 |
| 10 | SystemStatus.msg | `float32 cup_percent` | `float32 cpu_percent` | 与代码 `msg.cpu_percent` 不匹配 |
| 11 | 接口文件名 | `SyStemStatus.msg` | `SystemStatus.msg` | 与消息名大小写不一致 |
| 12 | 命令行 | `ros topic pub` / `ros topic echo` | `ros2 topic ...` | 命令不存在（`ros` 是 ROS 1） |
| 13 | 话题名 | `/tuerle1/cmd_vel`、`/turtles1/cmd_vel` | `/turtle1/cmd_vel` | 话题不存在 |
| 14 | 第一节注释 | `rclpy.init() # 初始化节点` | 初始化 rclpy 客户端库 | 概念混淆，与 `Node()` 分不清 |

### A.2 不会报错但建议改进的地方

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 1 | Patrol 客户端 | 在定时器回调里用 `while` 阻塞等 `wait_for_service` | 单线程 executor 下会卡死整个节点，改用 `service_is_ready()` 非阻塞检查 |
| 2 | Patrol 客户端/服务端 | 客户端随机 `0~14`，服务端限制 `< 12.0`，画布实际 `~11.09` | 范围对齐，如 `randint(1, 11)` |
| 3 | 小说朗读节点 | `import espeakng` 易装错包 | 正确的 pip 包名是 **`py-espeak-ng`**，且需系统装 `espeak-ng` |
| 4 | 小说朗读节点 | 线程没加 `daemon=True` | 退出时可能卡住，建议加上 |
| 5 | 小说朗读节点 | 方法名 `speake_thread` 拼写错误 | 改为 `speak_thread` |
| 6 | 多个示例 | 缺少 `if __name__ == '__main__': main()` | 无法直接 `python xxx.py` 调试 |
| 7 | 全文 | 包名在 4 个名字间跳来跳去 | 统一包名，或明确标注"本示例用 xxx 包" |
| 8 | 人脸检测 | `cv2_to_imgmsg(self.image)` 未指定 encoding | 显式写 `encoding='bgr8'`，避免颜色通道错乱 |
| 9 | 人脸检测 | `resource/` 图片未在 `setup.py` 登记 | 加 `data_files` 条目，否则 install 后找不到图 |
| 10 | 类名 | `TurtleCricleNode` / `turtleCricle_publisher` 拼写错误 | 改为 `Circle`（前后一致所以能跑，但会误导） |
| 11 | Patrol 客户端 | `random.seed(time.time())` | 多余，Python 默认已自动播种 |
| 12 | SystemStatus.msg | 内存/流量用 `float32` 存 MB | 建议改用 `uint64` 直接存字节，免换算免精度顾虑 |
| 13 | 服务概念 | "多种通信方式都是话题通信的变种" | 实现层对，但话题/服务/动作语义不同，建议分开理解 |
| 14 | 接口设计 | FaceDetector 用 4 个并行数组传人脸位置 | 字段一多容易下标错位，建议定义独立的 `.msg` 类型 |

### A.3 新增 TF 代码章节中的问题（均已在正文修正）

**会直接阻塞的问题：**

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | `setup.py` | 用了 `os.path.join` 和 `glob`，**但没补 `import os` / `from glob import glob`** | `colcon build` 直接失败：`NameError: name 'os' is not defined`（本机实测复现） |

> Jazzy 用 `ros2 pkg create` 生成的 `setup.py` 开头**只有** `from setuptools import find_packages, setup`——**没有** `os` 和 `glob`。这是很容易漏的一步。

**不会报错但会误导：**

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 2 | launch 目录名 | `lanch/demo_tf.launch.py` | 改为 `launch/`（拼写错误） |
| 3 | `tf_listener.py` | 变量名 `tranform`（少了 `s`） | 改为 `transform`（前后一致所以能跑，但会误导） |
| 4 | `tf_listener.py` | 缺 `if __name__ == '__main__': main()` | 补上，与另外两个节点保持一致 |
| 5 | 章节标题 | `### python中的坐标转化` 没编号 | 改为 `### 8、Python 代码中的坐标变换`，与该章其余小节（1~7）统一 |
| 6 | 依赖说明 | `> 安装依赖` 引用块后直接跟代码块，缺空行 | 已整理为独立小节 |

**已实测确认正确的部分**（无需改动）：

| 项 | 验证结果 |
|---|---|
| `StaticTransformBroadcaster(node)` | ✓ 签名匹配 |
| `TransformBroadcaster(node)` | ✓ |
| `Buffer()` / `TransformListener(buffer, node)` | ✓ 能跑（建议改为 `Buffer(node=self)`） |
| `lookup_transform(target, source, time, timeout)` 参数顺序 | ✓ 正确 |
| `rclpy.time.Time(seconds=0)` 表示"最新可用变换" | ✓ 正确用法 |
| 变换链最终结果 `(0.7, 0.3, 0.1)` / `(π, 0, 0)` | ✓ 与理论值完全一致 |

### A.4 新增「仿真与导航」章节中的问题（均已在正文修正）

**会直接阻塞的问题**（实测报错原文见[第七章]({{ '/tutorials/ROS2-bash/07-仿真与导航/' | relative_url }})对应小节）：

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | `first_robot.urdf` | `imu_link` 漏写 `</link>` | `XML_ERROR_MISMATCHED_ELEMENT`，`check_urdf` 直接失败 |
| 2 | `imu.urdf.xacro` | link 名 `imu_base`，joint 的 child 写 `imu_link` | `Failed to build tree: child link [imu_link] of joint [imu_joint] not found` |
| 3 | `camera.urdf.xacro` | 宏参数名 `parame="xyz"` | `xacro: Invalid parameter "xyz"` |
| 4 | `display_robot.launch.py` | `from ament_index_python.package import ...` | `ModuleNotFoundError: No module named 'ament_index_python.package'` |
| 5 | `display_robot.launch.py` | `DeclarelaunchArgument` | `AttributeError`（应为 `DeclareLaunchArgument`） |
| 6 | `display_robot.launch.py` | `launch_ros.parameterValue` | 属性不存在，正确写法 `launch_ros.parameter_descriptions.ParameterValue` |
| 7 | `CMakeLists.txt` | `DESTIANTION` | `CMake Error: install DIRECTORY given no DESTINATION!` |
| 8 | 总装文件 | 文件名 `firstbot.urdf.xacro`、内容含 `...` 省略号 | include 不到 / 模型残缺 |
| 9 | `common_inertia.xzcro` | 扩展名拼错 | include 找不到文件 |

**不会报错但会误导：**

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 10 | `base.urdf.xacro` | collision 里 `radius="${length}"` | 改成 `${radius}`，否则碰撞体比车体还大 |
| 11 | `base.urdf.xacro` | `<collision>` 里放了 `<material>` | 删除：URDF 规范里材质属于 `<visual>` |
| 12 | `wheel.urdf.xacro` | 圆柱 visual 未旋转，几何轴（z）与转轴（y）不一致 | 加 `<origin rpy="1.5707963 0 0"/>` |
| 13 | `wheel.urdf.xacro` | 轮宽 `length="0.32"`（32cm）比车体直径（20cm）还宽 | 疑为笔误，建议核对（正文保留原值） |
| 14 | `caster.urdf.xacro` | fixed 关节写了 `<axis>` | 删除：fixed 没有自由度，axis 无意义 |
| 15 | 全文代码块 | URDF 标成 ```` ```html ```` | 改为 ```` ```xml ````（URDF 是 XML，不是 HTML） |

**实测确认正确的部分**（原本看着可疑，实际没问题）：

| 项 | 验证结果 |
|---|---|
| `$(find fishbot_description)` 写法 | ✓ **正确**。xacro 只认 `find/env/optenv/dirname/arg`；把 launch 的 `$(find-pkg-share ...)` 抄进来反而报 `Unknown substitution command` |
| 同一个宏文件被 include 两次 | ✓ 不报错（xacro 重复定义宏、后者覆盖），但没必要 |
| `urdf_to_graphviz <urdf>` | ✓ 生成 `.gv` + `.pdf`；指定输出名是**第二个位置参数**，不是 `-o` |
| 完整模型 `xacro` 展开 + `check_urdf` | ✓ 解析通过，TF 结构为"1 个根 link + 7 个直接子 link" |
| `display_robot.launch.py` | ✓ `ros2 launch ... --show-args` 正常列出 `model` 参数 |

### A.5 新增「仿真与导航」部分的坑（Gazebo Harmonic / ros2_control / Nav2）

> 第 9 节的仿真命令已在**本机实测**（Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic 8.15.0）；
> `gz_ros2_control`、Nav2、slam_toolbox 本机**未安装**，按官方文档核对。
> 完整清单见[第七章]({{ '/tutorials/ROS2-bash/07-仿真与导航/' | relative_url }})第 16.2 节，这里只留最常撞上的。

| # | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 1 | `gazebo：未找到命令` | Gazebo Classic 已 EOL，24.04 没有这个包 | 改用 `gz sim`，并先 `source /opt/ros/jazzy/setup.bash` |
| 2 | `gz sim` 像没装（只有 help/sdf） | 这个终端没 source ROS，`GZ_CONFIG_PATH` 不全 | source 后用 `gz --commands` 自查 |
| 3 | 模型进仿真了，ROS 里没话题 | Harmonic 不再往仿真器塞 ROS 插件 | 起 `ros_gz_bridge/parameter_bridge` |
| 4 | 桥起了但数据不动 | 方向符写反 | `[` = gz→ROS，`]` = ROS→gz；**写反不报错** |
| 5 | 有话题但 RViz 没坐标系 | TF 桥过来是 `/model/<名>/tf` | 用 `remappings` 映射到 `/tf` |
| 6 | 里程计差一倍 | 照抄了 Classic 的 `wheel_diameter` | Harmonic 用 `wheel_radius`（半径） |
| 7 | 相机 / 雷达无数据 | 世界没挂 `Sensors` 插件 | 加 `gz-sim-sensors-system` + `ogre2` |
| 8 | IMU 无数据 | 世界没挂 IMU 插件 | 加 `gz-sim-imu-system` |
| 9 | 机器人走不直 | 万向轮摩擦没设 0 | 主动轮 `mu1/mu2=20`，万向轮 `0` |
| 10 | 相机方向不对 | 缺光学坐标系 | 加 `camera_optical_link`（`rpy="-1.5708 0 -1.5708"`） |
| 11 | 差速插件与 ros2_control 打架 | 两者抢同一批关节 | 用 ros2_control 时注释掉差速插件宏 |
| 12 | `gz_ros2_control` 报找不到库 | 照抄了 Classic 的插件名 | `gz_ros2_control/GazeboSimSystem` + `libgz_ros2_control-system.so` |
| 13 | RViz 里轮子变白 | 缺 `joint_state_broadcaster` 的 TF | 加载并激活该控制器 |
| 14 | 控制器激活失败 | launch Action 并行抢接口 | `RegisterEventHandler`+`OnProcessExit` 串行化 |
| 15 | Nav2 一直报 TF 错误 | 没给初始位姿 | RViz `2D Pose Estimate` 或发 `/initialpose` |
| 16 | 窄道过不去/撞墙 | `robot_radius` 与模型不符 | 填建模半径（本项目 0.12） |
| 17 | 地图上"走错位置" | 地图 yaml 的 `resolution`/`origin` 被手改坏 | 用 `map_saver_cli` 生成 |

## B. 常用命令速查

```bash
# ── 包与构建 ──────────────────────────────
ros2 pkg create <包名> --build-type ament_python --dependencies rclpy --license Apache-2.0
colcon build --symlink-install      # 调试期推荐，改 Python 代码免重编译
source install/setup.bash           # 每个新终端都要执行

# ── 节点 ─────────────────────────────────
ros2 node list
ros2 node info /节点名
ros2 run <包名> <可执行名>
ros2 launch <包名> <xxx.launch.py>

# ── 话题 ─────────────────────────────────
ros2 topic list -t                  # -t 显示消息类型（用于反推 import）
ros2 topic info /话题名 --verbose    # --verbose 看 QoS，排查"收不到消息"
ros2 topic echo /话题名
ros2 topic hz /话题名               # 实际发布频率
ros2 topic pub /话题名 类型 "{...}"  # 默认 1Hz 持续发布，--once 只发一次

# ── 服务 ─────────────────────────────────
ros2 service list -t
ros2 service call /服务名 类型 "{...}"
ros2 interface show <包名>/srv/<名字>   # msg 则换成 msg

# ── 参数 ─────────────────────────────────
ros2 param list
ros2 param get /节点名 参数名
ros2 param set /节点名 参数名 值
ros2 param describe /节点名 参数名
ros2 param dump /节点名 > params.yaml
ros2 run <包名> <可执行名> --ros-args --params-file params.yaml
ros2 run <包名> <可执行名> --ros-args -p 参数名:=值    # 注意是 :=

# ── TF 坐标变换 ───────────────────────────
ros2 run tf2_ros static_transform_publisher --x 0.1 --z 0.2 \
  --frame-id base_link --child-frame-id base_laser   # 发布静态变换（注意 --）
ros2 run tf2_ros tf2_echo base_link base_laser       # 查询两坐标系关系
ros2 topic echo /tf_static                           # 静态变换原始消息
ros2 topic info /tf_static --verbose                 # 看 Durability: TRANSIENT_LOCAL
ros2 run tf2_tools view_frames                       # 生成坐标系树 PDF（落在当前目录）
ros2 run tf2_tools view_frames -o ~/tf图/frames       # 指定输出（不带扩展名）
dot -Tpng frames.gv -o frames.png                    # .gv 转其它格式

# ── 可视化 ───────────────────────────────
rviz2                               # 三维可视化（首次启动报 Fixed Frame 错是正常的）
rviz2 -d ~/tf_demo.rviz             # 加载指定的配置文件
rqt                                 # plugins → service → service call
rqt_graph                           # 看节点与话题的连接关系，排查通信问题神器

# ── 仿真 / URDF 模型 ──────────────────────
ros2 pkg create <包名> --build-type ament_cmake --license Apache-2.0   # 模型包用 cmake
xacro 模型.xacro > /tmp/model.urdf        # 先展开：URDF 工具不认 xacro
check_urdf /tmp/model.urdf                # 校验结构（失败常见于名字对不上/父子成环）
urdf_to_graphviz /tmp/model.urdf 输出名    # 生成 .gv + .pdf（输出名是位置参数）
ros2 launch <包名> display_robot.launch.py
ros2 launch <包名> display_robot.launch.py --show-args   # 只列参数，不启动
ros2 topic echo /robot_description --once                # 确认模型参数发出来了
sudo apt install ros-$ROS_DISTRO-joint-state-publisher-gui  # 滑块手调关节

# ── Gazebo Harmonic 仿真（Jazzy）──────────
sudo apt install ros-$ROS_DISTRO-ros-gz      # 仿真器 + ROS 桥（gz sim 就在里面）
source /opt/ros/jazzy/setup.bash             # ★ 必须，否则 gz 里没有 sim 子命令
gz sim --version && gz --commands            # 自检
gz sim -r 你的世界.sdf                        # 启动（-s 只起服务端，不开界面）
gz topic -l                                  # ① 先看 gz 侧有没有数据
gz topic -e -t /clock -n 1                   # 仿真时间在不在走
ros2 run ros_gz_sim create -world default -file 模型.urdf -name fishbot -z 0.1   # 生成机器人
ros2 run ros_gz_bridge parameter_bridge \
  /clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock \
  /model/fishbot/cmd_vel@geometry_msgs/msg/Twist]gz.msgs.Twist \
  /model/fishbot/odometry@nav_msgs/msg/Odometry[gz.msgs.Odometry \
  /model/fishbot/tf@tf2_msgs/msg/TFMessage[gz.msgs.Pose_V
#   [ = gz→ROS    ] = ROS→gz    @ = 双向   （写反不报错，只是数据不动）
ros2 topic list | grep -E "cmd_vel|odom|scan"   # ② 再看桥过来没有
sudo apt install ros-$ROS_DISTRO-teleop-twist-keyboard && ros2 run teleop_twist_keyboard teleop_twist_keyboard

# ── ros2_control ─────────────────────────
sudo apt install ros-$ROS_DISTRO-ros2-control ros-$ROS_DISTRO-ros2-controllers
sudo apt install ros-$ROS_DISTRO-gz-ros2-control   # Harmonic 用这个（不是 gazebo-ros2-control）
ros2 control list_hardware_interfaces         # 看接口 [available][unclaimed]
ros2 control list_hardware_components
ros2 control list_controller_types
ros2 control load_controller fishbot_joint_state_broadcaster --set-state active
ros2 control list_controllers
ros2 control set_controller_state <控制器> inactive   # 卸载前先失活
ros2 control unload_controller <控制器>

# ── 建图（slam_toolbox）──────────────────
sudo apt install ros-$ROS_DISTRO-slam-toolbox
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=True
ros2 topic echo /map --once                   # 地图在不在发
sudo apt install ros-$ROS_DISTRO-nav2-map-server
ros2 run nav2_map_server map_saver_cli -f room   # 生成 room.pgm + room.yaml

# ── 导航（Nav2）──────────────────────────
sudo apt install ros-$ROS_DISTRO-navigation2 ros-$ROS_DISTRO-nav2-bringup
ros2 launch fishbot_navigation2 navigation2.launch.py
ros2 topic pub /initialpose geometry_msgs/msg/PoseWithCovarianceStamped \
  "{header: {frame_id: map}, pose: {pose: {position: {x: 0.0, y: 0.0}, orientation: {w: 1.0}}}}" --once
ros2 action list | grep -i navigate           # /navigate_to_pose、/follow_waypoints
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 2.0, y: 2.0}, orientation: {w: 1.0}}}}" --feedback
ros2 run tf2_ros tf2_echo map base_footprint  # 查机器人在地图里的位姿
ros2 topic echo /cmd_vel                      # 看导航输出的速度指令

# ── 排查 ─────────────────────────────────
ros2 doctor                         # 环境体检
echo $ROS_DOMAIN_ID                 # 多机/多容器通信时，域 ID 必须一致
pgrep -af static_transform_publisher # 找残留的 tf 发布器
pkill -f static_transform_publisher  # 一次清干净（kill 外壳杀不掉子进程）
```
