本章讲两件事：

- **RViz2**：把 ROS 话题里的数据**画出来**（怎么看）
- **ros2 bag**：把话题数据**录下来回放**（怎么存）

这两个工具是绝配——**录一段包，然后一遍遍回放、一遍遍在 RViz 里看**，是调试机器人最常用的工作流。

### 1、RViz2 是什么

**它是一个纯显示工具，自己不产生任何数据。**

```
传感器 / 算法节点  ──发布──▶  ROS 话题  ──订阅──▶  RViz2 画出来
   （数据源）                  （数据）              （只看不产）
```


> 💡 **知识点：记住这条，排错就有方向了**
>
> **RViz 里看不到东西，永远只有两种原因：**
> 1. **数据没来**（话题没发布，或话题名/类型不匹配）
> 2. **参考系不对**（Fixed Frame 设错了）
>
> 而不是"RViz 坏了"。所以排查顺序永远是：先 `ros2 topic list` 确认数据在不在，再查 Fixed Frame。

类比：RViz 之于 ROS，相当于**示波器之于电路**——只负责显示波形，不产生信号。

### 2、启动与界面

```bash
rviz2
```


> ⚠️ **首次启动看到一片灰 + 左边红字报错（`Fixed Frame [map] does not exist`），这是完全正常的。**
>
> 因为 RViz 默认配置里 Fixed Frame 是 `map`，而大多数学习用的 demo 根本没有这个坐标系。下一节就解决它。

界面分四块：

```
┌──────────────┬────────────────────────────┐
│  Displays    │                            │
│  （显示项清单）│        3D 视图             │
│              │      （真正看东西的地方）    │
│  Global      │                            │
│  Options     │                            │
│   └ Fixed    │                            │
│     Frame    │                            │
│              │                            │
│  ┌ Grid      │                            │
│  ┌ TF        │                            │
├──────────────┴────────────────────────────┤
│ Left-Click: Rotate   Middle-Click: Move   │ ← 鼠标操作提示
│ Right-Click/Mouse Wheel: Zoom             │
└───────────────────────────────────────────┘
```


| 区域 | 作用 |
|---|---|
| **左：Displays** | 要显示什么。每一项对应一类数据 |
| **中：3D 视图** | 画布 |
| **右上：Views** | 相机参数（视角类型、距离、角度） |
| **底部** | ROS 时间和鼠标操作提示 |

### 3、三个核心概念

只要搞懂这三个，RViz 就会用了。

#### 概念 1：Fixed Frame（固定参考系）

**整幅画面的坐标原点。** RViz 必须知道"我站在哪个坐标系里看世界"，才能把所有数据换算到同一个参考下画出来。

> ⚠️ **规则：Fixed Frame 必须填你 TF 树里真实存在的坐标系**，通常填最顶层的根。
>
> 比如 TF 树是 `base_link → camera_link → bottle_link`，就填 **`base_link`**。
>
> **这一项填错 = 整个画面空白 + 红字报错。新手 90% 的时间都卡在这里。**

> 💡 **知识点：为什么 RViz 默认是 `map`**
>
> `map` 是移动机器人导航的标准根坐标系，完整链表是：
>
> ```
> map ──▶ odom ──▶ base_link ──▶ 各种传感器
> ```
>
> RViz 面向的是这个主流场景，所以默认填了 `map`。学习 TF 或做小 demo 时没有 `map`，就必须改掉。

#### 概念 2：Displays（显示项）

RViz 里的每一项 = **"订阅某个话题 → 用某种方式画出来"**。

比如：

| Display | 订阅 | 画出什么 |
|---|---|---|
| `TF` | `/tf`、`/tf_static` | 所有坐标系的坐标轴 |
| `LaserScan` | 某个激光话题 | 激光雷达扫描点 |

> ⚠️ **要显示什么就得手动加什么，不会自动出现。** 点左下角的 **`Add`** 按钮添加。

#### 概念 3：Views（视角）

相机的位置和朝向。默认是 `Orbit`（轨道视角，可以绕着物体转）。

### 4、完整操作流程

拿第五章那个 TF demo 走一遍（`base_link → camera_link → bottle_link`）。

#### Step 0：确认数据源在跑

```bash
# 另开一个终端
source /opt/ros/jazzy/setup.bash
ros2 topic list | grep tf
# 应该看到 /tf 和 /tf_static
```


**没有数据源，RViz 里怎么点都是空的。**

#### Step 1：启动 RViz

```bash
rviz2
```


#### Step 2：设 Fixed Frame（关键一步）

左侧 `Global Options` → `Fixed Frame` 那一行。有两种改法：

**方法 A：直接打字（最可靠）**

1. 鼠标**左键单击**显示 `map` 的那个框
2. `Ctrl` + `A` 全选 → 输入 `base_link`
3. **按回车**

**方法 B：下拉选择**

点右边的箭头，选 `base_link`。

> ⚠️ **下拉列表是空的怎么办**
>
> 这是很常见的困惑。Fixed Frame 是个**可编辑下拉框**，列表内容 = "RViz 已经发现过的坐标系"，而发现**依赖 TF 显示项去订阅话题**。
>
> 这就形成了鸡生蛋问题：想设置参考系，但候选项又需要 TF 显示项才能发现。
>
> **所以：列表空的时候，直接用方法 A 打字即可**，完全绕过这个依赖。
> 另外确认一下左侧 `TF` 那一项**前面的勾打上了**——没勾的话 RViz 不会订阅 TF，列表永远是空的。

改完的瞬间红字消失，画面中间出现坐标轴。

#### Step 3：加 TF 显示项

左下角 **`Add`** → 弹窗里找 **`TF`** → 双击（或选中后点 OK）。

加完后展开左侧的 `TF` 项，建议这样设：

| 子选项 | 建议值 | 作用 |
|---|---|---|
| `Show Names` | ✅ 勾上 | 每个坐标轴旁显示坐标系名字 |
| `Show Axes` | ✅ 勾上 | 显示坐标轴 |
| `Show Arrows` | ✅ 勾上 | 用箭头表示父子关系 |
| `Marker Scale` | 拖到 2~3 | 坐标轴放大，否则太小看不见 |
| `Frames` → `All Enabled` | ✅ 勾上 | 显示全部坐标系 |

现在应该能看到三个坐标系：`base_link`、`camera_link`、`bottle_link`。

> 💡 **只看到一个轴？** 把 `Marker Scale` 调大。三个坐标系可能挨得很近，或者被 Grid 挡住了。

#### Step 4：鼠标操作

| 操作 | 效果 |
|---|---|
| **左键拖** | 旋转视角 |
| **中键拖** | 平移画面 |
| **右键拖 / 滚轮** | 缩放 |

这几条 RViz **底部状态栏**也写着，忘了随时低头看。

#### Step 5：保存配置

> ⚠️ **这一步很重要**，不做的话下次启动又要从头配一遍。

菜单 `File` → `Save Config As` → 存成 `~/tf_demo.rviz`

以后一步到位：

```bash
rviz2 -d ~/tf_demo.rviz
```


`-d`（`--display-config`）就是"加载指定配置文件"的意思。

### 5、常用 Display 速查

| Display | 订阅什么 | 能看到什么 |
|---|---|---|
| **Grid** | （不订阅） | 地面网格，纯参考用 |
| **TF** | `/tf`、`/tf_static` | 所有坐标系的坐标轴 |
| **RobotModel** | `/robot_description`、`/joint_states` | 机器人三维模型（URDF） |
| **LaserScan** | 激光话题 | 激光雷达扫出的点 |
| **PointCloud2** | 点云话题 | 三维点云 |
| **Image** | 图像话题 | 摄像头画面（独立二维窗口） |
| **Map** | 栅格地图话题 | 导航用的二维地图 |
| **Path** | 路径话题 | 规划出的轨迹 |
| **Odometry** | 里程计话题 | 运动轨迹 + 位姿 |
| **Marker / MarkerArray** | marker 话题 | 用代码画的任意图形 |

### 6、报错对照表

| 报错 / 现象 | 原因 | 解决 |
|---|---|---|
| `Fixed Frame [map] does not exist` | 树里没有 `map` | Fixed Frame 改成 `base_link` |
| `No tf data. Actual error: ...` | TF 显示项收不到数据 | ① 发布器在跑吗 ② TF 项勾了吗 ③ Fixed Frame 存在吗 |
| 改成 `base_link` 后仍然空白 | 数据源根本没起 | `ros2 topic list` 确认话题在 |
| 某个 Display 一直是红的 | 话题名 / 类型不匹配 | 展开该 Display 的 `Topic` 项，逐字核对话题名 |
| 画面全黑或全白 | 相机跑到物体内部/外部了 | 滚轮缩放，或把 `Views` 里的 `Distance` 改回 3 |

### 7、一句话总结

```
RViz 用不明白 = 99% 是 Fixed Frame 和 Displays 这两个地方没配对
```


**固定套路：**

1. `ros2 topic list` —— 看有什么数据
2. 起 `rviz2`
3. `Fixed Frame` 填**你 TF 树里真实存在的根坐标系**
4. `Add` —— 加对应的 Display
5. 点进 Display 检查 `Topic` 名字对不对
6. `File → Save Config As` —— 存起来

### 8、ros2 bag：数据录制与回放

#### 8.1 为什么需要录包

这是 ROS 2 里**最被低估的工具**。它的价值不只是"记录数据"：

| 用途 | 说明 |
|---|---|
| **复现偶发 bug** | 现场只出现一次的问题，录下来就能反复回放、反复调试 |
| **离线调算法** | 同一份数据喂给算法跑一百遍，每次输入完全一样 |
| **做数据集** | 跑一次真机，采一批数据回来慢慢用 |
| **分享现场** | 把包发给同事/厂商，对方不用有同样的硬件也能看 |

> 💡 **一句话记住它的价值**：**把"一次性的、不可重复的现实"变成"可反复播放的文件"。**

#### 8.2 录制

```bash
# 最常用：录制所有话题（不含隐藏话题）
ros2 bag record -a -o my_bag

# 只录指定话题（包小、干净，推荐）
ros2 bag record -o turtle_bag /turtle1/cmd_vel /turtle1/pose

# 不指定 -o 时，自动生成 rosbag2_<日期>_<时间> 目录
ros2 bag record -a
```


| 参数 | 作用 |
|---|---|
| `-a, --all` | 录制所有话题（可加 `--all-services` 连服务一起录） |
| `-o, --output` | 输出目录名 |
| `-s, --storage` | 存储格式，`mcap`（默认）或 `sqlite3` |

> ⚠️ **怎么停止录制：按 `Ctrl+C`**
>
> 不要用 `kill`。rosbag2 需要收到中断信号才能把索引写完——**直接 kill -9 会导致 `metadata.yaml` 丢失**，包就读不了了。
>
> 实测发现：在**非终端环境**下 `kill -INT` 可能不生效（rosbag2 靠 stdin 判断是否有键盘输入，日志会提示 `stdin is not a terminal device`）；这时用 `kill -TERM` 可以正常收尾。

#### 8.3 产物长什么样

```
my_bag/
├── metadata.yaml      ← 索引：话题列表、消息数、时间范围
└── my_bag_0.mcap      ← 真正的数据
```


> 💡 **知识点：Jazzy 的默认存储格式是 `mcap`，不是 `sqlite3`**
>
> | 版本 | 默认格式 | 文件后缀 |
> |---|---|---|
> | Humble 及以前 | sqlite3 | `.db3` |
> | **Jazzy 及以后** | **mcap** | **`.mcap`** |
>
> MCAP 是新一代格式，读写更快、支持索引和压缩。看老教程时如果对不上文件名，就是这个原因。想用回老格式加 `-s sqlite3`。

#### 8.4 查看包信息

```bash
ros2 bag info my_bag
```


实测输出：

```
Files:             my_bag_0.mcap
Bag size:          25.4 KiB
Storage id:        mcap
ROS Distro:        jazzy
Duration:          29.729986683s
Start:             Sep 24 2026 16:38:53.627928530
End:               Sep 24 2026 16:39:23.357915213
Messages:          13
Topic information: Topic: /rosout     | Type: rcl_interfaces/msg/Log    | Count: 12
                   Topic: /tf_static  | Type: tf2_msgs/msg/TFMessage    | Count: 1
```


**录完先 `info` 一下**是好习惯——能立刻确认：时长对不对、话题有没有漏、消息数是否合理（比如一个 10 Hz 的话题录了 30 秒，消息数应该接近 300 而不是 1）。

#### 8.5 回放

```bash
ros2 bag play my_bag               # 正常回放
ros2 bag play my_bag --loop        # 循环播放
ros2 bag play my_bag --rate 2.0    # 2 倍速（0.5 就是慢放）
ros2 bag play my_bag --start-paused # 先暂停，按空格开始
```


| 参数 | 作用 |
|---|---|
| `-l, --loop` | 循环播放 |
| `-r, --rate` | 播放倍速 |
| `-p, --start-paused` | 启动后先暂停 |
| `--clock` | 发布 `/clock`，配合 `use_sim_time` |

回放时，所有订阅这些话题的节点（包括 RViz）都会以为数据是**实时来**的——这就是它的精妙之处。

#### 8.6 常见问题

**Q1：`ros2 bag info` 报 `Could not find metadata in bag directory`**

多半是上次录制**没正常退出**（被 kill 掉了），`metadata.yaml` 没写成。可以重建（实测可用）：

```bash
ros2 bag reindex my_bag        # 从 mcap/db3 里重新生成 metadata.yaml
```


**Q2：某些话题明明在发布，却录不到**

**QoS 不匹配**。传感器类话题（摄像头、激光雷达）常用 `BEST_EFFORT`，而 `bag record` 默认按 `RELIABLE` 订阅，两边对不上就收不到数据。

解决：写一份 QoS 覆盖文件，用 `--qos-profile-overrides-path` 指定。这也是为什么很多人"录了半天包，打开发现是空的"。

**Q3：包太大**

```bash
# ① 只录需要的（最有效）
ros2 bag record -o small_bag /topic_a /topic_b

# ② 开压缩
ros2 bag record -a -o my_bag --compression-mode file --compression-format zstd

# ③ 限制写盘缓存
ros2 bag record -a -o my_bag --max-cache-size 100000000
```


**点云、图像话题是体积杀手**——一秒钟能写几十 MB。录之前先想清楚哪些真的需要。

### 9、RViz2 + bag 联动实战

这是这两个工具最常见的组合用法，也是**排查机器人问题的标准流程**：

```bash
# ── 第一步：录一段数据 ──
# 终端1
ros2 bag record -a -o my_run
#   然后让机器人/仿真跑一会儿，复现问题
#   问题出现后按 Ctrl+C 停止

# ── 第二步：回放 ──
# 终端2
ros2 bag play my_run --loop

# ── 第三步：看 ──
# 终端3
rviz2 -d ~/tf_demo.rviz
```


**为什么这个组合强大：**

```
没有 bag：  问题出现 → 手忙脚乱地查 → 问题消失了 → 只能等下次
有了 bag：  问题出现 → 录下来 → 反复回放 → 每次都是同样的数据 → 慢慢查
```


配合 `--loop` 循环播放，你可以让同一段故障数据**一遍遍重演**，直到找出原因。

> ⚠️ **回放时的时间问题**
>
> 如果包里录了 `/clock`（仿真时间），回放时数据的时间戳是"过去"的。这时：
> - 回放端加 `--clock` 让 rosbag2 发布 `/clock`
> - 其它节点（包括 RViz）如果开了 `use_sim_time`，就能跟着包里的时间走
> - **两边不一致会出现"数据永远在等"的现象**——RViz 里表现为什么都不显示

> 💡 **知识点：`/tf_static` 在包里只有一条**
>
> 看上面的 `info` 输出会发现 `/tf_static` 的 `Count: 1`——因为静态变换只发一次（latched）。
> 但回放时不用担心：rosbag2 会把这条以 `TRANSIENT_LOCAL` QoS 重新发出来，晚加入的订阅者照样能收到。这和第 5.5 节讲的 QoS 是同一个机制。
