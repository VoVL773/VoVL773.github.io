多种通信方式都是话题通信的变种。

> 💡 **知识点：三种通信方式的准确定位**
>
> 说"都是话题的变种"从**实现层面**看没错（底层都基于 DDS），但**使用语义**差别很大，混淆会导致选错工具：
>
> | | 话题 Topic | 服务 Service | 动作 Action |
> |---|---|---|---|
> | 模式 | 发布/订阅，单向 | 请求/响应，一问一答 | 长任务 + 中途反馈 |
> | 阻塞 | 不阻塞 | **客户端会等响应** | 不阻塞，可取消 |
> | 反馈 | 无 | 无 | **有持续反馈** |
> | 典型场景 | 传感器数据、速度指令 | 查询、设置参数、触发一次计算 | 导航到目标点、抓取 |
> | 命令 | `ros2 topic` | `ros2 service` | `ros2 action` |
>
> 判断口诀：**持续不断的数据流 → 话题；"做完告诉我结果" → 服务；"做完之前还要告诉我进度" → 动作。**

现在我们调用 `/spawn` 服务新建一个海龟。先查看对应的接口信息 `ros2 interface show turtlesim/srv/Spawn`

```text
float32 x
float32 y
float32 theta
string name # Optional.  A unique name will be created and returned if this is empty
---
string name
```


`---` 上方是**输入信息**（请求 request），下方是**输出信息**（响应 response）。

> ⚠️ **原笔记说"其中只有 x 和 y 是必需变量"，这个说法不准确**：
> `.srv` 里**所有字段都有默认值**（数值型默认 0，字符串默认空），所以严格来说**没有任何字段是"必需"的**。`ros2 service call` 时可以只写你想改的字段，其余自动取默认值。
> 真正"可选"的是 `name`——留空时 turtlesim 会自动生成一个唯一名字并在响应里告诉你。

示例：`ros2 service call /spawn turtlesim/srv/Spawn "{x: 1, y: 1}"`

`call` 一个服务：`服务名 接口名 参数`

可以使用可视化工具 rqt，直接输入 `rqt` 进入界面。

`plugins` → `service` → `service call` → 选择服务 → 输入参数 → `call` 即可。

通过服务可以修改参数，如下：

```text
/turtlesim/describe_parameters [rcl_interfaces/srv/DescribeParameters]
/turtlesim/get_parameter_types [rcl_interfaces/srv/GetParameterTypes]

```


> 💡 **知识点：参数（Parameter）本质上就是"用服务实现的配置项"**
>
> 上面这一堆 `get_parameters`、`set_parameters` 就是每个 ROS 2 节点**自动带的**服务。参数 = 节点运行时可读写的键值对配置，底层通过服务访问，所以能用 `ros2 service call` 直接操作。
>
> 参数支持的类型：`bool`、`int64`、`float64`、`string`、`byte[]`，以及这些类型的**数组**。

`ros2 param list` 列出所有的参数列表

`ros2 param describe /turtlesim background_r` 输出参数的说明

`describe`、`get`、`set` 等等各字段都有效果

导出 yaml 格式文件：

```bash
ros2 param dump /turtlesim > turtlesim_param.yaml
```


使用格式文件：

```bash
ros2 run turtlesim turtlesim_node --ros-args --params-file turtlesim_param.yaml
```


> ⚠️ **原笔记写的是 `--ros-arg`（少了 s）**，已修正为 **`--ros-args`**（复数）。
> 另外 **`--params-file` 不能单独使用**，它必须跟在 `--ros-args` 后面。凡是传递给 ROS 系统本身（而不是给你程序）的参数，都要放在 `--ros-args` 之后。

> 💡 **知识点：`--ros-args` 后面能放什么**
>
> | 用途 | 写法 |
> |---|---|
> | 加载参数文件 | `--ros-args --params-file xxx.yaml` |
> | 单独设一个参数 | `--ros-args -p background_r:=200` |
> | 重命名节点 | `--ros-args -r __node:=new_name` |
> | 重映射话题 | `--ros-args -r /old_topic:=/new_topic` |
> | 设置日志级别 | `--ros-args --log-level debug` |
>
> **注意 `:=` 不是 `=`**。这是 ROS 2 特有的赋值符号，写成 `=` 会报错。可以在运行时改参数而**不用改代码**，调试时特别方便。

rqt 也可进行快速的可视化修改。

### 人脸检测实例

首先需要自定义一个服务端接口，服务端进行人脸检测后将检测结果返回给客户端。

```bash
ros2 pkg create chapt4_interfaces \
    --build-type ament_cmake \
    --dependencies rosidl_default_generators sensor_msgs \
    --license Apache-2.0
```


创建目录 `srv` 后创建文件 `FaceDetector.srv`，写入以下内容：

```srv
sensor_msgs/Image image   # 原始图像
---
int16 number              # 人脸数目
float32 use_time          # 识别耗时
int32[] top               # 位置信息（变长数组，因为人脸数量不定）
int32[] right
int32[] bottom
int32[] left
```


> 💡 **知识点：为什么用四个数组而不是一个数组套结构体**
>
> ROS 2 的 `.msg` **不支持嵌套定义结构体**，你不可以在 `.srv` 里现场定义一个新类型。想返回"人脸的四个坐标"，只能：
>
> 1. **并列多个数组**（本代码的做法）——简单，但依赖"第 i 个元素互相对应"这个约定；
> 2. **单独定义一个 `.msg`**，然后在 `.srv` 里用 `MyFace[] faces`。
>
> 方法 2 更安全（编译器帮你保证对应关系），方法 1 更省事。人少的时候方法 1 够用；如果字段有七八个，强烈建议改成方法 2，否则很容易下标错位。

对 `CMakeLists.txt` 文件加入：

```cmake
# find dependencies
find_package(ament_cmake REQUIRED)
find_package(rosidl_default_generators REQUIRED)
find_package(sensor_msgs REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
    "srv/FaceDetector.srv"
    DEPENDENCIES sensor_msgs      # 用到了 sensor_msgs/Image，必须声明
)
```


再在 `package.xml` 添加 `<member_of_group>rosidl_interface_packages</member_of_group>`

之后初始化环境后 `ros2 interface show chapt4_interfaces/srv/FaceDetector` 即可查看并验证接口信息

> ⚠️ **原笔记写的是 `chapt4_interface`（少了 s）**，已修正为 `chapt4_interfaces`——包名以 `ros2 pkg create` 时的名字为准。

#### Python 部分

`learn_face_detect.py`

```python
import face_recognition
import cv2
from ament_index_python.packages import get_package_share_directory  # 获取功能包 share 绝对路径
import os

def main():
    # 获取 resource 目录的真实路径
    # 为什么要用 get_package_share_directory 而不是写死相对路径？
    # 因为包被 install 之后，源码目录和运行目录是分开的，写死路径必然找不到文件
    default_img_path = os.path.join(
        get_package_share_directory('demo_python_service'), 'resource')
    image1_path = os.path.join(default_img_path, 'people1.jpg')
    image2_path = os.path.join(default_img_path, 'people2.jpg')
    image1 = cv2.imread(image1_path)     # 读成 OpenCV 的 numpy 数组格式
    image2 = cv2.imread(image2_path)

    # face_locations 返回的是 [(top, right, bottom, left), ...] 列表
    # model='hog'：CPU 版，快但精度一般；'cnn'：GPU 版，准但慢
    # number_of_times_to_upsample：放大次数，越大越容易检出小脸，也越慢
    face_locations1 = face_recognition.face_locations(
        image1, number_of_times_to_upsample=1, model='hog')
    face_locations2 = face_recognition.face_locations(
        image2, number_of_times_to_upsample=1, model='hog')

    for top, right, bottom, left in face_locations1:
        # cv2.rectangle 的两个点：左上角 (left, top) 和右下角 (right, bottom)
        # 注意 x 在前 y 在后，而 face_locations 返回的顺序是 top 在前，别搞反
        cv2.rectangle(image1, (left, top), (right, bottom), (255, 0, 0), 4)   # 4 是线宽
    for top, right, bottom, left in face_locations2:
        cv2.rectangle(image2, (left, top), (right, bottom), (255, 0, 0), 4)

    cv2.imshow('Face Detect Result 1', image1)   # 弹窗显示
    cv2.imshow('Face Detect Result 2', image2)
    cv2.waitKey(0)             # 0 表示无限等待键盘输入，按任意键继续
    cv2.destroyAllWindows()    # 关闭所有 OpenCV 窗口

if __name__ == '__main__':
    main()
```


> 💡 **知识点：`cv2` 的坐标是 `(x, y)`，而 `face_locations` 返回 `(top, right, bottom, left)`**
>
> 这是初学最容易出错的地方：
>
> | | 顺序 |
> |---|---|
> | `face_locations` 返回 | `(top, right, bottom, left)` = `(y1, x2, y2, x1)` |
> | `cv2.rectangle` 要的 | `(left, top)` 和 `(right, bottom)` |
>
> 所以必须像代码里那样**重新组合**，直接 `cv2.rectangle(img, loc[:2], loc[2:], ...)` 会画到完全错误的位置。

> ⚠️ **注意：`resource/` 里的图片必须登记到 `setup.py`**
>
> 只在源码目录放图片是不够的，`colcon build` 不会自动拷贝它。必须在 `setup.py` 的 `data_files` 里声明：
>
> ```python
> data_files=[
>     ...
>     (os.path.join('share', package_name, 'resource'),
>         glob('resource/*.jpg')),
> ],
> ```
>
> 否则 `get_package_share_directory(...) + '/resource/people1.jpg'` 指向的文件**在 install 目录里根本不存在**，`cv2.imread` 会返回 `None`（注意：**不报错**，只是后续操作全部失败，很难查）。

`face_detect_node.py`

```python
import rclpy
from rclpy.node import Node
from chapt4_interfaces.srv import FaceDetector
from ament_index_python.packages import get_package_share_directory
from cv_bridge import CvBridge   # 用于在 ROS 图像消息和 OpenCV 图像之间转换
import cv2
import face_recognition
import time


class FaceDetectionNode(Node):
    def __init__(self):
        super().__init__('face_detection_node')
        self.bridge = CvBridge()

        # 创建服务端：参数为 (接口类型, 服务名, 回调函数)
        # 回调函数负责处理请求并返回响应
        self.service = self.create_service(
            FaceDetector, '/face_detect', self.detect_face_callback)

        # 拼接默认图片路径（请求里没带图时用这张）
        self.default_image_path = (
            get_package_share_directory('demo_python_service') + '/resource/default.jpg')

        # 声明参数：名字, 默认值。声明之后才能用 ros2 param 查看/修改
        self.declare_parameter('upsample_times', 1)   # 控制放大次数
        self.declare_parameter('model', 'hog')        # 指定模型

        # 读取参数值：get_parameter(名字).value
        self.model = self.get_parameter('model').value
        self.upsample_times = self.get_parameter('upsample_times').value

        self.get_logger().info("人脸识别服务启动!")

    def detect_face_callback(self, request, response):
        """服务回调：签名固定是 (self, request, response)，且必须 return response"""
        if request.image.data:
            # 请求里带了图像数据 → 从 ROS Image 消息转成 OpenCV 格式
            cv_image = self.bridge.imgmsg_to_cv2(request.image)
        else:
            # 没带图 → 用默认图片
            self.get_logger().info("将使用默认图像")
            cv_image = cv2.imread(self.default_image_path)

        start_time = time.time()
        self.get_logger().info('加载图像，开始检测')

        face_locations = face_recognition.face_locations(
            cv_image,
            number_of_times_to_upsample=self.upsample_times,
            model=self.model)

        end_time = time.time()
        self.get_logger().info(f'检测完成，耗时 {end_time - start_time}s')

        # 填充响应字段
        response.number = len(face_locations)
        response.use_time = end_time - start_time
        for top, right, bottom, left in face_locations:
            response.top.append(top)         # 变长数组用 append 追加
            response.right.append(right)
            response.bottom.append(bottom)
            response.left.append(left)

        return response                      # ⚠️ 必须返回 response，否则客户端会一直等


def main(args=None):
    rclpy.init(args=args)
    node = FaceDetectionNode()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```


> ⚠️ **原笔记有一处致命拼写错误**（已修正）：
> ```python
> self.upsample_times = self.get_patamete('upsample_times').value   # ❌ get_patamete
> self.upsample_times = self.get_parameter('upsample_times').value  # ✅ get_parameter
> ```
> 正确拼写是 **`parameter`**。写成 `get_patamete` 会直接 `AttributeError`，节点根本启动不起来。

> 💡 **知识点：服务回调的三个硬性约定**
>
> 1. **签名固定**：`def callback(self, request, response)`，参数名可以改，但顺序和个数不能变；
> 2. **必须 `return response`**：忘了 return 会返回 `None`，客户端**永远等不到响应**（表现为卡死，且没有报错——很难查）；
> 3. **要快**：服务回调同样跑在 spin 线程里，耗时操作会阻塞该节点所有其它回调。

> 💡 **知识点：CvBridge 为什么必须存在**
>
> ROS 的图像消息 `sensor_msgs/Image` 和 OpenCV 的 `numpy.ndarray` 是两套完全不同的数据结构：
>
> | | ROS `Image` | OpenCV `ndarray` |
> |---|---|---|
> | 数据 | 一段扁平字节，`data` 字段 | 多维数组 `(h, w, c)` |
> | 元信息 | 单独字段 `height`/`width`/`encoding` | 从数组 shape 推断 |
> | 编码 | 显式声明 `rgb8`/`bgr8`… | 维度顺序隐含 |
>
> `CvBridge` 就是这两者之间的翻译官：
>
> ```python
> bridge.imgmsg_to_cv2(msg)          # ROS → OpenCV
> bridge.cv2_to_imgmsg(img, 'bgr8')  # OpenCV → ROS
> ```
>
> **`encoding` 务必显式指定。** OpenCV 的通道顺序是 **BGR**，而 ROS 的惯例是 **RGB**。不写的话，图像能传但**颜色是反的**（红蓝互换），而且不会报错，只能靠肉眼发现。

`face_detect_client_node.py`

```python
import rclpy
from rclpy.node import Node
from chapt4_interfaces.srv import FaceDetector
from sensor_msgs.msg import Image
from ament_index_python.packages import get_package_share_directory
import cv2
from cv_bridge import CvBridge


class FaceDetectorClient(Node):
    def __init__(self):
        super().__init__('face_detect_client')
        # 创建服务客户端：接口类型和服务名必须与服务端完全一致
        self.client = self.create_client(FaceDetector, '/face_detect')
        self.bridge = CvBridge()
        self.test1_image_path = (
            get_package_share_directory('demo_python_service') + '/resource/test1.jpg')
        self.image = cv2.imread(self.test1_image_path)
        self.get_logger().info("人脸识别客户端已经启动")

    def send_request(self):
        # 1. 判断服务是否上线（服务端可能还没启动）
        while self.client.wait_for_service(timeout_sec=1.0) is False:
            self.get_logger().info('等待服务端上线...')

        # 2. 构造 Request
        request = FaceDetector.Request()   # 注意是 接口名.Request()
        # 显式指定 encoding='bgr8'，避免颜色通道错乱
        request.image = self.bridge.cv2_to_imgmsg(self.image, encoding='bgr8')

        # 3. 发送异步请求，并等待处理完成
        future = self.client.call_async(request)
        rclpy.spin_until_future_complete(self, future)   # 阻塞直到服务端返回

        # 4. 根据结果处理
        response = future.result()
        self.get_logger().info(
            f'接收到响应：图像中共有：{response.number} 张脸，耗时 {response.use_time}s')
        self.show_face_locations(response)

    def show_face_locations(self, response):
        for i in range(response.number):
            top = response.top[i]
            right = response.right[i]
            bottom = response.bottom[i]
            left = response.left[i]
            cv2.rectangle(self.image, (left, top), (right, bottom), (255, 0, 0), 2)
        cv2.imshow('Face Detection Result', self.image)
        cv2.waitKey(0)
        cv2.destroyAllWindows()


def main(args=None):
    rclpy.init(args=args)
    face_detect_client = FaceDetectorClient()
    face_detect_client.send_request()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```


> 💡 **知识点：同步调用 vs 异步调用**
>
> | 写法 | 特点 | 适用 |
> |---|---|---|
> | `client.call(request)` | 阻塞，等结果 | 简单脚本、和 spin 混用时容易死锁 |
> | `client.call_async(request)` | 立即返回 `future` | **推荐**，可配合 `spin_until_future_complete` 或回调 |
>
> 为什么推荐 async？因为 ROS 2 里**同步调用要求当前没有在 spin**——如果你在回调里用同步 `call()`，而 `spin()` 正在跑，就会**死锁**（自己在等自己）。用 `call_async` 则没有这个限制。
>
> `future` 是"期货凭证"：调用时立即拿到，结果稍后填进去。`spin_until_future_complete(self, future)` 会一边转事件循环一边等它完成——这就是它比 `future.result()` 更安全的原因。

### 通过自定义服务发布目标地点让海龟前往

接口

```srv
float32 target_x   # 目标坐标
float32 target_y
---
int8 SUCCESS = 1   # 常量：1 表示成功
int8 FAIL = 0      # 常量：0 表示失败
int8 result
```


> ⚠️ **原笔记把 `FAIL` 写成了 `FALL`**（已修正）。这是一个会直接崩的问题：
> `.srv` 里定义了 `FALL`，但 Python 代码里写的是 `Patrol.Response.FAIL`，运行时 `AttributeError: FAIL`。
> **常量的名字是你自己定的，但定义和使用必须严格一致。**

> 💡 **知识点：`.srv` 里的常量怎么用**
>
> `int8 SUCCESS = 1` 定义在 `---` 下方（响应区），会被生成到 `Patrol.Response` 上：
>
> ```python
> Patrol.Response.SUCCESS   # 服务端赋值用
> Patrol.Response.FAIL
> ```
>
> 好处是**调用双方不用记"1 代表成功"这种魔法数字**，代码自解释。注意常量**不属于消息字段**，不会占传输空间，只是编译期生成的类属性。

python：

```python
import math

import rclpy
from rclpy.node import Node
from chapt4_interfaces.srv import Patrol
from geometry_msgs.msg import Twist
from turtlesim.msg import Pose


class TurtleController(Node):
    def __init__(self):
        super().__init__('turtle_controller')

        # 创建服务端，服务名 patrol，回调 self.patrol_callback
        self.patrol_server_ = self.create_service(
            Patrol, 'patrol', self.patrol_callback)

        # 速度指令发布器
        self.cmd_vel_publisher_ = self.create_publisher(
            Twist, '/turtle1/cmd_vel', 10)

        # 订阅海龟实时位姿（要控制它，必须先知道它在哪、朝哪）
        self.pose_subscription_ = self.create_subscription(
            Pose, '/turtle1/pose', self.pose_callback, 10)

        # 50Hz 控制循环（0.02 秒一次）—— 闭环控制的频率要远高于动作速度
        self.control_timer_ = self.create_timer(0.02, self.control_loop)

        self.pose_: Pose | None = None       # 需要 Python 3.10+ 的联合类型语法
        self.target_x_: float | None = None
        self.target_y_: float | None = None
        self.get_logger().info("海龟巡逻服务已启动")

    def pose_callback(self, pose: Pose):
        # 只做"记下最新位姿"这一件事，越快越好
        self.pose_ = pose

    def patrol_callback(self, request, response):
        # 判断目标点是否在模拟器边界内（turtlesim 画布约 11.09 × 11.09）
        if 0 < request.target_x < 12.0 and 0 < request.target_y < 12.0:
            self.target_x_ = request.target_x
            self.target_y_ = request.target_y
            response.result = Patrol.Response.SUCCESS
            self.get_logger().info(
                f"目标点 ({request.target_x}, {request.target_y}) 已接收")
        else:
            response.result = Patrol.Response.FAIL
            self.get_logger().warn(
                f"目标点 ({request.target_x}, {request.target_y}) 超出范围")
        return response

    def control_loop(self):
        # 还没收到位姿或目标点时不做控制
        if self.pose_ is None or self.target_x_ is None or self.target_y_ is None:
            return

        dx = self.target_x_ - self.pose_.x
        dy = self.target_y_ - self.pose_.y
        distance = math.hypot(dx, dy)      # 直线距离 = sqrt(dx² + dy²)

        if distance < 0.1:                 # 到达目标点（留 0.1 的容差）
            self.cmd_vel_publisher_.publish(Twist())   # 发一条全零速度 = 急停
            self.get_logger().info("已到达目标点")
            self.target_x_ = None          # 清空目标，下个周期就 return 了
            self.target_y_ = None
            return

        msg = Twist()
        # 先转向：目标方向角 - 当前朝向角 = 角度偏差
        angle_error = math.atan2(dy, dx) - self.pose_.theta
        # 归一化到 [-pi, pi]：避免出现"要转 350°"这种绕远路的情况
        # 原理：sin/cos 是周期函数，(sin θ, cos θ) 能唯一还原出 [-π, π] 内的角
        angle_error = math.atan2(math.sin(angle_error), math.cos(angle_error))

        # 比例控制（P 控制）：偏差越大转得越快，并限制最大角速度 3.0 rad/s
        msg.angular.z = max(min(6.0 * angle_error, 3.0), -3.0)

        # 朝向基本对准后才开始前进 —— 否则会走出一条弧线而不是直线
        if abs(angle_error) < 0.2:
            msg.linear.x = min(1.5 * distance, 2.0)   # 距离越近走得越慢，防止冲过头

        self.cmd_vel_publisher_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = TurtleController()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```


> 💡 **知识点：这段代码是标准的"闭环控制"骨架**
>
> 它同时用到了 ROS 2 的三种通信方式，是个很好的综合练习：
>
> | 角色 | 通信方式 | 作用 |
> |---|---|---|
> | `cmd_vel_publisher_` | 发布话题 | 输出控制量 |
> | `pose_subscription_` | 订阅话题 | 读取当前状态 |
> | `patrol_server_` | 提供服务 | 接收外部任务指令 |
>
> 控制逻辑是经典的 **"感知 → 计算偏差 → 输出 → 再感知"** 循环，跑在 50Hz 定时器里。三个概念值得记住：
>
> - **比例控制（P 控制）**：输出 = 系数 × 偏差。简单有效，但系数太大会震荡，太小会迟缓；
> - **先转向再前进**：因为海龟不能横着走（非完整约束），必须先对准；
> - **容差**：现实中没有"正好等于目标"，所以用 `distance < 0.1` 判断到达。

> ⚠️ **注意两个可以改进的地方**
>
> **1. 服务端和客户端的范围对不上**
>
> | 位置 | 范围 |
> |---|---|
> | 服务端校验 | `0 < x < 12.0` |
> | turtlesim 实际画布 | 约 `0 ~ 11.09` |
> | 客户端随机生成 | `randint(0, 14)` → `0 ~ 14` |
>
> 客户端有相当比例的目标点**必然超出范围而返回 FAIL**。如果这是刻意用来演示失败分支，那没问题；否则建议把客户端改成 `randint(1, 11)`，服务端边界改成 `11.09`。
> （turtlesim 画布尺寸来自源码：窗口 `setFixedSize(500, 500)`，比例尺 `meter_ = 45`，所以 `(500-1)/45 ≈ 11.088`。**原点在左下角**，x 向右、y 向上。）

```python
import rclpy
from rclpy.node import Node
from chapt4_interfaces.srv import Patrol
import random
import time


class PatrolClient(Node):
    def __init__(self):
        super().__init__('patrol_client')
        # 创建服务客户端，服务名 patrol
        self.patrol_client_ = self.create_client(Patrol, 'patrol')
        # 创建定时器，每 10 秒触发一次 timer_callback
        self.timer_ = self.create_timer(10.0, self.timer_callback)
        # 用当前时间做随机种子
        # （其实大可不必：Python 默认就用操作系统熵自动播种，不设也是随机的）
        random.seed(time.time())

    def timer_callback(self):
        # 1. 等待服务端上线
        # ⚠️ 这里在回调里做阻塞等待，见下方分析
        while not self.patrol_client_.wait_for_service(timeout_sec=1.0):
            if not rclpy.ok():
                self.get_logger().error("等待服务的过程中被打断...")
                return
            self.get_logger().info("等待服务端上线中")

        # 2. 构造请求
        request = Patrol.Request()
        request.target_x = float(random.randint(0, 14))   # 闭区间：0~14 共 15 个值
        request.target_y = float(random.randint(0, 14))
        self.get_logger().info(
            f"请求巡逻: ({request.target_x}, {request.target_y})")

        # 3. 发送异步请求，并注册回调处理结果
        # add_done_callback：future 完成时自动调用 response_callback，不阻塞当前回调
        self.patrol_client_.call_async(request).add_done_callback(
            self.response_callback)

    def response_callback(self, future):
        response = future.result()
        if response.result == Patrol.Response.SUCCESS:
            self.get_logger().info("目标点处理成功")
        elif response.result == Patrol.Response.FAIL:
            self.get_logger().info("目标点处理失败")


def main(args=None):
    rclpy.init(args=args)
    node = PatrolClient()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```


> ⚠️ **原笔记这里有个值得认真对待的设计问题：在定时器回调里阻塞等**
>
> ```python
> while not self.patrol_client_.wait_for_service(timeout_sec=1.0):
> ```
>
> 这行本身能跑，但在**单线程 executor**（`rclpy.spin` 的默认行为）下，它会把**整个节点**卡住：
>
> | 被卡住的 | 后果 |
> |---|---|
> | 其它定时器 | 不触发 |
> | 服务响应回调 | 收不到（`response_callback` 永远不执行） |
> | 订阅回调 | 收不到消息 |
>
> 因为**所有回调共享同一个 spin 线程**。等待期间它一直在 `while` 里空转，别的回调根本没有机会执行。
>
> **更重要的是**：`wait_for_service` 等的是"服务端上线"，而 `response_callback` 恰恰要靠同一个线程才能被调用。所以一旦服务端没启动，这个节点就彻底卡死，连日志都不再输出。
>
> **正确做法**：不在回调里阻塞。要么先发请求、服务没上线就跳过这个周期：
>
> ```python
> def timer_callback(self):
>     if not self.patrol_client_.service_is_ready():   # 非阻塞检查
>         self.get_logger().info("服务端未就绪，跳过本次")
>         return
>     request = Patrol.Request()
>     ...
> ```
>
> 要么给节点用多线程 executor（`rclpy.executors.MultiThreadedExecutor`），让不同回调能并行。**这是 ROS 2 里最容易踩、也最值得记住的一类坑：回调要短。**

`demo.launch.py`

```python
import launch
import launch_ros


def generate_launch_description():
    # 函数名必须是 generate_launch_description，launch 系统靠它拿到启动描述
    action_node_turtle_control = launch_ros.actions.Node(
        package='demo_python_service',    # 包名：必须与 ros2 pkg create 时一致
        executable='turtle_control',      # 可执行文件名：来自 setup.py 的 entry_points
        output='screen',                  # 日志输出到终端（调试时最常用）
    )
    action_node_patrol_client = launch_ros.actions.Node(
        package='demo_python_service',
        executable='patrol_client',
        output='log',                     # 日志只写文件，不打印到终端
    )
    action_node_turtlesim_node = launch_ros.actions.Node(
        package='turtlesim',              # 系统自带的包，同样能启动
        executable='turtlesim_node',
        output='both',                    # 同时输出到终端和日志文件
    )

    # 合成启动描述并返回
    launch_description = launch.LaunchDescription([
        action_node_turtle_control,
        action_node_patrol_client,
        action_node_turtlesim_node,
    ])
    return launch_description
```


> ⚠️ **原笔记两处 `package='demo_python_service1'` 都写错了**（已修正为 `demo_python_service`）。多了个 `1` 会导致 launch 报 `Package 'demo_python_service1' not found`，整个 launch 直接失败。
> 全文出现过 `demo_python_pkg`、`Ros2_learn`、`demo_python_service`、`demo_python_service1` 四个名字，**跟做时务必统一成你实际创建的包名**。

> 💡 **知识点：`output` 的三个取值**
>
> | 取值 | 含义 | 什么时候用 |
> |---|---|---|
> | `'screen'` | 打印到当前终端 | **调试首选**，能立刻看到报错 |
> | `'log'` | 只写入 `~/.ros/log/` | 节点多、刷屏严重时 |
> | `'both'` | 两者都输出 | 既要看又要留档 |
>
> 另外 `package` 和 `executable` 是**最容易配错的两个字段**：
> - `package` = `ros2 pkg create` 时的包名；
> - `executable` = `setup.py` 里 `entry_points` 中等号**左边**那个名字（**不是**文件名，也不是函数名）。
>
> 手动验证方法：先 `ros2 run 包名 可执行名` 能跑通，再写进 launch 就一定对。

`setup.py` 写入：

```python
import os
from glob import glob

setup(
    ...
    data_files=[
        ('share/ament_index/resource_index/packages',
            ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        # 把 launch 目录下的脚本安装到 share/<包名>/launch/
        # 这样 ros2 launch <包名> xxx.launch.py 才能找到它
        (os.path.join('share', package_name, 'launch'),
            glob('launch/*.launch.py')),
    ],
    ...
)
```


> 💡 **知识点：为什么 launch 文件也必须登记**
>
> `ros2 launch` 是在 **install 目录**里找 launch 文件的（和你运行节点是同一个逻辑），而不是在你的源码目录里找。所以不写进 `data_files`，`ros2 launch` 就会报 `file not found`。
>
> 启动命令：
> ```bash
> ros2 launch demo_python_service demo.launch.py
> ```
> 格式是 `ros2 launch 包名 launch文件名`。
>
> **launch 的真正价值不只是"少开几个终端"**，而是：
> - 统一管理参数、命名空间、话题重映射；
> - 处理**启动顺序和依赖**（可以等某个节点就绪再启动下一个）；
> - 一个 launch 文件就是一份可复现的系统配置，团队协作时不会"你那边能跑我这边不行"。
