> **目标**：从一个空目录开始，做出一个能在仿真里自主巡检的小车。
> 建模 → 进 Gazebo → 建图 → Nav2 导航 → 按路点巡检（记录 / 拍照 / 播报）→ 录包复盘。

## 怎么用这份手册

**① 一步一步来。** 每章只干一件事，做完立刻验证再进下一章。每章末尾都有 **「本章收尾」**，
告诉你这一章要改什么、跑什么命令验证。

**② 不要提前写后面的东西。** 每章只创建这一步真正用到的文件。`CMakeLists.txt` 会**随着文件出现而长大**——
第 2 章它只有 `ros2 pkg create` 的默认内容，**第一个 `install(...)` 要到第 4 章才出现**，最后一段在第 9 章。
原因很硬：`install(DIRECTORY urdf ...)` 里的目录、`install(PROGRAMS xxx.py ...)` 里的脚本
**必须真实存在**，否则 `colcon build` 直接报 `file INSTALL cannot find ...`。提前抄一份"最终版"只会在第 2 章卡死。

**③ 代码块都是从真文件里拼进来的。** 标了文件路径的代码块，都是工作空间里**已经跑通的那一份原文**
（生成方式见[附录 C](#附录-c这份文档是怎么生成的)）。

**命令约定**：所有命令在工作空间根目录下执行，`$WS` 代指它。

```bash
export WS=~/VoVL773/ROS2/patrol_ws
```


> **验证程度（诚实说明）**
>
> 完整链路已端到端实测：`patrol_sim.launch.py` 一键启动后，4 个巡检点位依次 `SUCCEEDED`
> （约 2 分钟一圈），照片 / CSV / 语音全部正常，`Failed to create plan` 与 `Failed to make progress` 各 0 次。
>
> **唯一没验证的**是 7.2「自动巡航建出来的 SLAM 地图质量」——那个节点能跑、不撞墙，
> 但它产出的地图没被验收；本手册的导航链路走的是 7.4 渲染的**真值地图**。
> 想一条路走到底，直接用 7.4。

## 第 2 章 建两个空包，先让它编译过

这一章**不写任何实际功能**，目标只有一个：让两个包能 `colcon build` 通过。
后面每一章再往里加东西。

### 2.1 建包

```bash
export WS=~/VoVL773/ROS2/patrol_ws
mkdir -p $WS/src && cd $WS/src

source /opt/ros/jazzy/setup.bash
ros2 pkg create --build-type ament_cmake fishbot_description
ros2 pkg create --build-type ament_cmake fishbot_navigation2

# 目录骨架：先把目录建出来，后面写文件时不用再 mkdir
mkdir -p fishbot_description/{urdf/fishbot/{sensor,plugins},launch,world,config,scripts}
mkdir -p fishbot_navigation2/{launch,param,maps,scripts}
```


> ⚠️ **必须用一个全新的空目录**。`ros2 pkg create` 在"包已存在"的目录里会直接报
> `package already exists`；而且两个项目共用一个 `install/`，`source` 之后话题和参数会互相污染。

**为什么是两个包**：

| 包 | 放什么 | 为什么分开 |
|---|---|---|
| `fishbot_description` | 模型（urdf/xacro）、世界（sdf）、launch、配置 | 只装**数据**不装代码，用 `install(DIRECTORY ...)` 最省事 |
| `fishbot_navigation2` | 地图、Nav2 参数、巡检节点、launch | 换机器人不用动导航配置，换导航策略也不用动模型 |

> 所以不急着一次写全——本手册在第 5 章（仿真相关）和第 8 章（导航相关）各补一批。

它们会在第 4、5、7、8、9 章**随着文件出现而逐步加上去**（见 0.3 的表）。

确认一下内容（不用改，看一眼就行）：

```bash

```

```bash

## 第 3 章 建模：用 URDF/Xacro 把小车拼出来

本章只产出 `.xacro` 文本文件。**验证方式是直接用 `xacro` 展开**，
不需要 `colcon build`，所以这一章 CMakeLists 依旧不用动。

### 3.0 先建立三个概念

| 概念 | 说明 | 本项目里的例子 |
|---|---|---|
| **link（连杆）** | 一个"刚体"，可以是几何形状 | 车身 `base_link`、左轮 `left_wheel_link` |
| **joint（关节）** | 两个 link 之间怎么连、能不能动 | `left_wheel_joint` 是 `continuous`（能连续转） |
| **visual / collision / inertial** | 同一个 link 的三个"身份" | 看得见的样子 / 撞得到的外形 / 质量与惯量 |

> ⚠️ **只写 `<visual>` 是初学者最常见的错**：
> - 没有 `<collision>` → 车**穿过地面掉下去**，或者穿墙
> - 没有 `<inertial>` → 物理引擎抱怨并**瞎猜质量**，车会抖、会飘
>
> 所以在 RViz 里看起来"好好的"模型，进 Gazebo 可能要重做——**这三个必须成套写**。

### 3.1 惯量公式：`common_inertia.xacro`

文件：`src/fishbot_description/urdf/fishbot/common_inertia.xacro`

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

    <xacro:macro name="box_inertia" params="m x y z">
        <inertial>
            <origin xyz="0.0 0.0 0.0" rpy="0.0 0.0 0.0"/>
            <mass value="${m}"/>
            <inertia ixx="${m*(y*y+z*z)/12}" ixy="0" ixz="0"
                     iyy="${m*(x*x+z*z)/12}" iyz="0"
                     izz="${m*(x*x+y*y)/12}"/>
        </inertial>
    </xacro:macro>

    <xacro:macro name="cylinder_inertia" params="m r h rpy:='0 0 0'">
        <inertial>
            <origin xyz="0.0 0.0 0.0" rpy="${rpy}"/>
            <mass value="${m}"/>
            <inertia ixx="${m*(3*r*r+h*h)/12}" ixy="0" ixz="0"
                     iyy="${m*(3*r*r+h*h)/12}" iyz="0"
                     izz="${m*r*r/2}"/>
        </inertial>
    </xacro:macro>
    <xacro:macro name="sphere_inertia" params="m r">
        <inertial>
            <origin xyz="0 0 0" rpy="0 0 0"/>
            <mass value="${m}"/>
            <inertia ixx="${2*m*r*r/5}" ixy="0" ixz="0"
                     iyy="${2*m*r*r/5}" iyz="0"
                     izz="${2*m*r*r/5}"/>
        </inertial>
    </xacro:macro>
</robot>
```


**它在干什么**：把"质量 + 尺寸 → 惯量张量"的公式写成三个宏，后面每个 link 直接调，避免手抄公式抄错。

| 宏 | 用途 | 公式要点 |
|---|---|---|
| `box_inertia` | 方块 | `ixx = m(y²+z²)/12` |
| `cylinder_inertia` | 圆柱（车身、轮子） | `ixx = m(3r²+h²)/12`，`izz = mr²/2` |
| `sphere_inertia` | 球（万向轮） | `i = 2mr²/5` |

> 💡 `cylinder_inertia` 有个 `rpy` 参数（默认 `0 0 0`）。**轮子会用到它**——原因见 3.3。

### 3.2 车身：`base.urdf.xacro`

文件：`src/fishbot_description/urdf/fishbot/base.urdf.xacro`

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:include filename="common_inertia.xacro"/>

    <xacro:macro name="base_xacro" params="length radius">

        <!-- ① 导航用的"贴地虚拟根"：Nav2 要求机器人有一个 z=0 的根坐标系 -->
        <link name="base_footprint"/>

        <!-- ② 车身本体 -->
        <link name="base_link">
            <visual>
                <origin xyz="0 0 0" rpy="0 0 0"/>
                <geometry>
                    <cylinder radius="${radius}" length="${length}"/>
                </geometry>
                <material name="white">
                    <color rgba="1.0 1.0 1.0 0.8"/>
                </material>
            </visual>

            <!-- 仿真必须有 collision，否则会直接穿过地面 -->
            <collision>
                <origin xyz="0 0 0" rpy="0 0 0"/>
                <geometry>
                    <cylinder radius="${radius}" length="${length}"/>
                </geometry>
            </collision>

            <!-- 仿真必须有 inertial，否则物理引擎会警告并给个乱猜的质量 -->
            <xacro:cylinder_inertia m="1.0" r="${radius}" h="${length}"/>
        </link>

        <joint name="base_joint" type="fixed">
            <parent link="base_footprint"/>
            <child link="base_link"/>
            <!-- 车身抬高到 ${length/2 + 0.01}，让轮子刚好着地 -->
            <origin xyz="0 0 ${length/2 + 0.01}" rpy="0 0 0"/>
        </joint>

    </xacro:macro>
</robot>
```


**三个设计要点**：

1. **为什么要 `base_footprint`？** 它是一个"贴地的虚拟根"（z=0）。Nav2 要求机器人有一个
   地面投影坐标系，用来算代价地图和路径。
2. **`base_link` 被抬高了 `length/2 + 0.01`**：圆柱的中心在几何中心，抬到"底面刚好在地面上方 1cm"，
   这样轮子才能着地。
3. **`base_joint` 是 `fixed`**：车身和 `base_footprint` 之间没有自由度。
   `fixed` 关节**不要写 `<axis>`**（写了没意义）。

### 3.3 驱动轮：`wheel.urdf.xacro`

文件：`src/fishbot_description/urdf/fishbot/wheel.urdf.xacro`

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:include filename="common_inertia.xacro"/>

    <xacro:macro name="wheel_xacro" params="wheel_name xyz">
        <link name="${wheel_name}_wheel_link">
            <visual>
                <!-- 圆柱默认轴沿 Z；绕 X 转 90° 后轴变成 Y，才能绕 Y 滚动 -->
                <origin xyz="0 0 0" rpy="1.5707963 0 0"/>
                <geometry>
                    <cylinder radius="0.032" length="0.02"/>
                </geometry>
                <material name="yellow">
                    <color rgba="1.0 1.0 0.0 1.0"/>
                </material>
            </visual>

            <collision>
                <origin xyz="0 0 0" rpy="1.5707963 0 0"/>
                <geometry>
                    <cylinder radius="0.032" length="0.02"/>
                </geometry>
            </collision>

            <!-- rpy 要和上面一致，惯量才跟着转过去 -->
            <xacro:cylinder_inertia m="0.05" r="0.032" h="0.02" rpy="1.5707963 0 0"/>
        </link>

        <joint name="${wheel_name}_wheel_joint" type="continuous">
            <origin xyz="${xyz}"/>
            <parent link="base_link"/>
            <child link="${wheel_name}_wheel_link"/>
            <axis xyz="0 1 0"/>
        </joint>

        <!-- 橡胶胎要有抓地力，不然原地打滑、里程计乱飘 -->
        <gazebo reference="${wheel_name}_wheel_link">
            <mu1 value="20.0"/>
            <mu2 value="20.0"/>
            <kp value="1000000000.0"/>
            <kd value="1.0"/>
        </gazebo>
    </xacro:macro>
</robot>
```


**三个设计要点**：

1. **圆柱默认轴是 Z，必须转 90°**：`<origin rpy="1.5707963 0 0"/>` 让轴变成 Y 方向，轮子才能绕 Y 滚。
   ⚠️ 忘了转不报错，但 RViz 里轮子是"立着的圆桶"。
2. **惯量的 `rpy` 要跟 geometry 一致**：否则惯量张量还是按 Z 轴算的，物理表现会很怪。
3. **`mu1/mu2 = 20`（橡胶胎抓地力）**：摩擦给太小，轮子原地打滑，**里程计会乱飘**，
   SLAM 建出来的图会有"鬼影"。

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="fishbot">

    <!-- ========== 引入各个部件 ========== -->
    <xacro:include filename="base.urdf.xacro"/>
    <xacro:include filename="wheel.urdf.xacro"/>
    <xacro:include filename="caster.urdf.xacro"/>
    <xacro:include filename="sensor/imu.urdf.xacro"/>

    <xacro:include filename="plugins/gazebo_sensor_plugin.xacro"/>

    <!-- ========== 参数（要改尺寸就改这里）========== -->
    <xacro:property name="base_length" value="0.12"/>
    <xacro:property name="base_radius" value="0.10"/>
    <xacro:property name="wheel_sep"   value="0.20"/>

    <!-- ========== 装配 ========== -->
    <xacro:base_xacro length="${base_length}" radius="${base_radius}"/>

    <!-- 左右驱动轮：y 方向各偏 ±轮距/2，z 让轮心落在 0.032（= 轮半径，刚好着地）
         车身中心在 z = base_length/2 + 0.01 = 0.07，所以相对车身是 0.032 - 0.07 = -0.038 -->
    <xacro:wheel_xacro wheel_name="left"  xyz="0  ${wheel_sep/2} -0.038"/>
    <xacro:wheel_xacro wheel_name="right" xyz="0 -${wheel_sep/2} -0.038"/>

    <!-- 万向轮：放在车头前方，球心离地 0.01 -->
    <xacro:caster_xacro xyz="0.08 0 -0.06"/>

    <!-- 传感器 -->
    <xacro:imu_xacro    xyz="0 0 0.02"/>
    <xacro:laser_xacro  xyz="0 0 0.10"/>
    <xacro:camera_xacro xyz="0.10 0 0.075"/>

    <!-- ========== 仿真插件 ========== -->
    <xacro:gazebo_control_plugin/>
    <xacro:gazebo_sensor_plugin/>

</robot>
```


> ⚠️ 这个文件里还 `include` 了第 5 章才写的两个插件文件，
> 所以**现在直接用 `xacro` 展开会报"找不到 plugins/*.xacro"**。
> 本章的验证只针对 3.1~3.5 那 6 个文件，总装留到第 5 章一起验。

**尺寸参数表**（要改尺寸只改这里）：

| 参数 | 值 | 含义 |
|---|---|---|
| `base_length` | 0.12 | 车身圆柱的高（**竖直方向**） |
| `base_radius` | 0.10 | 车身圆柱的半径 |
| `wheel_sep` | 0.20 | 轮距（左右轮中心距），第 5 章的差速插件必须填一样 |

**装配坐标是怎么算出来的**（初学最容易照抄而不理解的地方）：

| 部件 | 坐标 | 推导 |
|---|---|---|
| 左轮 | `0  0.10 -0.038` | y = +轮距/2 = +0.10；z：轮心要离地 0.032（=轮半径），车身中心在 0.07，所以相对车身是 `0.032 - 0.07 = -0.038` |
| 右轮 | `0 -0.10 -0.038` | 同上，y 取负 |
| 万向轮 | `0.08 0 -0.06` | 车头前方 8cm；球心离地 0.01 → 相对车身 `0.01 - 0.07 = -0.06` |
| IMU | `0 0 0.02` | 车身中心略上 |
| 激光 | `0 0 0.10` | 越高越不容易被车身挡住视线 |
| 相机 | `0.10 0 0.075` | 车头最前、略高，朝前看 |

> 💡 **改尺寸时要连带重算这几个 z 坐标**，否则轮子会陷进地里或悬空。
> 这也是为什么把尺寸写成 `<xacro:property>` 而不是散落各处的数字。

### 4.1 写第一个 launch

文件：`src/fishbot_description/launch/display_robot.launch.py`

```python
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.substitutions import Command
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg_share = get_package_share_directory('fishbot_description')
    xacro_file = os.path.join(pkg_share, 'urdf', 'fishbot', 'fishbot.urdf.xacro')

    robot_description = ParameterValue(Command(['xacro ', xacro_file]), value_type=str)

    return LaunchDescription([
        Node(
            package='robot_state_publisher',
            executable='robot_state_publisher',
            parameters=[{'robot_description': robot_description}],
            output='screen'),
        Node(
            package='joint_state_publisher_gui',
            executable='joint_state_publisher_gui',
            output='screen'),
        Node(
            package='rviz2',
            executable='rviz2',
            output='screen'),
    ])
```


**逐段讲解**：

| 代码 | 作用 | 坑 |
|---|---|---|
| `ParameterValue(Command(['xacro ', xacro_file]), value_type=str)` | 把 `.xacro` 展开成 URDF 字符串，作为 `robot_description` 参数传给节点 | ⚠️ **必须包 `ParameterValue(..., value_type=str)`**：不包的话 launch 会把它当 YAML 解析，URDF 里的数字/冒号会解析失败 |
| `robot_state_publisher` | 按 URDF 的关节关系发布 TF | 它只发**静态关节 + 由 `joint_states` 驱动的关节** |
| `joint_state_publisher_gui` | 弹一个小窗口，可以拖动轮子转 | 建模阶段用它确认"轮子转轴对不对" |
| `get_package_share_directory('fishbot_description')` | 拿到 `install/` 里的路径 | ⚠️ 改完 xacro 要重新 `colcon build` 才会同步到 `install/` |

## 第 5 章 让它进 Gazebo（插件 + 世界 + 桥接）

从 RViz 到物理仿真。这一章要理解一件事：

> **Harmonic 不会自动把 ROS 的东西塞进仿真。** 想让车能被 `/cmd_vel` 驱动、想让雷达出数据，
> 必须在 URDF 里写**插件**（`<gazebo><plugin>`），在世界文件里挂**系统插件**，
> 还要用 `ros_gz_bridge` 把 gz 话题桥到 ROS。三件事缺一不可。

### 5.1 差速控制插件

文件：`src/fishbot_description/urdf/fishbot/plugins/gazebo_control_plugin.xacro`

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">
    <xacro:macro name="gazebo_control_plugin">
        <gazebo>
            <plugin filename="gz-sim-diff-drive-system"
                    name="gz::sim::systems::DiffDrive">
                <left_joint>left_wheel_joint</left_joint>
                <right_joint>right_wheel_joint</right_joint>

                <!-- 运动学：轮距与轮半径，正逆解和里程计都靠它俩 -->
                <wheel_separation>0.20</wheel_separation>
                <wheel_radius>0.032</wheel_radius>

                <odom_publish_frequency>30</odom_publish_frequency>

                <!-- ★ 必须显式指定子坐标系，否则 TF 树是【断的】
                     默认值是 "<模型名>/base_footprint"，也就是 fishbot/base_footprint，
                     而 URDF 里机器人根是 base_footprint —— 两段接不上，
                     RViz 里机器人和雷达都渲染不出来。
                     （odom 帧在 Harmonic 里写死是 "<模型名>/odom"，没有参数可改） -->
                <child_frame_id>base_footprint</child_frame_id>

                <max_linear_acceleration>1.0</max_linear_acceleration>
                <min_linear_acceleration>-1.0</min_linear_acceleration>
                <max_angular_acceleration>2.0</max_angular_acceleration>
                <min_angular_acceleration>-2.0</min_angular_acceleration>
                <max_linear_velocity>0.5</max_linear_velocity>
                <min_linear_velocity>-0.5</min_linear_velocity>
                <max_angular_velocity>1.0</max_angular_velocity>
                <min_angular_velocity>-1.0</min_angular_velocity>

**逐项讲解**：

| 参数 | 值 | 说明 |
|---|---|---|
| `left_joint` / `right_joint` | `left_wheel_joint` / `right_wheel_joint` | 必须是 URDF 里**真实存在**的关节名 |
| `wheel_separation` | 0.20 | **必须和 3.6 的 `wheel_sep` 一致**，否则转向角速度算错 |
| `wheel_radius` | 0.032 | ⚠️ **是半径不是直径**！填成直径里程计会差一倍 |
| `child_frame_id` | `base_footprint` | ⚠️ **不写就是断的 TF 树**，见下面 |
| `max_linear_velocity` | 0.5 | 后面 Nav2 的 `max_vel_x` **不要超过它** |

> ⚠️⚠️ **全篇最关键的一个坑：`child_frame_id`**
>
> Harmonic 的 DiffDrive 默认把子坐标系叫 `<模型名>/base_footprint`（即 `fishbot/base_footprint`），
> 而你 URDF 里的机器人根是 `base_footprint` —— **两段接不上，TF 树是断的**，
> 表现为：RViz 里机器人和雷达都渲染不出来、Nav2 一起来就报 TF 找不到。
>
> 另外：**`odom` 帧名在 Harmonic 里写死是 `<模型名>/odom`**（即 `fishbot/odom`），**没有参数可以改**。
> 记住这个名字，第 7 章（SLAM）和第 8 章（Nav2）都要用它。

```python
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription, RegisterEventHandler, DeclareLaunchArgument
from launch.conditions import IfCondition
from launch.event_handlers import OnProcessExit
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import Command, LaunchConfiguration
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue


def generate_launch_description():
    pkg_share = get_package_share_directory('fishbot_description')

    xacro_file = os.path.join(pkg_share, 'urdf', 'fishbot', 'fishbot.urdf.xacro')
    world_file = os.path.join(pkg_share, 'world', 'fishbot.sdf')
    robot_description = ParameterValue(Command(['xacro ', xacro_file]), value_type=str)

    model_name = 'fishbot'

    # ① 启动 Gazebo Harmonic
    #    注意：gz_sim.launch.py 没有 world 参数，世界是通过 gz_args 传的
    gz_sim = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(get_package_share_directory('ros_gz_sim'),
                         'launch', 'gz_sim.launch.py')),
        launch_arguments={'gz_args': '-r ' + world_file}.items())

    # ② URDF -> /robot_description
    robot_state_publisher = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        parameters=[{'robot_description': robot_description,
                     'use_sim_time': True}],
        output='screen')

    # ③ 从 /robot_description 把机器人生成到世界里
    spawn_entity = Node(
        package='ros_gz_sim',
        executable='create',
        arguments=['-world', 'default',
                   '-topic', 'robot_description',
                   '-name', model_name,
                   '-z', '0.3'],
        output='screen')

    # ④ 桥接：gz 话题 <-> ROS 话题
    #    方向符： [ = gz→ROS    ] = ROS→gz    @ = 双向
    bridge = Node(
        package='ros_gz_bridge',
        executable='parameter_bridge',
        arguments=[
            # 仿真时钟（Gazebo 出，ROS 收）
            '/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock',

            # 差速驱动：速度指令 ROS→gz，里程计和 TF 是 gz→ROS
            f'/model/{model_name}/cmd_vel@geometry_msgs/msg/Twist]gz.msgs.Twist',
            f'/model/{model_name}/odometry@nav_msgs/msg/Odometry[gz.msgs.Odometry',
            f'/model/{model_name}/tf@tf2_msgs/msg/TFMessage[gz.msgs.Pose_V',

            # 传感器
            '/scan@sensor_msgs/msg/LaserScan[gz.msgs.LaserScan',
            '/imu@sensor_msgs/msg/Imu[gz.msgs.IMU',
        ],
        remappings=[
            # 把 gz 那套名字映射成 ROS 里通用的名字
            (f'/model/{model_name}/cmd_vel',  '/cmd_vel'),
            (f'/model/{model_name}/odometry', '/odom'),
            (f'/model/{model_name}/tf',       '/tf'),
        ],
        parameters=[{'use_sim_time': True}],
        output='screen')

    # ⑤ RViz
    rviz = Node(
        package='rviz2',
        executable='rviz2',
        parameters=[{'use_sim_time': True}],
        output='screen')

    # ⑥ SLAM 建图（slam_toolbox 异步模式），订阅 /scan + TF，发布 /map
    slam_params_file = os.path.join(pkg_share, 'config',
                                    'mapper_params_online_async.yaml')
    slam = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(get_package_share_directory('slam_toolbox'),
                         'launch', 'online_async_launch.py')),
        launch_arguments={
            'use_sim_time': 'true',
            'slam_params_file': slam_params_file,
        }.items(),
        condition=IfCondition(LaunchConfiguration('slam')),)

    # ⑦ 自动巡航建图（默认开启；想手动遥控就传 auto_explore:=false）
    auto_explore = Node(
        package='fishbot_description',
        executable='auto_explore',
        name='auto_explore',
        parameters=[{'use_sim_time': True}],
        condition=IfCondition(LaunchConfiguration('auto_explore')),
        output='screen')

    return LaunchDescription([
        DeclareLaunchArgument(
            'auto_explore', default_value='true',
            description='是否启动自动巡航避障节点（false 时可手动 teleop）'),
        DeclareLaunchArgument(
            'slam', default_value='true',
            description='true=建图模式（起 slam_toolbox）；false=导航模式（用地图+AMCL）'),
        gz_sim,
        robot_state_publisher,
        spawn_entity,
        bridge,
        slam,
        auto_explore,
        rviz,
    ])
```


**七段逐一讲解**：

| 段 | 干什么 | 关键点 / 坑 |
|---|---|---|
| ① `gz_sim` | 启动 Gazebo 并载入世界 | ⚠️ `gz_sim.launch.py` **没有 `world` 参数**，世界是通过 `gz_args='-r 世界路径'` 传的 |

### 7.2 自动巡航建图脚本

文件：`src/fishbot_description/scripts/auto_explore.py`

```python
#!/usr/bin/env python3
"""自主探索建图：基于"边界（frontier）"的探索节点。

为什么不再用旧的反应式逻辑
    旧版见同目录 `auto_explore_reactive.py.bak`：前方有障碍就转向"更宽的一侧"。
    在有房间的户型里，房间是封闭小空间、大厅是开阔大空间 —— 它每次都选大厅，
    结构性回避门洞，所以永远进不去房间，地图只有客厅。

新版的思路（先看图，再决定去哪）
    1) 订阅 /map（slam_toolbox 发布），找出"已知空闲格 紧邻 未知格"的边界点（frontier）
    2) 把相邻的边界点**聚成一簇**（避免贴着墙一个个啃）
    3) 挑"离自己最近 + 有视线（中间不隔墙）+ 没被拉黑"的簇，朝**簇心**走
    4) 朝目标：先转向对准，再直行；同时用 /scan 做紧急避障
    5) 到达 / 超时 / 卡住 → 拉黑，换下一簇
    6) 再也找不到 frontier → 宣布探索完成，并打印存图命令

为什么这样才进得去房间
    门洞在地图上就是"空闲走廊连着未知区域"的边界。frontier 算法主动朝"未知"走，
    并且**有视线检查**，所以不会因为房间比大厅窄就掉头，也不会去啃墙后面的点。

依赖：/map、/scan、/odom、TF(map → base_footprint)
"""
import math
import time

import rclpy
from geometry_msgs.msg import Twist
from nav_msgs.msg import OccupancyGrid, Odometry
from rclpy.node import Node
from rclpy.time import Time
from sensor_msgs.msg import LaserScan
from tf2_ros import Buffer, TransformListener

# ===== 调参区 =====
CONTROL_HZ = 10.0            # 控制频率
REPLAN_PERIOD = 1.0          # 每隔多久重新挑一次目标（秒）
FORWARD_SPEED = 0.18         # m/s，慢一点，建图质量好
BACK_SPEED = -0.12           # m/s
YAW_KP = 1.8                 # 朝向比例增益
MAX_TURN = 1.0               # rad/s 上限
ALIGN_TOL = 0.30             # 朝向误差小于它才允许直行（rad）
FRONT_STOP = 0.38            # 正前方这个距离内有障碍就转向让开（m）
DANGER_STOP = 0.22           # 更近就先后退（m）
FRONT_HALF_ANGLE = 25.0      # 紧急避障用的前方扇区半角（度）
SIDE_ANGLE = (40.0, 140.0)   # 左右侧扇区（度，左侧为正）
GOAL_TOL = 0.40              # 到目标这么近算到达（m）
MIN_GOAL_DIST = 1.0          # 比这更近的边界簇忽略（避免贴着墙一点点啃）
MAX_GOAL_DIST = 8.0          # 比这更远的忽略（不横跨整个房子）
CLUSTER_RADIUS = 0.5         # 边界点聚类半径（m）
BLACKLIST_RADIUS = 0.80      # 拉黑半径（m）
LOS_STEP = 0.05              # 视线检查采样步长（m）
GOAL_TIMEOUT = 30.0          # 单个目标最长尝试时间（秒）
STUCK_TIME = 3.0             # 判定"轮子转但车不动"的时间（秒）
STUCK_SPEED = 0.05           # 实测速度低于它算没动（m/s）
BACK_TIME = 0.6              # 后退持续（秒）
MAX_RUNTIME = 900.0          # 总时限（秒），到点强制停
EMPTY_FRONTIER_ROUNDS = 15   # 连续这么多轮找不到边界就宣布探索完成


# ===== 纯函数区（不依赖 ROS，便于单独测试）=====
def find_frontiers(data, width, height, origin_x, origin_y, resolution,
                   stride=2, min_unknown_neighbors=1):
    """找出所有「空闲格且紧邻未知格」的格子。

    data: OccupancyGrid.data（0=空闲, 100=障碍, -1=未知）
    返回 [(x, y, 未知邻居个数), ...]，世界坐标。
    """
    out = []
    for r in range(1, height - 1, stride):
        base = r * width
        for c in range(1, width - 1, stride):
            i = base + c
            if data[i] != 0:                      # 只从空闲格出发
                continue
            unknown = 0
            if data[i + 1] == -1:
                unknown += 1
            if data[i - 1] == -1:
                unknown += 1
            if data[i + width] == -1:
                unknown += 1
            if data[i - width] == -1:
                unknown += 1
            if unknown >= min_unknown_neighbors:
                out.append((origin_x + (c + 0.5) * resolution,
                            origin_y + (r + 0.5) * resolution,
                            unknown))
    return out


def has_line_of_sight(data, width, height, origin_x, origin_y, resolution,
                      x0, y0, x1, y1, step=LOS_STEP):
    """从 (x0,y0) 到 (x1,y1) 的直线是否不穿过障碍格（用来排除"墙后面的目标"）。"""
    dist = math.hypot(x1 - x0, y1 - y0)
    n = max(1, int(dist / step))
    for k in range(1, n):
        x = x0 + (x1 - x0) * k / n
        y = y0 + (y1 - y0) * k / n
        c = int((x - origin_x) / resolution)
        r = int((y - origin_y) / resolution)
        if not (0 <= c < width and 0 <= r < height):
            return False
        if data[r * width + c] >= 50:             # 撞到障碍
            return False
    return True


def cluster_frontiers(frontiers, radius=CLUSTER_RADIUS):
    """把相邻的边界点聚成簇（贪心），返回 [[(x,y,unknown), ...], ...]。"""
    clusters = []
    for p in frontiers:
        for cl in clusters:
            if any(abs(p[0] - q[0]) <= radius and abs(p[1] - q[1]) <= radius for q in cl):
                cl.append(p)
                break
        else:
            clusters.append([p])
    return clusters


def pick_goal(frontiers, robot_x, robot_y, blacklist, data, width, height,
              origin_x, origin_y, resolution,
              min_dist=MIN_GOAL_DIST, max_dist=MAX_GOAL_DIST,
              blacklist_radius=BLACKLIST_RADIUS, require_los=True):
    """挑"最近的、有视线、没被拉黑"的边界簇。

    返回该簇的代表点：有视线时给**簇心**（朝未知区域里推），否则退化给簇内最近点。
    没有合适目标时返回 None。
    """
    candidates = []
    for cluster in cluster_frontiers(frontiers):
        cx = sum(p[0] for p in cluster) / len(cluster)
        cy = sum(p[1] for p in cluster) / len(cluster)
        nearest = min(cluster, key=lambda p: math.hypot(p[0] - robot_x, p[1] - robot_y))
        d = math.hypot(nearest[0] - robot_x, nearest[1] - robot_y)
        if d < min_dist or d > max_dist:
            continue
        if any(math.hypot(nearest[0] - bx, nearest[1] - by) < blacklist_radius
               for bx, by in blacklist):
            continue
        los = has_line_of_sight(data, width, height, origin_x, origin_y, resolution,
                                robot_x, robot_y, nearest[0], nearest[1])
        candidates.append((d, los, cx, cy, nearest))

    if not candidates:
        return None
    if require_los:
        visible = [c for c in candidates if c[1]]
        if visible:
            candidates = visible
    candidates.sort(key=lambda c: c[0])
    d, los, cx, cy, nearest = candidates[0]
    # ★ 返回簇内"离机器人最近"的边界点，而不是簇心：
    #   簇心可能落在墙后面（例如房间深处），直线开过去会撞墙；
    #   而边界点一定在"已知空闲区"，配合上面的视线检查，目标就总是可达的。
    return (nearest[0], nearest[1])


def normalize_angle(a):
    """把角度折到 [-pi, pi]，避免跨 ±π 时绕远路掉头。"""
    while a > math.pi:
        a -= 2.0 * math.pi
    while a < -math.pi:
        a += 2.0 * math.pi
    return a


class FrontierExplorer(Node):

    def __init__(self):
        super().__init__('auto_explore')
        self.cmd_pub = self.create_publisher(Twist, 'cmd_vel', 10)
        self.create_subscription(OccupancyGrid, 'map', self.on_map, 1)
        self.create_subscription(LaserScan, 'scan', self.on_scan, 10)
        self.create_subscription(Odometry, 'odom', self.on_odom, 10)

        self.tf_buffer = Buffer()
        self.tf_listener = TransformListener(self.tf_buffer, self)

        self.grid = None             # OccupancyGrid
        self.ranges = None
        self.angle_min = 0.0
        self.angle_inc = 0.0
        self.actual_vx = 0.0
        self.pose = None             # map 系下 (x, y, yaw)

        self.goal = None
        self.goal_since = 0.0
        self.blacklist = []          # 试过的目标点（世界坐标）
        self.empty_rounds = 0
        self.stuck_since = None
        self.back_until = 0.0
        self.turn_dir = 1
        self.start_time = time.monotonic()
        self.done = False

        self.create_timer(1.0 / CONTROL_HZ, self.control_loop)
        self.create_timer(REPLAN_PERIOD, self.replan)
        self.get_logger().info('auto_explore（frontier 版）已启动：先看图，再朝"未知区域"走')

    # ---------- 回调 ----------
    def on_map(self, msg):
        self.grid = msg

    def on_scan(self, msg):
        self.ranges = msg.ranges
        self.angle_min = msg.angle_min
        self.angle_inc = msg.angle_increment

    def on_odom(self, msg):
        self.actual_vx = msg.twist.twist.linear.x

    # ---------- 工具 ----------
    def _idx_at(self, deg):
        a = math.radians(deg) % (2.0 * math.pi)
        return int((a - self.angle_min) / self.angle_inc) % len(self.ranges)

    def _sector_min(self, lo_deg, hi_deg):
        """取 [lo, hi] 扇区内的最近距离（度，逆时针为正，支持跨 0°）。"""
        best = float('inf')
        i = self._idx_at(lo_deg)
        end = self._idx_at(hi_deg)
        n = len(self.ranges)
        steps = 0
        while True:
            r = self.ranges[i]
            if r == r and r != float('inf') and r > 0.0:
                best = min(best, r)
            if i == end or steps > n:
                break
            i = (i + 1) % n
            steps += 1
        return best

    def _update_pose(self):
        """从 TF 取 map → base_footprint 的位姿（SLAM 会维护这条变换）。"""
        try:
            tf = self.tf_buffer.lookup_transform('map', 'base_footprint', Time())
        except Exception:                       # noqa: BLE001
            return False
        t = tf.transform.translation
        q = tf.transform.rotation
        yaw = math.atan2(2.0 * (q.w * q.z + q.x * q.y),
                         1.0 - 2.0 * (q.y * q.y + q.z * q.z))
        self.pose = (t.x, t.y, yaw)
        return True

    def _stop(self):
        self.cmd_pub.publish(Twist())

    def finish(self, why):
        self.done = True
        self._stop()
        self.get_logger().info('=' * 56)
        self.get_logger().info(why)
        self.get_logger().info('下一步——存图：')
        self.get_logger().info('  ros2 run nav2_map_server map_saver_cli -f <你的路径>/maps/room')
        self.get_logger().info('再体检：')
        self.get_logger().info('  python3 ~/dsh工作区/tools/地图覆盖检查.py')
        self.get_logger().info('=' * 56)

    # ---------- 选目标 ----------
    def replan(self):
        if self.done or self.grid is None or not self._update_pose():
            return
        info = self.grid.info
        frontiers = find_frontiers(self.grid.data, info.width, info.height,
                                   info.origin.position.x, info.origin.position.y,
                                   info.resolution)
        rx, ry, _ = self.pose

        # 目标还新鲜就继续用（滞回：避免在两个目标之间左右横跳）
        if self.goal is not None:
            age = time.monotonic() - self.goal_since
            dist = math.hypot(self.goal[0] - rx, self.goal[1] - ry)
            if age < GOAL_TIMEOUT and dist > GOAL_TOL:
                return

        goal = pick_goal(frontiers, rx, ry, self.blacklist,
                         self.grid.data, info.width, info.height,
                         info.origin.position.x, info.origin.position.y,
                         info.resolution)
        if goal is None:
            self.goal = None
            self.empty_rounds += 1
            if self.empty_rounds >= EMPTY_FRONTIER_ROUNDS:
                self.finish('地图里已经没有新的边界了：探索完成 ✅')
            return

        self.empty_rounds = 0
        self.goal = goal
        self.goal_since = time.monotonic()
        dist = math.hypot(goal[0] - rx, goal[1] - ry)
        self.get_logger().info(
            f'新目标 ({goal[0]:.2f}, {goal[1]:.2f})  距离 {dist:.2f} m  '
            f'(边界点 {len(frontiers)} 个，已拉黑 {len(self.blacklist)} 个)')

    # ---------- 主控制 ----------
    def control_loop(self):
        cmd = Twist()
        if self.done:
            self.cmd_pub.publish(cmd)
            return
        now = time.monotonic()
        if now - self.start_time > MAX_RUNTIME:
            self.finish(f'到达总时限 {MAX_RUNTIME:.0f} s，停止探索（可用 teleop 补扫剩下的角落）')
            return
        if self.ranges is None or not self._update_pose():
            self.cmd_pub.publish(cmd)          # 等 /scan 和 TF
            return

        # ① 后退让开
        if now < self.back_until:
            cmd.linear.x = BACK_SPEED
            self.cmd_pub.publish(cmd)
            return

        # ② 紧急避障优先于去目标
        front = self._sector_min(-FRONT_HALF_ANGLE, FRONT_HALF_ANGLE)
        if front < DANGER_STOP:
            self.get_logger().warn(f'贴太近 {front:.2f} m，先后退')
            self.back_until = now + BACK_TIME
            cmd.linear.x = BACK_SPEED
            self.cmd_pub.publish(cmd)
            return
        if front < FRONT_STOP:
            left = self._sector_min(*SIDE_ANGLE)
            right = self._sector_min(-SIDE_ANGLE[1], -SIDE_ANGLE[0])
            self.turn_dir = 1 if left >= right else -1
            cmd.angular.z = MAX_TURN * self.turn_dir
            self.cmd_pub.publish(cmd)
            return

        # ③ 朝目标走
        if self.goal is None:
            self.cmd_pub.publish(cmd)
            return
        rx, ry, yaw = self.pose
        err = normalize_angle(math.atan2(self.goal[1] - ry, self.goal[0] - rx) - yaw)
        cmd.angular.z = max(-MAX_TURN, min(MAX_TURN, YAW_KP * err))
        if abs(err) < ALIGN_TOL:
            cmd.linear.x = FORWARD_SPEED
        self.cmd_pub.publish(cmd)

        # ④ 到达判定
        if math.hypot(self.goal[0] - rx, self.goal[1] - ry) < GOAL_TOL:
            self.get_logger().info('到达目标 → 拉黑它，换下一簇')
            self.blacklist.append(self.goal)
            self.goal = None
            return

        # ⑤ 卡住判定（轮子转但车没动）
        if cmd.linear.x > 0.05 and abs(self.actual_vx) < STUCK_SPEED:
            if self.stuck_since is None:
                self.stuck_since = now
            elif now - self.stuck_since > STUCK_TIME:
                self.get_logger().warn('轮子在转但车没动 → 拉黑当前目标，后退换方向')
                self.blacklist.append(self.goal)
                self.goal = None
                self.stuck_since = None
                self.back_until = now + BACK_TIME
        else:
            self.stuck_since = None


def main(args=None):
    rclpy.init(args=args)
    node = FrontierExplorer()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node._stop()                      # 退出前发零速，防止车继续跑
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()

这是一个**基于栅格前沿（frontier）**的探索节点，不是"撞墙就拐"的反应式脚本：

- 从 `/map` 里找**前沿格**（自己空闲、但旁边有未知格子的边界）；
- 用贪心聚类把前沿分成一簇一簇，挑**离车最近的一簇**；
- 在这一簇里选一个"有视线（光线检查不穿墙）、距离合适（1.0~8.0m）"的格子当目标；
- 到不了 / 超时 / 卡住的目标拉黑 0.8m 范围，不再反复尝试；
- 连续 15 轮找不到前沿就**自己收工**，并打印保存地图的命令。

> ⚠️ **为什么强调"前沿"**：早先的版本是"直行 → 前方 0.6m 有障碍就转向更宽的一侧"，
> 实测**永远进不了房间**——门洞处两侧都窄，"选更宽的一侧"总是把它带回大厅，
> 日志一直刷 `前方 0.59m 有障碍（左 x / 右 y），向…转`。所以换成了前沿算法。

```python
#!/usr/bin/env python3
"""把 Gazebo 世界文件（.sdf）直接渲染成 Nav2 用的占据栅格地图。

为什么需要它
    SLAM 建图会受里程计漂移影响，出现重影/墙体错位；而世界文件里每堵墙、每个
    障碍物的坐标都是精确已知的 —— 直接按几何渲染出来的是一张"真值地图"，
    干净、无重影，Nav2 拿它做 AMCL 定位 + 全局规划完全够用。

用法（在工作空间根目录执行，$WS = 你的工作空间）
    python3 src/fishbot_navigation2/scripts/make_map_from_world.py \
        src/fishbot_description/world/fishbot.sdf \
        src/fishbot_navigation2/maps/room

产出
    <输出前缀>.pgm   占据栅格图像（0=障碍 205=未知 254=空闲）
    <输出前缀>.yaml  Nav2 地图元数据

同时会做两件检查：
    1) 各房间采样点是否落在空闲区
    2) 从出生点(0,0)做洪泛填充，报告能否走到每个房间（门洞没被堵死）
"""
import math
import pathlib
import sys
import xml.etree.ElementTree as ET
from collections import deque

FREE, OCC, UNK = 254, 0, 205

# 户型里各房间的内部采样点（世界坐标），用于验证连通性
ROOM_PROBES = {
    '左上房间': (-3.0, 1.8),
    '左下房间': (-4.0, -2.0),
    '右下房间': (2.5, -2.0),
    '大厅': (0.0, 0.0),
}


def parse_obstacles(sdf_path):
    """从 SDF 里抽出所有静态障碍物的世界坐标包围盒 [(x0,y0,x1,y1), ...]（跳过地面 plane）。"""
    root = ET.parse(sdf_path).getroot()
    boxes = []
    for model in root.iter('model'):
        pose_el = model.find('pose')
        px = py = yaw = 0.0
        if pose_el is not None and pose_el.text:
            vals = [float(v) for v in pose_el.text.split()]
            if len(vals) >= 2:
                px, py = vals[0], vals[1]
            if len(vals) >= 6:
                yaw = vals[5]
        for link in model.iter('link'):
            lpose = link.find('pose')
            lx = ly = lyaw = 0.0
            if lpose is not None and lpose.text:
                vals = [float(v) for v in lpose.text.split()]
                if len(vals) >= 2:
                    lx, ly = vals[0], vals[1]
                if len(vals) >= 6:
                    lyaw = vals[5]
            cx, cy = px + lx, py + ly
            total_yaw = yaw + lyaw
            for geom in link.iter('geometry'):
                box = geom.find('box')
                cyl = geom.find('cylinder')
                if box is not None:
                    size = [float(v) for v in box.find('size').text.split()]
                    hx, hy = size[0] / 2.0, size[1] / 2.0
                    # 有 yaw 就按旋转后的外接框算（本项目 yaw 都是 0，这条是保险）
                    ext_x = abs(hx * math.cos(total_yaw)) + abs(hy * math.sin(total_yaw))
                    ext_y = abs(hx * math.sin(total_yaw)) + abs(hy * math.cos(total_yaw))
                    boxes.append((cx - ext_x, cy - ext_y, cx + ext_x, cy + ext_y))
                elif cyl is not None:
                    r = float(cyl.find('radius').text)
                    boxes.append((cx - r, cy - r, cx + r, cy + r))
                # plane（地面）忽略
    return boxes


def render(boxes, res, margin):
    """渲染成占据栅格。返回 (data, width, height, origin_x, origin_y)。"""
    xs = [b[0] for b in boxes] + [b[2] for b in boxes]
    ys = [b[1] for b in boxes] + [b[3] for b in boxes]
    x0 = math.floor((min(xs) - margin) / res) * res
    y0 = math.floor((min(ys) - margin) / res) * res
    x1 = math.ceil((max(xs) + margin) / res) * res
    y1 = math.ceil((max(ys) + margin) / res) * res
    width = int(round((x1 - x0) / res))
    height = int(round((y1 - y0) / res))
    data = [UNK] * (width * height)

    def cell_of(x, y):
        return int((x - x0) / res), int((y - y0) / res)

    # ① 先标记障碍（所有墙和家具的包围盒）
    for bx0, by0, bx1, by1 in boxes:
        c0, r0 = cell_of(bx0, by0)
        c1, r1 = cell_of(bx1, by1)
        for r in range(max(0, r0), min(height, r1 + 1)):
            base = r * width
            for c in range(max(0, c0), min(width, c1 + 1)):
                data[base + c] = OCC

    # ② 外墙内部填成空闲（外轮廓 = 最外圈的墙包围盒）
    outer_x0 = min(b[0] for b in boxes)
    outer_y0 = min(b[1] for b in boxes)
    outer_x1 = max(b[2] for b in boxes)
    outer_y1 = max(b[3] for b in boxes)
    c0, r0 = cell_of(outer_x0, outer_y0)
    c1, r1 = cell_of(outer_x1, outer_y1)
    for r in range(max(0, r0 + 1), min(height, r1)):
        base = r * width
        y = y0 + (r + 0.5) * res
        if not (outer_y0 < y < outer_y1):
            continue
        for c in range(max(0, c0 + 1), min(width, c1)):
            x = x0 + (c + 0.5) * res
            if outer_x0 < x < outer_x1 and data[base + c] == UNK:
                data[base + c] = FREE
    return data, width, height, x0, y0


def flood_fill(data, width, height, origin_x, origin_y, res, seed):
    """从 seed 世界坐标做洪泛，返回可达的空闲格集合。"""
    c = int((seed[0] - origin_x) / res)
    r = int((seed[1] - origin_y) / res)
    if not (0 <= c < width and 0 <= r < height) or data[r * width + c] != FREE:
        return set()
    seen = {(c, r)}
    q = deque([(c, r)])
    while q:
        cc, rr = q.popleft()
        for dc, dr in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nc, nr = cc + dc, rr + dr
            if 0 <= nc < width and 0 <= nr < height and (nc, nr) not in seen:
                if data[nr * width + nc] == FREE:
                    seen.add((nc, nr))
                    q.append((nc, nr))
    return seen


def write_pgm(path, data, width, height):
    """PGM(P5)：第一行对应世界 y 最大处，所以行要倒序写。"""
    with open(path, 'wb') as fh:
        fh.write(b'P5\n%d %d\n255\n' % (width, height))
        for r in range(height - 1, -1, -1):
            fh.write(bytes(data[r * width:(r + 1) * width]))


def main():
    if len(sys.argv) < 3:
        print(__doc__)
        return 1
    sdf_path = pathlib.Path(sys.argv[1]).expanduser()
    out_prefix = pathlib.Path(sys.argv[2]).expanduser()
    res = float(sys.argv[3]) if len(sys.argv) > 3 else 0.05
    margin = float(sys.argv[4]) if len(sys.argv) > 4 else 1.0

    boxes = parse_obstacles(sdf_path)
    print(f'从世界文件读到 {len(boxes)} 个障碍物/墙体包围盒')
    data, width, height, ox, oy = render(boxes, res, margin)
    total = width * height
    free = data.count(FREE)
    occ = data.count(OCC)
    unk = data.count(UNK)
    print(f'栅格 {width} x {height} @ {res} m  origin=({ox:.2f}, {oy:.2f})')
    print(f'空闲 {free*100/total:.1f}%   障碍 {occ*100/total:.1f}%   未知 {unk*100/total:.1f}%')

    # 连通性检查：从出生点(0,0)能不能走到每个房间
    reach = flood_fill(data, width, height, ox, oy, res, (0.0, 0.0))
    print(f'\n从出生点(0,0)洪泛可达空闲格: {len(reach)} 个')
    all_ok = True
    for name, (x, y) in ROOM_PROBES.items():
        c = int((x - ox) / res)
        r = int((y - oy) / res)
        in_free = data[r * width + c] == FREE
        ok = (c, r) in reach
        all_ok &= ok
        tag = '✅ 可达' if ok else ('⚠️ 在该点是空闲但走不到' if in_free else '❌ 不在空闲区')
        print(f'  {name:8s} ({x:>5.1f},{y:>5.1f})  {tag}')

    pgm = out_prefix.with_suffix('.pgm')
    yml = out_prefix.with_suffix('.yaml')
    write_pgm(pgm, data, width, height)
    yml.write_text(
        f'image: {pgm.name}\n'
        f'mode: trinary\n'
        f'resolution: {res}\n'
        f'origin: [{ox:.3f}, {oy:.3f}, 0.0]\n'
        f'negate: 0\n'
        f'occupied_thresh: 0.65\n'
        f'free_thresh: 0.196\n', encoding='utf-8')
    print(f'\n已写出:\n  {pgm}\n  {yml}')
    print('\n结论:', '✅ 地图可用（所有房间都从大厅连通）' if all_ok else '⚠️ 有房间走不到，检查门洞是否被堵')
    return 0


if __name__ == '__main__':
    sys.exit(main())

colcon build --packages-select fishbot_navigation2     # ① 装脚本
source install/setup.bash
ros2 run fishbot_navigation2 make_map_from_world \
  src/fishbot_description/world/fishbot.sdf \
  src/fishbot_navigation2/maps/room                   # ② 生成 room.pgm / room.yaml

colcon build --packages-select fishbot_navigation2     # ③ ★ 第二次：把新生成的地图装进去
ls install/fishbot_navigation2/share/fishbot_navigation2/maps/   # 确认 room.pgm 在里面
```


> ⚠️⚠️ **第 ③ 步绝对不能省。** `install(DIRECTORY maps ...)` 在 `--symlink-install` 下
> 是按**编译那一刻的文件列表**建软链的。如果 `room.pgm` 是编译**之后**才生成的，
> `install/` 里就没有它，于是：
>
> ```
> [map_server] Failed to load image file .../install/.../maps/room.pgm
> [lifecycle_manager_localization] Failed to bring up all requested nodes. Aborting bringup.
> ```
> → map_server 起不来 → 没有 `map→odom` 的 TF → `bt_navigator` 永远是 inactive
> → **每个导航目标都被直接拒绝**（`Action server is inactive. Rejecting the goal.`）
>
> 这个坑实测踩过：报错现场（"目标被拒"）离真正原因（地图没装进 `install/`）非常远，
> 极易查错方向。**养成习惯：生成完地图就再编译一次并 `ls` 确认。**

```

> 否则你要同时调试"建图质量"和"导航参数"两件难事，很容易卡住。
>
> ⚠️ **"未知 35.1%" 是正常的**——那是户型墙外的区域（地图外扩了 1m）。
> 判断地图能不能用的标准不是未知比例，而是上面那句"所有房间都从大厅连通"。
> `room.pgm` 是二进制图像没法贴进文档，所以**这一步必须靠跑脚本得到，不要手抄**。

## 第 8 章 Nav2 导航（★ 参数对齐是关键）

### 8.1 先理解：Nav2 需要四样东西

| 要素 | 本项目的值 | 从哪来 |
|---|---|---|
| 一张地图 | `maps/room.yaml` | 第 7 章生成的 |
| 定位（在地图里知道自己在哪） | **AMCL**（不是 SLAM！） | Nav2 自带 |
| 一套正确的坐标系 | `map → fishbot/odom → base_footprint` | 模型（5.1）+ SLAM/AMCL |
| 一份参数文件 | `param/nav2_params.yaml` | 官方模板 + 你改十几处 |

> ⚠️ **导航阶段一定不要同时开 SLAM**：SLAM 和 AMCL 都会发布 `map→odom`，两个一起跑必然打架。
> 所以仿真那边要用 `slam:=false`（第 10 章会把它固化到一键脚本里）。

### 8.2 拿官方参数当模板

```bash
cd $WS/src/fishbot_navigation2
cp /opt/ros/jazzy/share/nav2_bringup/params/nav2_params.yaml param/nav2_params.yaml
wc -l param/nav2_params.yaml       # 约 500 行；下面只改十几处
```


### 8.3 ★ 必须改的键（漏一处就刷 TF 错，或者进不去房间）

官方模板默认按 TurtleBot3 写（`base_link` + `odom`），而**你的模型是 `base_footprint` + `fishbot/odom`**。

| 段 | 键 | 官方默认 | **改成** | 为什么 |
|---|---|---|---|---|
| `amcl` | `base_frame_id` | `base_link` | **`base_footprint`** | 你模型的导航根 |
| `amcl` | `odom_frame_id` | `odom` | **`fishbot/odom`** | Harmonic 写死的帧名（5.1） |
| `amcl` | `scan_topic` | `scan` | **`/scan`** | 桥出来的话题 |
| `amcl` | `set_initial_pose` | `false` | **`True`** | ★ 开机就用 `initial_pose` 定位，省掉手点 "2D Pose Estimate" |
| `amcl` | `initial_pose` | 无 | **x/y/z/yaw 全 `0.0`** | ★ 车出生在世界 (0,0)，而地图是**按世界坐标**渲染的，所以初值就是 0 |
| `bt_navigator` | `robot_base_frame` | `base_link` | **`base_footprint`** | 同上 |
| `bt_navigator` | `odom_topic` | `odom` | **`/odom`** | 话题名，保持带斜杠 |
| `local_costmap` | `global_frame` | `odom` | **`fishbot/odom`** | 局部代价地图在里程计系里 |
| `local_costmap` / `global_costmap` | `robot_base_frame` | `base_link` | **`base_footprint`** | 同上 |
| `local_costmap` / `global_costmap` | `robot_radius` | `0.22` | **`0.12`** | 你的车半径（3.6：`base_radius=0.10` + 余量） |
| `local_costmap` / `global_costmap` | `inflation_radius` | `0.70` | **`0.22`** | ★ 官方值按大车调的；本户型门洞只有 1.0m，0.70 的膨胀会让规划器"看着门却不敢进" |
| `local_costmap` / `global_costmap` → 雷达层 | 雷达源 `topic` | `scan` | **`/scan`** | 同上 |
| `controller_server` | `FollowPath.max_vel_x` | 0.26 | **≤0.5** | 差速插件上限就是 0.5（5.1） |
| `behavior_server` / `docking_server` | `global_frame` / `odom_frame_id` | `odom` | **`fishbot/odom`** | 恢复行为也在里程计系里 |

> 💡 **一句话记法**：把所有**当坐标系用**的 `odom` 换成 `fishbot/odom`，把所有 `base_link` 换成 `base_footprint`。
> **只改坐标系字段，别改话题名字段**（`odom_topic`、`scan_topic` 是话题名，保持 `/odom`、`/scan`）。

### 8.4 ⚠️ 全局代价地图要**去掉** `obstacle_layer`（否则进不去房间）

这一条不在任何官方"改哪几个键"清单里，但**不做的后果很严重**，所以单独讲。

**现象**：车在大厅里怎么都进不了左侧房间，`planner_server` 反复报

```
GridBased plugin failed to plan from (-1.49, -0.31) to (-3.30, 1.80):
  "Failed to create plan with tolerance of: 0.500000"
```


**原因**（把 `global_costmap` 逐格抓下来和静态地图比对之后才定位到的）：

1. 静态地图本身**完全连通**（用半径 0.12m 的圆盘做 BFS，四个房间都走得到）；
2. 但全局代价图里**多出 1.4~3.5 m² 的"幻影致命障碍"格**，离最近的真墙中位数只有 0.30m —— 那是 AMCL 的
   定位误差（~0.1-0.3m）把激光回波标到了墙外/门洞里；而 `obstacle_layer` 的 `raytrace_max_range: 3.0`
   意味着**超出 3m 的旧标记永远不会被清除**，于是越积越多；
3. 最后 1.0m 宽的门被这些点连成一道"虚线墙"，NavFn 判定不可通行。

**做法**：全局代价图只用 **静态地图 + 膨胀**；实时避障交给 `local_costmap` 的 `voxel_layer`
（它是滚动窗口、会清理旧标记，本来就负责"别撞上突然出现的东西"）：

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      plugins: ["static_layer", "inflation_layer"]   # ★ 去掉 obstacle_layer
      obstacle_layer:
        plugin: "nav2_costmap_2d::ObstacleLayer"
        enabled: False                                # 明确关掉；留着这块当文档
```


> 💡 这么改为什么合理：全局代价图是用来**规划路线**的，用的是我们那份真值静态地图（障碍物一个不少）；
> "会不会撞到东西"由局部代价地图 + 控制器兜底。仿真里没有动态障碍，这样配最稳。

**附录 B 是改好的 `nav2_params.yaml` 全文**，想省事就直接整份覆盖（推荐，能避开一切手改疏漏）。

### 8.5 `launch/navigation2.launch.py`

文件：`src/fishbot_navigation2/launch/navigation2.launch.py`

```python
"""Nav2 导航启动：用现成地图 + AMCL（不启 SLAM）。

用法：
    ros2 launch fishbot_navigation2 navigation2.launch.py
    ros2 launch fishbot_navigation2 navigation2.launch.py map:=/别的/路径/room.yaml
    ros2 launch fishbot_navigation2 navigation2.launch.py --show-args     # 只看参数不启动

三个默认值都指向本项目里的实际文件：
    params_file → param/nav2_params.yaml   （已按 fishbot 的 base_footprint / fishbot/odom 改好）
    map         → maps/room.yaml           （由世界文件渲染的真值地图）
    use_sim_time→ true                     （仿真里必须）
"""
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration


def generate_launch_description():
    nav2_bringup = get_package_share_directory('nav2_bringup')
    my_pkg = get_package_share_directory('fishbot_navigation2')

    params_file = LaunchConfiguration('params_file')
    map_file = LaunchConfiguration('map')
    use_sim_time = LaunchConfiguration('use_sim_time')

    return LaunchDescription([
        DeclareLaunchArgument(
            'params_file',
            default_value=os.path.join(my_pkg, 'param', 'nav2_params.yaml'),
            description='Nav2 参数文件（已按 fishbot 的坐标系改过）'),
        DeclareLaunchArgument(
            'map',
            default_value=os.path.join(my_pkg, 'maps', 'room.yaml'),
            description='地图（由世界文件渲染，所有房间连通）'),
        DeclareLaunchArgument('use_sim_time', default_value='true',
                              description='用仿真时钟'),

        # 直接用官方 bringup，把几个关键开关传进去
        IncludeLaunchDescription(
            PythonLaunchDescriptionSource(
                os.path.join(nav2_bringup, 'launch', 'bringup_launch.py')),
            launch_arguments={
                'slam': 'False',             # ★ 用现成地图 + AMCL；SLAM 由 gazebo_sim 那边控制
                'map': map_file,
                'params_file': params_file,
                'use_sim_time': use_sim_time,
                'autostart': 'true',         # 自动激活生命周期节点，不用手动 configure
                'use_composition': 'False',  # 仿真里不开组合：日志好读、好排错
            }.items(),
        ),
    ])
```


> 💡 三个默认值都指向本项目里的真实文件（参数、地图），所以
> `ros2 launch fishbot_navigation2 navigation2.launch.py` **不带任何参数**就能起。
> 想看有哪些可传参数：加 `--show-args`。

## 第 9 章 巡检节点：走点 → 记录 → 拍照 → 播报

### 9.1 设计思路（先想清楚再写代码）

| 需求 | 做法 | 为什么这么做 |
|---|---|---|
| 按路线走 | **逐个** `goToPose()`，而不是一次 `followWaypoints()` | 因为"**到点要做事**"：逐个走时"到达"这个时机天然明确；`FollowWaypoints` 只给 `current_waypoint` 反馈，判断到达要绕 |
| 路线可配置 | 路点写在 YAML 里 | 换巡检线路不改代码 |
| 到点记录 | 写 CSV | 事后能对账：几点到了哪个点、有没有失败 |
| 到点拍照 | 订阅相机话题，存 PNG | **放在单独节点 + 单独线程**，避免和 `BasicNavigator` 内部的 spin 抢执行器 |
| 到点播报 | `espeak-ng -v cmn` | 有普通话语音；用 `Popen` 不阻塞导航 |
| 可取消 | `Ctrl+C` → `nav.cancelTask()` | 车要真的停下来 |

> 💡 用官方的 `nav2_simple_commander`（`BasicNavigator`），它把 NavigateToPose 的
> 发送目标、等结果、取消都封装好了。

### 9.2 巡检路线

文件：`src/fishbot_navigation2/param/patrol_waypoints.yaml`

```yaml
# 巡检路线（航点由地图自动挑选：每个点周围 0.7m 内全是空闲，保证可通行）
# 换路线只改这个文件，不用改代码
patrol:
  frame_id: map
  loop: true
  pause_at_waypoint: 3.0
  voice: true
  photo: true
  # 相机话题不在这里配：它由 launch 参数说了算，保证桥接和巡检脚本用的是同一个名字
  #   ros2 launch fishbot_navigation2 patrol_sim.launch.py camera_topic:=/camera/image_raw
  waypoints:
    # ★ 1 号点位故意离出生点 (0,0) 有 1.5m：太近的话 Nav2 会觉得"原地没进展"，
    #   反复报 Failed to make progress，在目标边上磨几十秒才承认到达
    - {name: "1号点位-大厅中部", x: 1.5, y: 0.1, yaw: 0.0}
    - {name: "2号点位-左上房间", x: -3.3, y: 1.8, yaw: 0.0}
    - {name: "3号点位-左下房间", x: -4.0, y: -2.1, yaw: 0.0}
    - {name: "4号点位-右下房间", x: 3.2, y: -2.1, yaw: 0.0}
```


> ⚠️ **三个坑都藏在这份小 yaml 里**：
>
> 1. **坐标必须是地图里真实可通行的点**。本户型 12m×6m（x∈[-6,6]，y∈[-3,3]）。
>    填之前先在 RViz 里对着地图量（RViz 底部状态栏会显示鼠标处的 map 坐标），不要凭感觉抄。
> 2. **千万别填出生点 (0,0) 或离它太近的点**。实测把 1 号点位放在离出生点 0.3m 处时，
>    Nav2 判定"原地没进展"，反复报 `Failed to make progress`，在目标旁边磨了 **57 秒**才承认到达。
>    本项目的 1 号点位故意离出生点 1.5m。
> 3. **`camera_topic` 不在这里配**，它由 launch 参数决定——
>    这样桥接和巡检脚本必然用同一个名字，不会一个叫 `/camera/image_raw` 另一个叫 `/camera/image`。

### 9.3 巡检节点

文件：`src/fishbot_navigation2/scripts/patrol_inspector.py`

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""巡检（巡逻）小车：按航点自动巡航，到点拍照 + 语音播报 + 记录 CSV。

它做什么
--------
1. 等 Nav2 起来（bt_navigator / navigate_to_pose 就绪、AMCL 出了定位）；
2. 从 patrol_waypoints.yaml 读航点，一个点一个点地导航过去；
3. 每个点到了以后：停 pause_at_waypoint 秒 → 用相机拍一张 PNG → 用 espeak-ng 播报点位名；
4. 全程写一份 CSV 日志（谁、什么时候、到没到、花了多久、照片在哪）；
5. 走完一圈看 yaml 里的 loop：true 就再走一圈，false 就收工；
6. Ctrl+C 时取消当前导航目标 + 往 /cmd_vel 灌几帧零速度，保证小车停下来。

一般不用手动跑它，patrol_sim.launch.py 会一键拉起来：
    ros2 launch fishbot_navigation2 patrol_sim.launch.py

单独跑（Nav2 已经开着的时候）：
    ros2 run fishbot_navigation2 patrol_inspector
    ros2 run fishbot_navigation2 patrol_inspector --ros-args -p loop:=false
"""

#  一、几个纯函数（不碰 ROS，方便单独测试）

def yaw_to_quaternion(yaw):
    """偏航角(弧度) → 四元数的 (z, w)。因为 roll=pitch=0，只用这两个分量。"""
    return math.sin(yaw / 2.0), math.cos(yaw / 2.0)


def make_pose(frame_id, x, y, yaw, stamp):
    """拼一个 PoseStamped：Nav2 的目标点就是这种消息。"""
    pose = PoseStamped()
    pose.header.frame_id = frame_id          # 必须在 map 系里，Nav2 才知道你说的是哪儿
    pose.header.stamp = stamp
    pose.pose.position.x = float(x)
    pose.pose.position.y = float(y)
    pose.pose.position.z = 0.0
    qz, qw = yaw_to_quaternion(float(yaw))
    pose.pose.orientation.z = qz
    pose.pose.orientation.w = qw
    return pose


def sanitize(name):
    """点位名 → 能当文件名用的字符串（中文保留，空格和斜杠换掉）。"""
    out = []
    for ch in str(name):
        out.append('_' if ch in ' /\\:*?"<>|' else ch)
    return ''.join(out).strip('_') or 'waypoint'


def image_msg_to_array(msg):
    """sensor_msgs/Image → numpy 数组。

    这里刻意不用 cv_bridge：它要额外装包，而且我们只要存图，
    用 numpy + PIL 两步就够了（PIL 和 numpy 都是系统自带的）。

    坑：msg.step 是"每行占多少字节"，可能比 宽×通道数 大（行对齐填充），
    所以先按 step 切成一行一行，再把多余的填充列去掉，最后才 reshape。
    """
    if msg.encoding in ('32FC1', '32FC1_depth', 'mono32f'):
        # 深度图：float32，单位米。先按 float32 切行。
        buf = np.frombuffer(msg.data, dtype=np.float32)
        rows = buf.reshape(msg.height, msg.step // 4)
        return rows[:, :msg.width]

    channels = {'mono8': 1, '8UC1': 1,
                'rgb8': 3, 'bgr8': 3, '8UC3': 3,
                'rgba8': 4, 'bgra8': 4, '8UC4': 4}.get(msg.encoding)
    if channels is None:
        raise ValueError('不认识的图像编码：%s' % msg.encoding)

    buf = np.frombuffer(msg.data, dtype=np.uint8)
    rows = buf.reshape(msg.height, msg.step)
    rows = rows[:, :msg.width * channels]
    if channels == 1:
        return rows.reshape(msg.height, msg.width)
    return rows.reshape(msg.height, msg.width, channels)


def save_image_msg(msg, path):
    """把一帧 Image 存成 PNG 文件，返回 path。"""
    from PIL import Image as PILImage   # 放函数里 import：没装 PIL 也不影响巡逻本身

    arr = image_msg_to_array(msg)

    if arr.dtype != np.uint8:
        # 深度图之类的浮点数据：归一化到 0~255 纯为了"看得见"，不是原始深度值
        a = np.nan_to_num(arr, nan=0.0, posinf=0.0, neginf=0.0)
        hi = float(a.max())
        if hi > 0.0:
            a = a / hi * 255.0
        arr = a.astype(np.uint8)
    elif msg.encoding == 'bgr8':
        arr = arr[:, :, ::-1]                      # OpenCV 的 BGR 要翻成 RGB
    elif msg.encoding == 'bgra8':
        arr = arr[:, :, [2, 1, 0, 3]]

    PILImage.fromarray(arr).save(path)
    return path

class PatrolInspector(BasicNavigator):
    """继承 BasicNavigator：它已经帮我们建好了 NavigateToPose 的 action client，
    还有 goToPose() / isTaskComplete() / cancelTask() 这些现成方法。"""

    def __init__(self):
        super().__init__(node_name='patrol_inspector')

        # ---------------- 参数（launch 里会传，命令行也能覆盖） ----------------
        default_wp = os.path.join(get_package_share_directory('fishbot_navigation2'),
                                  'param', 'patrol_waypoints.yaml')
        self.declare_parameter('waypoints_file', default_wp)
        self.declare_parameter('log_dir', os.path.expanduser('~/patrol_log'))
        self.declare_parameter('camera_topic', '/camera/image_raw')
        self.declare_parameter('voice_name', 'cmn')       # espeak-ng 的中文嗓音
        self.declare_parameter('goal_timeout', 120.0)     # 单个点位最多走多久(秒)
        self.declare_parameter('photo_timeout', 5.0)      # 等一帧新图像最多等多久(秒)
        self.declare_parameter('nav2_timeout', 180.0)     # 等 Nav2 起来最多等多久(秒)
        self.declare_parameter('arrive_tolerance', 0.6)   # 已经在目标这么近，就别再让 Nav2 挪了
        self.declare_parameter('loop', '')                # 留空=用 yaml 里的 loop；true/false 强制覆盖

        # ---------------- 读航点配置 ----------------
        wp_file = str(self.get_parameter('waypoints_file').value)
        if not os.path.isfile(wp_file):
            raise RuntimeError('找不到航点文件：%s' % wp_file)
        with open(wp_file, 'r', encoding='utf-8') as f:
            cfg = yaml.safe_load(f) or {}
        patrol = cfg.get('patrol', cfg)          # 兼容"有没有外面那层 patrol:"两种写法

        self.route = patrol.get('waypoints') or []
        if not self.route:
            raise RuntimeError('航点文件里一个 waypoints 都没有：%s' % wp_file)
        self.frame_id = patrol.get('frame_id', 'map')
        self.loop = bool(patrol.get('loop', True))
        self.pause = float(patrol.get('pause_at_waypoint', 3.0))
        self.voice = bool(patrol.get('voice', True))
        self.photo = bool(patrol.get('photo', True))
        self.camera_topic = str(self.get_parameter('camera_topic').value)

        # 命令行强制覆盖 loop（留空则听 yaml 的）
        override = str(self.get_parameter('loop').value).strip().lower()
        if override in ('true', '1', 'yes', 'y'):
            self.loop = True
        elif override in ('false', '0', 'no', 'n'):
            self.loop = False

        self.goal_timeout = float(self.get_parameter('goal_timeout').value)
        self.photo_timeout = float(self.get_parameter('photo_timeout').value)
        self.voice_name = str(self.get_parameter('voice_name').value)
        self.arrive_tolerance = float(self.get_parameter('arrive_tolerance').value)

        # ---------------- 日志目录 / CSV ----------------
        self.log_dir = os.path.expanduser(str(self.get_parameter('log_dir').value))
        self.photo_dir = os.path.join(self.log_dir, 'photos')
        os.makedirs(self.photo_dir, exist_ok=True)
        stamp = datetime.now().strftime('%Y%m%d_%H%M%S')
        self.csv_path = os.path.join(self.log_dir, 'patrol_%s.csv' % stamp)
        # utf-8-sig：带 BOM，双击用 Excel 打开中文不乱码
        self.csv_file = open(self.csv_path, 'w', newline='', encoding='utf-8-sig')
        self.csv = csv.writer(self.csv_file)
        self.csv.writerow(['序号', '时间', '点位名', '目标x', '目标y', '目标yaw',
                           '结果', '耗时(秒)', '照片文件'])
        self.csv_file.flush()

        # ---------------- 相机：只留最新一帧 ----------------
        self._img = None
        self._img_seq = 0
        self._img_warned = False
        self._voice_warned = False
        # 传感器数据用 BEST_EFFORT + depth=1：只关心最新帧，丢帧无所谓
        self.create_subscription(
            Image, self.camera_topic, self._on_image,
            QoSProfile(depth=1, history=QoSHistoryPolicy.KEEP_LAST,
                       reliability=QoSReliabilityPolicy.BEST_EFFORT))

        # ---------------- 当前位置（AMCL 给的）：判断"是不是已经在点位旁边了" ----------------
        self._pose = None
        self.create_subscription(
            PoseWithCovarianceStamped, 'amcl_pose', self._on_amcl_pose,
            QoSProfile(depth=1, durability=QoSDurabilityPolicy.TRANSIENT_LOCAL,
                       reliability=QoSReliabilityPolicy.RELIABLE))

        # ---------------- 安全停车用 ----------------
        self._cmd_pub = self.create_publisher(Twist, '/cmd_vel', 10)

    # ------------------------------------------------------------------
    #  相机 / 语音 小工具
    # ------------------------------------------------------------------
    def _on_amcl_pose(self, msg):
        self._pose = (msg.pose.pose.position.x, msg.pose.pose.position.y)

    def _on_image(self, msg):
        self._img = msg
        self._img_seq += 1

    def speak(self, text):
        """调 espeak-ng 说话。用 Popen 不等待，所以不会卡住导航。"""
        if not self.voice:
            return
        try:
            subprocess.Popen(['espeak-ng', '-v', self.voice_name, '-s', '160', text],
                             stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
        except FileNotFoundError:
            if not self._voice_warned:
                self._voice_warned = True
                self.get_logger().warn('没装 espeak-ng，语音播报关掉（sudo apt install espeak-ng）')

    def take_photo(self, index, name):
        """等到一帧"新"图像并存盘，返回文件路径；拿不到就返回空字符串。"""
        seq_before = self._img_seq
        deadline = time.time() + self.photo_timeout
        while time.time() < deadline:
            rclpy.spin_once(self, timeout_sec=0.1)     # 收图靠 spin
            if self._img_seq > seq_before and self._img is not None:
                break

        if self._img is None:
            if not self._img_warned:
                self._img_warned = True
                self.get_logger().warn(
                    '拿不到相机图像（订阅的是 %s）。三步排查：\n'
                    '  ① gz topic -l | grep camera   → 看 Gazebo 到底发不发\n'
                    '  ② ros2 topic hz %s            → 看桥接通没通\n'
                    '  ③ 桥接写在 patrol_sim.launch.py 的 camera_bridge 那段'
                    % (self.camera_topic, self.camera_topic))
            return ''

        fname = '%02d_%s_%s.png' % (index, sanitize(name),
                                    datetime.now().strftime('%H%M%S'))
        path = os.path.join(self.photo_dir, fname)
        try:
            save_image_msg(self._img, path)
            return path
        except Exception as exc:                       # 存图失败不该让巡逻中断
            self.get_logger().error('存图失败：%s: %s' % (type(exc).__name__, exc))
            return ''

    def stop_robot(self):
        """连发几帧零速度，确保底盘真的停住。"""
        zero = Twist()
        for _ in range(10):
            self._cmd_pub.publish(zero)
            time.sleep(0.05)

    def rest(self, seconds):
        """停留 N 秒，但期间继续 spin（不然 /amcl_pose、TF 会断掉）。"""
        end = time.time() + float(seconds)
        while time.time() < end:
            rclpy.spin_once(self, timeout_sec=0.1)

    # ------------------------------------------------------------------
    #  等 Nav2 / 走一个点位
    # ------------------------------------------------------------------
    def wait_for_nav2(self):
        """分两步等：先等 NavigateToPose 动作服务器，再等 AMCL 出定位。

        为什么不用官方的 waitUntilNav2Active()？
        它内部是 while 死循环等生命周期节点变 active，一旦某个节点没起来，
        它会**静默卡死**（日志只在 debug 级别）。这里改成带超时的等待，
        卡住了会明确报错，让你知道该去看谁的日志。
        """
        timeout = float(self.get_parameter('nav2_timeout').value)
        self.get_logger().info('等 Nav2 起来（最多 %.0f 秒）…' % timeout)

        t0 = time.time()
        while time.time() - t0 < timeout:
            if self.nav_to_pose_client.server_is_ready():
                break
            rclpy.spin_once(self, timeout_sec=0.2)
        else:
            raise RuntimeError(
                '等了 %.0fs 还没等到 navigate_to_pose 动作服务器，Nav2 没起来。' % timeout)
        self.get_logger().info('navigate_to_pose 已就绪（等了 %.1fs）' % (time.time() - t0))

        # ★ 光看"动作服务器在"是不够的！
        #   bt_navigator 在 configure 之后就会建好 action server，但它可能一直停在
        #   inactive —— 例如 map_server 加载地图失败会让整个导航组 bringup 中止。
        #   这时送目标会被直接拒绝：
        #       [bt_navigator]: Action server is inactive. Rejecting the goal.
        #   而 BasicNavigator 只会记一条 error 就返回，结果变成 UNKNOWN，
        #   脚本就会一圈一圈空转（实测空转了 672 圈）。
        #   所以这里再等它真正变成 active，等不到就带着排查线索报错退出。
        state_cli = self.create_client(GetState, 'bt_navigator/get_state')
        t0 = time.time()
        state = '未知'
        while time.time() - t0 < timeout:
            if state_cli.wait_for_service(timeout_sec=1.0):
                fut = state_cli.call_async(GetState.Request())
                rclpy.spin_until_future_complete(self, fut, timeout_sec=2.0)
                if fut.result() is not None:
                    state = fut.result().current_state.label
                    if state == 'active':
                        break
            rclpy.spin_once(self, timeout_sec=0.2)

        if state != 'active':
            raise RuntimeError(
                'bt_navigator 一直不是 active（当前状态：%s，等了 %.0fs）。\n'
                '    最常见原因：map_server 没能加载地图，导致整个导航组 bringup 中止，'
                '于是没有 map→odom 的 TF，planner_server 激活超时。排查三步：\n'
                '      ① ros2 lifecycle get /map_server\n'
                '      ② ls -l install/fishbot_navigation2/share/fishbot_navigation2/maps/\n'
                '         —— install(DIRECTORY) 是编译时"快照"文件列表的：新生成的地图\n'
                '            （map_saver_cli 或 make_map_from_world 产出的 room.pgm）\n'
                '            不重新 colcon build 就不会被装进 install/，\n'
                '            map_server 会报 Failed to load image file ... room.pgm\n'
                '      ③ 看终端里 map_server 的报错' % (state, timeout))
        self.get_logger().info('bt_navigator 已 active，导航栈可用')

        t0 = time.time()
        while time.time() - t0 < 60.0 and self._pose is None:
            rclpy.spin_once(self, timeout_sec=0.2)
        if self._pose is not None:
            self.get_logger().info('AMCL 已发布 /amcl_pose，定位就绪（当前 %.2f, %.2f）'
                                   % self._pose)
        else:
            self.get_logger().warn('一直没收到 /amcl_pose：检查 AMCL 是否 active、'
                                   'nav2_params.yaml 里 amcl.set_initial_pose 是否为 true')

        # 第一次规划前把代价地图清一下，避免开机残留的障碍把起点围死
        try:
            self.clearAllCostmaps()
        except Exception as exc:
            self.get_logger().warn('清代价地图失败（不影响继续）：%s' % exc)

    def visit_waypoint(self, index, wp):
        name = str(wp.get('name', '点位%d' % index))
        x, y = float(wp['x']), float(wp['y'])
        yaw = float(wp.get('yaw', 0.0))

        self.get_logger().info('─' * 56)
        self.get_logger().info('[%d/%d] 出发 → %s  (x=%.2f, y=%.2f, yaw=%.2f)'
                               % (index, len(self.route), name, x, y, yaw))

        # 已经在点位旁边了就别再让 Nav2 挪：距离小于 arrive_tolerance 时，
        # 送目标反而会触发 "Failed to make progress"（原地磨几十秒）。
        # 开机时 1 号点位离出生点很近的话，这一段能省掉一大截无谓等待。
        if self._pose is not None:
            dx, dy = self._pose[0] - x, self._pose[1] - y
            near = math.hypot(dx, dy)
            if near <= self.arrive_tolerance:
                self.get_logger().info('    已经在 %.2fm 以内（容差 %.2fm），直接巡检，不再导航'
                                       % (near, self.arrive_tolerance))
                self.speak('已在%s' % name)
                photo = self.take_photo(index, name) if self.photo else ''
                if photo:
                    self.get_logger().info('    照片已存：%s' % photo)
                self.rest(self.pause)
                self.write_csv(index, name, x, y, yaw, 'ALREADY_HERE', 0.0, photo)
                return TaskResult.SUCCEEDED

        self.speak('前往%s' % name)

        goal = make_pose(self.frame_id, x, y, yaw, self.get_clock().now().to_msg())
        t0 = time.time()
        self.goToPose(goal)

        timed_out = False
        last_log = 0.0
        while not self.isTaskComplete():
            fb = self.getFeedback()
            now = time.time()
            if fb is not None and now - last_log > 3.0:
                last_log = now
                dist = getattr(fb, 'distance_remaining', float('nan'))
                self.get_logger().info('    导航中… 还剩 %.2f m' % dist)
            if now - t0 > self.goal_timeout:
                self.get_logger().warn('    超过 %.0fs 还没到，放弃这个点位'
                                       % self.goal_timeout)
                self.cancelTask()
                timed_out = True
                break
            time.sleep(0.05)          # isTaskComplete() 内部已经在 spin 了

        result = TaskResult.CANCELED if timed_out else self.getResult()
        cost = time.time() - t0
        photo = ''

        if result == TaskResult.SUCCEEDED:
            self.get_logger().info('    到达 %s（用时 %.1fs）' % (name, cost))
            self.speak('已到达%s' % name)
            if self.photo:
                photo = self.take_photo(index, name)
                if photo:
                    self.get_logger().info('    照片已存：%s' % photo)
            self.rest(self.pause)
        else:
            self.get_logger().warn('    %s 没走到（%s），跳下一个' % (name, result.name))
            self.speak('%s未能到达' % name)

        self.write_csv(index, name, x, y, yaw, result.name, cost, photo)
        return result

    def write_csv(self, index, name, x, y, yaw, result, cost, photo):
        self.csv.writerow([index, datetime.now().strftime('%Y-%m-%d %H:%M:%S'),
                           name, '%.3f' % x, '%.3f' % y, '%.3f' % yaw,
                           result, '%.1f' % cost, photo])
        self.csv_file.flush()          # 立刻落盘：就算 Ctrl+C 也不会丢记录

    # ------------------------------------------------------------------
    #  主流程
    # ------------------------------------------------------------------
    def run(self):
        self.get_logger().info('巡检路线（来自 %s）：'
                               % self.get_parameter('waypoints_file').value)
        for i, wp in enumerate(self.route, start=1):
            self.get_logger().info('    %d. %s  (%.2f, %.2f)'
                                   % (i, wp.get('name', ''), wp['x'], wp['y']))
        self.get_logger().info('循环=%s，每点停留 %.1fs，拍照=%s，语音=%s，相机=%s'
                               % (self.loop, self.pause, self.photo, self.voice,
                                  self.camera_topic))
        self.get_logger().info('CSV 日志：%s' % self.csv_path)

        self.wait_for_nav2()

        lap = 0
        while rclpy.ok():
            lap += 1
            self.get_logger().info('=' * 56)
            self.get_logger().info('第 %d 圈开始' % lap)
            rejected = 0
            for i, wp in enumerate(self.route, start=1):
                result = self.visit_waypoint(i, wp)
                # ★ 保险丝：目标被连续拒绝说明导航栈根本没在工作，
                #   这时候绝不能一圈一圈空转（实测会刷 600+ 圈日志）
                rejected = rejected + 1 if result == TaskResult.UNKNOWN else 0
                if rejected >= 3:
                    raise RuntimeError(
                        '连续 3 个点位都被 Nav2 拒绝（结果 UNKNOWN），导航栈没在正常工作。\n'
                        '    先别空转，查这个：ros2 lifecycle get /bt_navigator')
            self.get_logger().info('第 %d 圈结束' % lap)
            if not self.loop:
                self.get_logger().info('loop=false，一圈走完收工')
                break
        self.get_logger().info('巡检结束')

    def shutdown(self):
        """收尾：取消目标 → 停车 → 关 CSV → 销毁节点。"""
        try:
            self.cancelTask()
        except Exception:
            pass
        self.stop_robot()
        try:
            self.csv_file.close()
        except Exception:
            pass
        print('CSV 日志已保存：%s' % self.csv_path)
        try:
            self.destroyNode()
        except Exception:
            pass


def main(args=None):
    rclpy.init(args=args)
    node = None
    try:
        node = PatrolInspector()
        node.run()
    except KeyboardInterrupt:
        print('\n收到 Ctrl+C，取消导航目标并停车…')
    except Exception as exc:
        print('巡检节点出错：%s: %s' % (type(exc).__name__, exc), file=sys.stderr)
    finally:
        if node is not None:
            node.shutdown()
        rclpy.try_shutdown()


if __name__ == '__main__':
    main()

> 💡 这份脚本值得重点看四处：
>
> | 位置 | 为什么这么写 |
> |---|---|
> | `wait_for_nav2()` | **故意不用**官方 `waitUntilNav2Active()`：它内部是死循环等生命周期节点变 active，卡住时只在 debug 级别出声，等于静默卡死。这里换成带超时的等待，超时直接报错告诉你去看谁的日志 |
> | `visit_waypoint()` 开头 | "已经在目标 0.6m 内就直接巡检、不再导航"，专治上面说的 `Failed to make progress` |
> | `_on_image()` / `take_photo()` | 只留最新一帧、`BEST_EFFORT` QoS；存图用 numpy+PIL，**不需要 `cv_bridge`** |
> | `shutdown()` | Ctrl+C 时先 `cancelTask()` 再往 `/cmd_vel` 灌几帧零速度，保证车真的停下来 |

### 9.5 本章收尾②：补相机桥接（要拍照，必须先有图像话题）

第 5 章的桥接里**没有相机**，这一步补上。但先记住一个**实测结论**，否则一定踩坑：

> ⚠️ **Gazebo Harmonic 的 `depth_camera` 传感器，`<topic>` 上发的是深度图，不是彩色图。**
>
> 实测（传感器写 `<topic>camera</topic>`）ROS 侧拿到的是：
>
> | gz 话题 | 内容 | ROS 侧编码 |
> |---|---|---|
> | `/camera` | **深度图** | `32FC1` |
> | `/camera_info` | 内参（注意**不是** `/camera/camera_info`） | — |
> | `/camera/points` | 点云 | — |
>
> 网上教程常见的 `/camera/image`、`/camera/depth_image` 在这套版本里**都不存在**。
> 所以"巡检拍照"想要能看的彩色照片，必须**再挂一个普通 `camera` 传感器**——
> 5.2 的 `gazebo_sensor_plugin.xacro` 里已经有了，话题叫 `camera_rgb`，挂在同一个 `camera_link` 上。

先自己确认一遍真实话题名（养成习惯，别照抄教程）：

```bash
gz topic -l | grep -i camera
# 本项目期望看到：/camera  /camera_info  /camera/points  /camera_rgb
```


**单独测试时**，直接在终端起一个桥接（第 10 章的一键 launch 里会包含同样的三条规则）：

```bash
ros2 run ros_gz_bridge parameter_bridge \
  '/camera_rgb@sensor_msgs/msg/Image[gz.msgs.Image' \
  '/camera@sensor_msgs/msg/Image[gz.msgs.Image' \
  '/camera_info@sensor_msgs/msg/CameraInfo[gz.msgs.CameraInfo' \
  --ros-args \
  -r /camera_rgb:=/camera/image_raw \
  -r /camera:=/camera/depth \
  -r /camera_info:=/camera/camera_info
```


> 💡 `ros_gz_bridge` 参数语法是 `<话题名>@<ROS类型>[<GZ类型`，
> **方括号的方向就是数据流向**（`[` = gz→ROS，`]` = ROS→gz，`@` = 双向）。
> 另外**一条规则里 ROS 名和 GZ 名是同一个字符串**——想让 ROS 侧叫别的名字，只能用 remapping 改。

**验收**：

```bash

ros2 topic echo /camera/image_raw --field encoding --once     # 期望 rgb8
ros2 run rqt_image_view rqt_image_view /camera/image_raw      # 能看到车前方的彩色画面
```


> 💡 巡检脚本两种编码都支持：`rgb8` 存彩色照片；`32FC1` 会归一化成灰度"深度快照"存下来，不会崩。
> 所以就算你只桥了深度话题也能出图，只是照片是深度图而已。

### 10.2 一键启动脚本

文件：`src/fishbot_navigation2/launch/patrol_sim.launch.py`

```python
"""一键启动"巡检小车"：Gazebo（导航模式）+ Nav2 + 航点巡检任务。

    ros2 launch fishbot_navigation2 patrol_sim.launch.py

它其实就把三件事按顺序拼起来：
    ① gazebo_sim.launch.py   且 slam:=false  auto_explore:=false → 起仿真，用现成地图不建图
    ② navigation2.launch.py  → 起 Nav2（AMCL 定位 + 规划 + 控制），读 maps/room.yaml
    ③ patrol_inspector       → 我们自己的巡检脚本，按 param/patrol_waypoints.yaml 跑点位

顺手还多干了两件事：
    · 单独起一个 ros_gz_bridge，把 Gazebo 的相机桥到 ROS（拍照要用）
    · 巡检脚本延后 10 秒启动，等 Nav2 的生命周期节点变 active，日志干净一些

只想起仿真不巡检：
    ros2 launch fishbot_navigation2 patrol_sim.launch.py patrol:=false
想换地图 / 参数 / 航点，改对应的 launch 参数（见下面 DeclareLaunchArgument）。
"""
import os

from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import (DeclareLaunchArgument, IncludeLaunchDescription,
                            TimerAction)
from launch.conditions import IfCondition
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node


def generate_launch_description():
    desc_pkg = get_package_share_directory('fishbot_description')
    nav_pkg = get_package_share_directory('fishbot_navigation2')

    map_file = LaunchConfiguration('map')
    params_file = LaunchConfiguration('params_file')
    waypoints_file = LaunchConfiguration('waypoints_file')
    use_sim_time = LaunchConfiguration('use_sim_time')
    camera_topic = LaunchConfiguration('camera_topic')
    camera_info_topic = LaunchConfiguration('camera_info_topic')
    depth_topic = LaunchConfiguration('depth_topic')
    patrol = LaunchConfiguration('patrol')

    # ① 仿真：导航模式 = 不建图、不自动探索
    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(desc_pkg, 'launch', 'gazebo_sim.launch.py')),
        launch_arguments={
            'slam': 'false',          # ★ 用现成地图 + AMCL，不起 slam_toolbox
            'auto_explore': 'false',  # ★ 不跑 frontier 探索，改由 Nav2 按航点走
        }.items())

    # ② Nav2：AMCL 定位 + 全局/局部代价地图 + 规划控制
    nav2 = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(nav_pkg, 'launch', 'navigation2.launch.py')),
        launch_arguments={
            'map': map_file,
            'params_file': params_file,
            'use_sim_time': use_sim_time,
        }.items())

    # ③ 相机桥接。Gazebo 这边实际有这么几个话题（都是实测确认的，别照抄教程）：
    #      /camera_rgb    gz.msgs.Image            彩色图 ← 普通 camera 传感器，拍照用
    #      /camera        gz.msgs.Image            深度图（ROS 侧 32FC1！）
    #      /camera_info   gz.msgs.CameraInfo       深度相机内参
    #      /camera/points gz.msgs.PointCloudPacked 点云（本脚本用不到）
    #    踩过的坑：depth_camera 传感器的 <topic> 上发的是深度图，不是彩色图，
    #    而且 camera_info 叫 /camera_info（不是 /camera/camera_info）。
    #    注意 ros_gz_bridge 一条规则里 ROS 名和 GZ 名是同一个字符串，
    #    想让 ROS 侧叫别的名字只能用 remappings 改（下面就是这么做的）。
    camera_bridge = Node(
        package='ros_gz_bridge',
        executable='parameter_bridge',
        name='camera_bridge',
        arguments=[
            '/camera_rgb@sensor_msgs/msg/Image[gz.msgs.Image',
            '/camera@sensor_msgs/msg/Image[gz.msgs.Image',
            '/camera_info@sensor_msgs/msg/CameraInfo[gz.msgs.CameraInfo',
        ],
        remappings=[
            ('/camera_rgb', camera_topic),        # 彩色 → /camera/image_raw
            ('/camera', depth_topic),             # 深度 → /camera/depth
            ('/camera_info', camera_info_topic),
        ],
        parameters=[{'use_sim_time': use_sim_time}],
        output='screen')

    # ④ 巡检脚本：延后 10 秒，等 Nav2 起来
    inspector = Node(
        package='fishbot_navigation2',
        executable='patrol_inspector',
        name='patrol_inspector',
        parameters=[{
            'use_sim_time': use_sim_time,
            'waypoints_file': waypoints_file,
            'camera_topic': camera_topic,
        }],
        condition=IfCondition(patrol),
        output='screen')

    return LaunchDescription([
        DeclareLaunchArgument(
            'map',
            default_value=os.path.join(nav_pkg, 'maps', 'room.yaml'),
            description='地图 yaml（默认用世界文件渲染的真值地图）'),
        DeclareLaunchArgument(
            'params_file',
            default_value=os.path.join(nav_pkg, 'param', 'nav2_params.yaml'),
            description='Nav2 参数文件（已按 base_footprint / fishbot/odom 改好）'),
        DeclareLaunchArgument(
            'waypoints_file',
            default_value=os.path.join(nav_pkg, 'param', 'patrol_waypoints.yaml'),
            description='巡检航点文件（换路线只改这个 yaml）'),
        DeclareLaunchArgument(
            'camera_topic', default_value='/camera/image_raw',
            description='彩色相机在 ROS 侧的名字（巡检拍照订阅的就是它）'),
        DeclareLaunchArgument(
            'depth_topic', default_value='/camera/depth',
            description='深度相机在 ROS 侧的名字（32FC1，加分项用）'),
        DeclareLaunchArgument(
            'camera_info_topic', default_value='/camera/camera_info',
            description='深度相机内参在 ROS 侧的名字'),
        DeclareLaunchArgument(
            'use_sim_time', default_value='true', description='用仿真时钟'),
        DeclareLaunchArgument(
            'patrol', default_value='true',
            description='false = 只起仿真和 Nav2，不跑巡检任务'),

        gazebo,
        nav2,
        camera_bridge,
        TimerAction(period=10.0, actions=[inspector]),
    ])
```


> 💡 它把 ①仿真（导航模式）②Nav2 ③相机桥接 ④巡检节点 串起来，
> 其中巡检节点用 `TimerAction(period=10.0, ...)` 延后 10 秒启动，等 Nav2 的生命周期节点 active，日志更干净。

**本章 CMakeLists.txt 不用改** —— `launch/` 在第 8 章已经在 `install(DIRECTORY ...)` 列表里了。

### 10.4 两个便利脚本（可选，但强烈建议）

这两个脚本不参与编译，放在工作空间根目录 `$WS/` 下即可。

**① `启动仿真.sh`**：在 **snap 版 VS Code 的集成终端**里，snap 会注入
`GTK_EXE_PREFIX`、`GTK_PATH`、`GIO_MODULE_DIR` 等变量，导致 `rviz2`、`gz sim gui` 一启动就崩：

```

  undefined symbol: __libc_pthread_init, version GLIBC_PRIVATE
```


脚本检测到 snap 环境后先清掉这些变量，再 source 环境、检查有没有残留的 Gazebo，最后才 launch。

```bash
# 用法：./启动仿真.sh <包名> <launch 文件> [参数:=值 ...]
./启动仿真.sh fishbot_navigation2 patrol_sim.launch.py
```


文件：`启动仿真.sh`

```bash
#!/usr/bin/env bash
# 在 VS Code(snap) 终端里也能正常启动 ROS 仿真/GUI 的包装脚本。
# 用法： ./启动仿真.sh fishbot_description gazebo_sim.launch.py slam:=false
#       ./启动仿真.sh fishbot_navigation2 navigation2.launch.py
#       ./启动仿真.sh fishbot_navigation2 patrol_sim.launch.py
set -e
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# ★ 关键：清掉 snap 版 VS Code 注入的 GTK/GIO 路径，否则 rviz2 / gz sim gui 会崩：
#   symbol lookup error: /snap/core20/.../libpthread.so.0: undefined symbol __libc_pthread_init
if [ -n "${GTK_EXE_PREFIX:-}" ] && [ "${GTK_EXE_PREFIX#/snap}" != "$GTK_EXE_PREFIX" ]; then
  echo "[启动仿真] 检测到 snap 终端环境，正在清理 GTK/GIO 变量…"
  unset GTK_EXE_PREFIX GTK_PATH GTK_IM_MODULE_FILE GIO_MODULE_DIR GSETTINGS_SCHEMA_DIR LOCPATH
  export XDG_DATA_DIRS=/usr/share/ubuntu:/usr/share/gnome:/usr/local/share/:/usr/share/:/var/lib/snapd/desktop
fi

# ── 可选：如果 Gazebo 报 "libEGL warning ... driver (null)" 且 /scan 没数据 ──
#  说明离屏渲染被 Mesa 接管了（Mesa 不认 NVIDIA dGPU），强制只用 NVIDIA 的 EGL：
#  export __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/10_nvidia.json
#  极端情况下可以退回软件渲染（慢，但一定有数据）：
#  export LIBGL_ALWAYS_SOFTWARE=1

source /opt/ros/jazzy/setup.bash
source "$HERE/install/setup.bash"

# 顺带提醒：上一次的仿真没关干净会导致"两套系统抢话题/地图重影"
if pgrep -f '[g]z sim server' >/dev/null; then
  echo "[启动仿真] ⚠️ 检测到已有 Gazebo 在跑！先执行 ./停全部.sh，否则会出现两套仿真、地图重影"
  exit 1
fi
exec ros2 launch "$@"
```


**② `停全部.sh`**：一键停掉仿真/导航/巡检的所有进程。两件事值得注意：

- `gz sim server` **会忽略 SIGTERM**（GPU/EGL 收尾时卡住），所以脚本先发 SIGTERM 让能退的优雅退出，再 `-9` 强杀；
- `ros2 launch` 收到 SIGTERM 时**偶尔会漏掉子进程**。实测 `opennav_docking` 就活了下来，
  白占 15% CPU 还继续订阅代价地图和 TF——**下次启动就是两套系统抢资源，表现为地图重影**。
  所以脚本除了点名 Nav2 全家桶，最后还按 ROS 安装目录 `/opt/ros/jazzy/(lib|bin)/` 兜底扫一遍，
  并**真的列出**还活着的 ROS 进程（而不是数几个名字就报"干净"）。

文件：`停全部.sh`

```bash
#!/usr/bin/env bash
# 一键停掉所有仿真 / 导航 / 遥控相关进程。
#
# ★ 为什么要分两步：gz sim server 会忽略 SIGTERM（渲染/EGL 收尾时卡住），
#   所以先发 SIGTERM 让能退的优雅退出，再对残留的用 SIGKILL(-9) 强杀。
# ★ 用 [x] 写法 + 以脚本文件运行，避免把执行这条命令的自己杀掉。
# ★ 为什么要把 Nav2 每个节点都点名：实测过——ros2 launch 收到 SIGTERM 时
#   会漏掉个别子进程。有一次 opennav_docking 活了下来，白占 15% CPU、
#   还继续订阅代价地图和 TF，下次启动就是两套系统抢资源。
#   所以宁可啰嗦，把 Nav2 全家桶都列上。
#
# 用法： ./停全部.sh

PATTERNS=(
  # —— 仿真、我们自己的节点 ——
  '[g]azebo_sim.launch.py' '[p]atrol_sim.launch.py' '[g]z sim'
  '[a]sync_slam_toolbox' '[p]arameter_bridge' '[a]uto_explore'
  '[r]obot_state_publisher' '[r]viz2' '[t]eleop_twist_keyboard'
  '[p]atrol_inspector' '[m]ap_server' '[a]mcl'

  # —— Nav2 全家桶（漏一个就变孤儿）——
  '[c]ontroller_server' '[p]lanner_server' '[b]t_navigator'
  '[w]aypoint_follower' '[b]ehavior_server' '[s]moother_server'
  '[v]elocity_smoother' '[c]ollision_monitor' '[r]oute_server'
  '[o]pennav_docking' '[l]ifecycle_manager'
  '[g]lobal_costmap' '[l]ocal_costmap' '[n]av2_container'

  # —— 兜底（真正管用的那一招）——
  # ROS 2 的可执行文件都在 /opt/ros/jazzy/lib/<包名>/ 或 /opt/ros/jazzy/bin/ 下面。
  # 直接按安装目录匹配，所有 ROS 进程一网打尽：不管它是被 launch 拉起的、
  # 被 ros2 run 起的，还是收 SIGTERM 时漏下来的孤儿。
  #   实测教训：只按 'launch_params_' / 'ros2 launch' 兜底是不够的，
  #   `ros2 run tf2_ros static_transform_publisher` 那种就漏了。
  # ⚠️ 副作用：同时开着的别的 ROS 项目也会被一起杀掉。
  #    不想这样就把下面这行注释掉，只留上面的点名清单。
  '/opt/ros/jazzy/(lib|bin)/'
)

echo "① SIGTERM（优雅退出，等 3 秒）…"
for pat in "${PATTERNS[@]}"; do pkill -f "$pat" 2>/dev/null || true; done
sleep 3

echo "② SIGKILL（强杀残留：gz sim server 必须走这一步）…"
for pat in "${PATTERNS[@]}"; do pkill -9 -f "$pat" 2>/dev/null || true; done
sleep 2

# ★ 残留检查不再靠"数名字"，而是直接列出所有还活着的 ROS 进程。
#   之前吃过亏：检查项里没有 opennav_docking，它明明是孤儿却检查不出来。
echo "--- 残留检查 ---"
LEFT="$(ps -eo pid,etime,pcpu,args | grep -E '/opt/ros/jazzy/(lib|bin)/' | grep -v grep)"
GZ="$(pgrep -f '[g]z sim' 2>/dev/null || true)"

if [ -z "$LEFT" ] && [ -z "$GZ" ]; then
  echo "  ✓ 干净：没有任何 ROS / Gazebo 进程残留"
else
  [ -n "$GZ" ] && echo "  ⚠️ 还有 gz sim 没退（它会在 GPU/EGL 收尾时卡住）"
  [ -n "$LEFT" ] && { echo "  ⚠️ 还有这些 ROS 进程没退："; echo "$LEFT"; }
  echo "  再跑一次本脚本；gz sim 始终杀不掉的话，注销一次会话（或重启）最干净。"
fi
```


> ⚠️ 兜底规则会杀掉**所有** `/opt/ros/jazzy/` 下的进程。如果你同时开着别的 ROS 项目，把那一条注释掉。

### 12.3 术语表

| 词 | 一句话解释 |
|---|---|
| **URDF / Xacro** | 描述机器人长什么样的格式；Xacro 是带变量/宏的 URDF 生成器 |
| **link / joint** | 刚体 / 刚体之间的连接（`fixed` 不能动、`continuous` 能连续转） |
| **visual / collision / inertial** | 看得见的样子 / 碰撞外形 / 质量与惯量 |
| **base_footprint** | 贴地的虚拟根坐标系（Nav2 要它） |
| **`fishbot/odom`** | Gazebo 差速插件发布的里程计坐标系（**写死的名字**） |
| **TF** | ROS 里"坐标系之间的变换关系"这套机制 |
| **bridge（桥接）** | 在 Gazebo 话题和 ROS 话题之间搬运数据；方向符 `[`=gz→ROS，`]`=ROS→gz |
| **SLAM / 建图** | 边走边画地图（本项目用 `slam_toolbox`） |
| **AMCL / 定位** | 已经有地图了，靠激光在地图里确定自己位置 |
| **costmap / 代价地图** | Nav2 用来避障的栅格地图（全局 + 局部各一张） |
| **Action** | ROS 2 的"长任务"通信模式：可以取消、可以给进度反馈 |
| **`use_sim_time`** | 用仿真时钟（Gazebo 的 `/clock`）而不是墙上时间；仿真里几乎都要开 |

## 附录 C：这份文档是怎么生成的

文档里所有**项目文件**的代码块都不是手抄的，而是由脚本从工作空间 `~/VoVL773/ROS2/patrol_ws`
里的**真实文件**读出来、原文插入的。好处有两个：

1. **抄不歪**：读者复刻的是"已经被验证能跑的那一份"；
2. **能重新生成**：改了源文件之后重跑一次脚本，文档自动同步。

生成材料放在 `~/dsh工作区/dsh-工作中间产物/tools/手册生成/`：

```
part1.md      # 头部 + 第 0~3 章
part2.md      # 第 4~7 章
part3.md      # 第 8~9 章
part4.md      # 第 10~12 章 + 附录
build.py      # 拼接脚本
```


重新生成：

```bash
python3 ~/dsh工作区/dsh-工作中间产物/tools/手册生成/build.py
```


> 占位符语法 `{% raw %}{{FILE:相对路径|语言}}{% endraw %}`，相对路径相对工作空间根目录。
