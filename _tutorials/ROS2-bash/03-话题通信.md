以海龟节点为例：`ros2 run turtlesim turtlesim_node`

指令清单：

- `ros2 node list` —— 列出所有正在运行的节点
- `ros2 node info /turtlesim` —— 显示 `/turtlesim` 这个节点的信息（它订阅了什么、发布了什么、提供了哪些服务）
- `ros2 topic --help` —— 话题对应的命令

示例 `ros2 topic echo /turtle1/pose` 打印海龟节点 **/turtlesim** 的位置。

输出依次是：x 轴坐标、y 轴坐标、朝向角 theta（与 x 轴的夹角，单位弧度）、线速度 linear_velocity、角速度 angular_velocity。

- `ros2 topic info /turtle1/cmd_vel` —— 显示这个话题的消息类型，以及发布者和订阅者的数量
- `ros2 interface show` —— 查看对应接口的详细定义
- `ros2 topic pub 话题名 接口名 对应参数`
    > 示例：`ros2 topic pub /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5, y: 0.0}, angular: {z: 0.0}}"`
    >
    > 发布一个对应控制海龟速度的接口的话题，让海龟节点以指定速度运动。


> 💡 **知识点：节点名 vs 话题名**
>
> 海龟模拟器里有两类名字，初学特别容易混：
>
> | 名字 | 是什么 |
> |---|---|
> | `/turtlesim` | **节点名**（整个模拟器程序） |
> | `/turtle1` | **海龟实体名**（可以 spawn 出 turtle2、turtle3……） |
> | `/turtle1/cmd_vel` | **话题名**，给 turtle1 下发速度指令 |
> | `/turtle1/pose` | **话题名**，turtle1 上报自己的位姿 |
>
> 所以 `ros2 node info /turtlesim` 用节点名，`ros2 topic echo /turtle1/pose` 用话题名。

> 💡 **知识点：`ros2 topic pub` 的默认行为**
>
> 不加 `--once` / `-1` 时，它会**按 1 Hz 持续发布**，所以海龟会一直动。想只发一次就加 `--once`。
> 参数用 YAML 写，**可以只写要改的字段**，没写到的字段取默认值（0）。所以 `"{linear: {x: 0.5}}"` 是合法的。

### 示例项目：小说发布与接收然后读取

发布节点如下：

```python
import rclpy
from rclpy.node import Node
import requests
from std_msgs.msg import String
from queue import Queue          # 线程安全的队列，用于在"下载线程"和"定时器回调"之间传数据
import threading

class NovelPubNode(Node):
    def __init__(self, node_name):
        super().__init__(node_name)                     # 必须调用父类构造，完成节点初始化
        self.get_logger().info(f"{node_name}节点，启动")

        # 队列：下载线程往里放，定时器回调从里取。Queue 内部有锁，多线程读写安全
        self.novels_queue = Queue()

        # 创建发布者：参数依次为 (消息类型, 话题名, QoS 队列深度)
        # 话题名 'novel' 是相对名字，ROS 2 会自动补上命名空间，最终通常是 /novel
        self.novel_publisher = self.create_publisher(String, 'novel', 10)

        # 创建定时器：每 5 秒调用一次 timer_callback
        self.create_timer(5, self.timer_callback)

    def timer_callback(self):
        # 只有队列里有内容才发布，避免把空行刷到话题上
        if self.novels_queue.qsize() > 0:
            line = self.novels_queue.get()               # 从队列取出一行（取走即删除）
            msg = String()                               # ROS 消息必须先实例化
            msg.data = line                              # String 消息只有一个字段 data
            self.novel_publisher.publish(msg)            # 发布出去
            self.get_logger().info(f"发布了：{msg.data}")

    def download(self, url):
        # 这个方法跑在子线程里，负责把整本小说切行塞进队列
        response = requests.get(url)
        response.encoding = 'gbk'                        # 中文小说站多为 GBK，不指定会乱码
        text = response.text
        self.get_logger().info(f'下载{url}, {len(text)} 字')
        for line in text.splitlines():                   # 按行切分
            self.novels_queue.put(line)                  # 逐行入队

def main():
    rclpy.init()
    node = NovelPubNode('novel_pub')

    # 建议换成你自己准备的一个本地 txt 文件或稳定的测试地址：
    # 第三方下载站的链接经常失效，而且抓取受版权保护的内容有法律风险。
    url = ('https://download.zxcs.zip/%E3%80%8A%E5%87%A1%E4%BA%BA%E4%BF%AE%E4%BB%99%E4%BC%A0%E3%80%8B'
           '%EF%BC%88%E6%A0%A1%E5%AF%B9%E7%89%88%E5%85%A8%E6%9C%AC+%E7%95%AA%E5%A4%96%EF%BC%89'
           '%E4%BD%9C%E8%80%85%EF%BC%9A%E5%BF%98%E8%AF%AD.txt')

    # 放到子线程下载，daemon=True 让它随主程序退出而结束
    # 下载可能要几十秒，如果放在主线程会把后面的 rclpy.spin 堵住
    download_thread = threading.Thread(target=node.download, args=(url,), daemon=True)
    download_thread.start()

    rclpy.spin(node)        # 主线程在这里跑事件循环，定时器才能被触发
    rclpy.shutdown()

if __name__ == "__main__":
    main()
```


> 💡 **知识点：为什么必须用 `Queue` 而不是普通 `list`**
>
> 下载在**子线程**，发布在**主线程的定时器回调**里，两者共享数据。普通 `list` 的 `append` / `pop(0)` 不是原子操作，并发读写可能丢数据或读到"半成品"。`queue.Queue` 内部自带锁，是**跨线程传数据的标准做法**。
>
> 记住这个模式：**ROS 回调 + 子线程协作 = 用 Queue 或锁**。后面 Qt 那个例子用的是另一种更优雅的方案（信号槽）。

> 💡 **知识点：`create_publisher` 的第三个参数是什么**
>
> 那个 `10` 不是"缓冲区大小"这么简单，它是 **QoS（服务质量）的队列深度**。ROS 2 的通信质量由 QoS 策略控制，最常用的两项是：
>
> - **可靠性（Reliability）**：默认 `RELIABLE`（保证送达，丢包会重传）；可改为 `BEST_EFFORT`（尽力而为，适合高频传感器数据，如摄像头、激光雷达）
> - **历史深度（History Depth）**：默认 `10`，即最多缓存 10 条待发消息，超出后丢最旧的
>
> 发布者和订阅者的 QoS **必须兼容**才能通信。如果你遇到"话题明明对，就是收不到消息"，八成是 QoS 不匹配——用 `ros2 topic info /话题名 --verbose` 对比两边的 QoS 设置。

接收节点如下：

```python
import espeakng          # 注意：PyPI 包名是 py-espeak-ng，不是 espeakng（见下方说明）
import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from queue import Queue
import threading
import time

class NovelSubNode(Node):
    def __init__(self, node_name):
        super().__init__(node_name)
        self.get_logger().info(f'{node_name} 启动！')

        self.novels_queue_ = Queue()

        # 创建订阅者：参数依次为 (消息类型, 话题名, 回调函数, QoS 队列深度)
        # 消息类型和话题名必须与发布端完全一致，否则收不到
        self.novel_subscriber_ = self.create_subscription(
            String, 'novel', self.novel_callback, 10)

        # 朗读很耗时（一句话要好几秒），绝不能放在回调里做，否则会卡住整个 spin
        # 所以单独开一个线程专职朗读
        self.speech_thread = threading.Thread(target=self.speak_thread, daemon=True)
        self.speech_thread.start()

    def novel_callback(self, msg):
        # 订阅回调要尽可能快：这里只做"入队"这一件事，立刻返回
        self.novels_queue_.put(msg.data)

    def speak_thread(self):
        # 这个函数跑在子线程里
        speaker = espeakng.ESpeakNG()
        speaker.voice = 'zh'          # 指定中文发音

        while rclpy.ok():             # rclpy.ok() 在 shutdown 后变 False，循环随之退出
            if self.novels_queue_.qsize() > 0:
                text = self.novels_queue_.get()
                self.get_logger().info(f'读：{text}')
                speaker.say(text, sync=True)   # sync=True：等这句话读完再返回，否则会叠着读
            else:
                time.sleep(1)         # 队列空了就歇 1 秒，避免 while 空转把 CPU 跑满

def main():
    rclpy.init()
    node = NovelSubNode('novel_sub')
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == "__main__":
    main()
```


> ⚠️ **注意：`espeakng` 这个名字有个大坑**
>
> PyPI 上有**两个**名字相近的包，装错了会直接 `ImportError`：
>
> | 你想用的 API | 正确的 pip 包名 | 装错的后果 |
> |---|---|---|
> | `espeakng.ESpeakNG()`（本代码用的） | **`py-espeak-ng`** | — |
> | `espeakng.Speaker()` | `espeakng` | 报 `AttributeError: module 'espeakng' has no attribute 'ESpeakNG'` |
>
> 所以安装命令是：
>
> ```bash
> pip install py-espeak-ng
> sudo apt install espeak-ng      # 还需要系统层面的 espeak-ng 引擎
> ```
>
> **光 pip 装不够**，`py-espeak-ng` 只是 Python 封装，底层要调用系统的 `espeak-ng` 可执行程序。系统没装会报找不到引擎。

> ⚠️ **注意：这里同时修了两个问题**
>
> 1. **方法名拼写**：`speake_thread` → `speak_thread`（原来拼错了，虽然前后一致所以能跑，但容易误导）
> 2. **补了 `daemon=True`**：原代码没加。不加的话，主程序退出时这个线程可能还卡在 `speaker.say()` 里，导致进程**退不干净**（要再按一次 Ctrl+C）。加了 `daemon=True`，主程序一退，子线程立刻被强制结束。
>
> 另外原笔记的接收节点末尾漏了 `if __name__ == "__main__": main()`，也补上了。

原理就是创建一个发布者，发布特定类型和名字的话题，然后在另一个代码里写上接收者，指定该特定类型和名字的话题，即可接收话题里包含的信息。

```python
# 发布端：类型 String，话题名 'novel'，队列深度 10
self.novel_publisher = self.create_publisher(String, 'novel', 10)

# 订阅端：类型 String，话题名 'novel'，回调 self.novel_callback，队列深度 10
self.novel_subscriber_ = self.create_subscription(String, 'novel', self.novel_callback, 10)
```


> 💡 **知识点：话题通信的三个"必须一致"**
>
> 发布端和订阅端要能通上，**消息类型**和**话题名**必须一致（QoS 要兼容）。这也是为什么后面自定义接口时，`.msg` 文件一改，所有用它的节点都得重新编译。

现在写一个对海龟节点进行控制的发布者的示例：

海龟运动就是通过发布 `/turtle1/cmd_vel` 这个 Twist 话题控制的。从 `geometry_msgs` 消息包中导入 Twist 消息类型。Twist 用于描述速度。

创建一个发布者（Publisher）：

消息类型：`Twist`

话题名：`/turtle1/cmd_vel`（turtlesim 默认监听的速度话题）

队列长度：10（最多缓存 10 条待发消息）

把发布者对象保存在 `self.turtleCircle_publisher` 中，后面回调函数要用。

> 💡 **知识点：Twist 为什么能同时表示"直线走"和"转弯"**
>
> `Twist` 是**速度**消息，由两个 `Vector3` 组成：
>
> | 字段 | 含义 | 常用分量 |
> |---|---|---|
> | `linear` | 线速度（m/s） | `linear.x` 前进后退 |
> | `angular` | 角速度（rad/s） | `angular.z` 左转右转 |
>
> 二维平面里海龟只有 3 个自由度（x、y、朝向），所以实际只用 `linear.x`（前进）和 `angular.z`（转向）。**同时给这两个值，海龟就会走弧线**——这正是下面画圆代码的原理。

**疑惑点：为什么是 `from geometry_msgs.msg import Twist`？**

首先 `ros2 topic list` 查看所有话题，`ros2 topic info 话题名`

输出

```text
Type: geometry_msgs/msg/Twist
Publisher count: 0
Subscription count: 1
```


看到 `geometry_msgs/msg/Twist` 就说明：

包名：`geometry_msgs`

消息名：`Twist`

导入写法：`from geometry_msgs.msg import Twist`

查看消息的字段结构

`ros2 interface show geometry_msgs/msg/Twist`

输出

```text
Vector3  linear
        float64 x
        float64 y
        float64 z
Vector3  angular
        float64 x
        float64 y
        float64 z
```


这样你就知道 Twist 里有 linear 和 angular，各自又含 x/y/z。

> 💡 **知识点：从接口全名反推 import 语句**
>
> 这是 ROS 2 里最实用的一条推导规则：
>
> ```
> geometry_msgs/msg/Twist
> └─包名─────┘ └类型┘└消息名┘
>
> 消息：from geometry_msgs.msg import Twist
> 服务：from turtlesim.srv import Spawn
> ```
>
> 规律是 **`from 包名.msg import 消息名`**（服务则把 `.msg` 换成 `.srv`）。知道这条，你就不用死记任何 `import` 语句了——`ros2 topic info` 或 `ros2 service list -t` 一查就知道该怎么导。

接下来进入代码部分：

```python
import rclpy
from geometry_msgs.msg import Twist
from rclpy.node import Node

"""
海龟节点画圆
"""

class TurtleCircleNode(Node):
    def __init__(self, node_name):
        super().__init__(node_name)
        self.get_logger().info(f'{node_name}节点启动')

        # 发布速度指令到 turtlesim 监听的话题
        self.turtleCircle_publisher = self.create_publisher(
            Twist, '/turtle1/cmd_vel', 10)

        # 每 1 秒发布一次速度指令
        self.create_timer(1, self.timer_callback)

    def timer_callback(self):
        twist = Twist()                 # 每次都新建一条消息
        twist.linear.x = 1.0            # 前进速度 1.0 m/s
        twist.angular.z = 0.25          # 逆时针转 0.25 rad/s

        # 关键：线速度和角速度同时不为 0 → 合成运动轨迹就是一个圆
        # 半径 r = v / ω = 1.0 / 0.25 = 4.0 米
        # 改变这两个值的比例，就能改变圆的半径
        self.turtleCircle_publisher.publish(twist)
        self.get_logger().info(f'发布了话题{twist}')

def main():
    rclpy.init()
    node = TurtleCircleNode('TurtleCircleNode')
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == "__main__":
    main()
```


> 💡 **知识点：为什么每秒发一次也能持续运动**
>
> `cmd_vel` 是**速度**指令，turtlesim 收到后会一直按这个速度走，直到收到新指令。所以定时器只要**持续重复发**同一条指令即可（这里的 1 秒是刷新周期，也是"保活"）。
>
> 反过来说：**如果发布者挂了，海龟会继续按最后一次的速度走**，不会自动停。实际机器人上必须做"心跳丢失就急停"的保护。
>
> 补充：`twist.linear.y`、`twist.linear.z` 等没赋值的字段默认是 0，所以不需要显式写。

### 自定义接口以及 QT 的 Python 使用

首先我们自定义通信接口。

创建一个 C++ 版本的包：

```bash
ros2 pkg create status_interfaces \
    --build-type ament_cmake \
    --dependencies builtin_interfaces rosidl_default_generators \
    --license Apache-2.0
```


> ⚠️ **原笔记这里没写 `--build-type ament_cmake`**。虽然它正好是默认值所以能跑，但**定义消息接口的包必须是 `ament_cmake`**，显式写出来能避免以后照抄时出错。

结构如下

```bash
status_interfaces/
├── CMakeLists.txt
├── include
│   └── status_interfaces
├── LICENSE
├── package.xml
└── src
└── msg                  # 需要自己新建，与 CMakeLists.txt 同级
    └── SystemStatus.msg
```


新建一个 `msg` 目录，在目录下创建接口声明文件 `SystemStatus.msg`，写入如下内容：

```msg
builtin_interfaces/Time stamp   # 记录时间戳
string host_name                # 主机名
float32 cpu_percent             # CPU 使用率(%)
float32 memory_percent          # 内存使用率(%)
float32 memory_total            # 内存总大小(MB)
float32 memory_available        # 剩余内存(MB)
float64 net_sent                # 网络发送数据总量(MB)
float64 net_recv                # 网络数据接收总量(MB)
```


`include` 和 `src` 目录可删，因为只是定义接口，一般用不到。

> ⚠️ **注意两处拼写**（已在上面修正）：
>
> 1. 文件名 `SyStemStatus.msg` → **`SystemStatus.msg`**。文件名 = 消息名，**首字母必须大写，其余不能有大写错位**，否则 `import SystemStatus` 会失败。
> 2. 字段名 `cup_percent` → **`cpu_percent`**（CPU 不是 CUP）。
>    这个错尤其要注意：下面 Python 代码里写的是 `msg.cpu_percent`，如果你照着原笔记建 `.msg`，运行时会直接报 `AttributeError`。
>    原笔记后面 `ros2 interface show` 的输出里显示的是正确的 `cpu_percent`，说明只是文档里的笔误。

> 💡 **知识点：`.msg` 文件的书写规则**
>
> ```msg
> 字段类型 字段名    # 注释
> ```
>
> 几条硬性规则：
>
> | 规则 | 说明 |
> |---|---|
> | 字段名用 **snake_case** | `cpu_percent`，不能写 `cpuPercent` |
> | 消息名用 **CamelCase** | `SystemStatus`，文件名必须与之一致 |
> | 类型可以是内置类型或其它包的消息 | `float32`、`string`、`int32[]`，或 `builtin_interfaces/Time`、`sensor_msgs/Image` |
> | `#` 后面是注释 | 可以写在行尾 |
> | 数组用 `[]` | `int32[] top` 表示变长数组 |
> | 常量用 `=` | `int8 SUCCESS = 1`（只能用在 `.srv`/`.msg` 里，值不能改） |
>
> **不要写 `;` 结尾**，也不要写 C++ 类型（`double` 要写 `float64`）。

之后在 `CMakeLists.txt` 的 `# find dependencies` 下写入如下内容：

```cmake
# find dependencies
find_package(ament_cmake REQUIRED)
find_package(builtin_interfaces REQUIRED)
find_package(rosidl_default_generators REQUIRED)

# rosidl_generate_interfaces 是 CMake 函数，来自 rosidl_default_generators
# 作用：把 .msg / .srv / .action 接口定义文件生成对应语言的代码（Python 类、C++ 头文件）
rosidl_generate_interfaces(${PROJECT_NAME}
    "msg/SystemStatus.msg"
    DEPENDENCIES builtin_interfaces   # 用到了 builtin_interfaces/Time，必须声明
)
```


> ⚠️ **原笔记把 `ament_cmake` 拼成了 `ament_camke`**（已修正）。这种拼写错误会导致 CMake 配置阶段直接失败，报 `Could not find a package configuration file provided by "ament_camke"`。

另外在 `package.xml` 声明：

```xml
<member_of_group>rosidl_interface_packages</member_of_group>
```


> 💡 **知识点：这三行分别解决什么问题**
>
> | 写在哪 | 内容 | 作用 |
> |---|---|---|
> | `package.xml` | `<depend>builtin_interfaces</depend>` 等 | 声明**依赖**，让 colcon 知道构建顺序 |
> | `package.xml` | `<member_of_group>rosidl_interface_packages</member_of_group>` | 告诉 ROS：**这个包里定义了消息接口**，其它包才能通过 `ros2 interface show` 找到它 |
> | `CMakeLists.txt` | `rosidl_generate_interfaces(...)` | 真正**生成代码** |
>
> 三者缺一不可。最常见的报错 `Package 'xxx' not found` 或 `ros2 interface show` 查不到，基本都是漏了 `member_of_group` 这一行。

`colcon build` 创建即可，之后运行 `setup.bash` 后 `ros2 interface show <接口名>` 查看即可。

显示如下内容即可：

```bash
ros2 interface show status_interfaces/msg/SystemStatus
```

builtin_interfaces/Time stamp #记录时间戳
        int32 sec
        uint32 nanosec
string host_name  #主机名
float32 cpu_percent #cpu使用率
float32 memory_percent #内存使用率

> 💡 **知识点：为什么 `Time` 会展开成 sec 和 nanosec**
>
> `builtin_interfaces/Time` 是 ROS 2 的内置类型，只有两个字段：
>
> | 字段 | 类型 | 含义 |
> |---|---|---|
> | `sec` | `int32` | 秒 |
> | `nanosec` | `uint32` | 纳秒（0 ~ 999999999） |
>
> 注意 **`1MB = 8Mb`** 这条注释：**M**B 是字节（Byte），**M**b 是比特（bit），1 Byte = 8 bit。网卡和运营商按 **Mb** 宣传带宽（比如"100M 宽带"），而 `psutil` 统计的是 **Byte**。做限速/带宽换算时这里是 8 倍关系，搞混了会差 8 倍。

之后我们就在代码里使用接口。

创建一个新的 Python 包叫 `status_publisher`，编写代码：

```bash
ros2 pkg create status_publisher \
    --build-type ament_python \
    --dependencies rclpy status_interfaces \
    --license Apache-2.0
```


> ⚠️ **原笔记写的是 `status_interface`（少了 s）**，已修正为 `status_interfaces`。依赖名写错会导致构建时找不到包。

```python
import rclpy
from rclpy.node import Node
from status_interfaces.msg import SystemStatus   # 自定义接口的导入方式
import psutil
import platform


class SysStatusPub(Node):
    def __init__(self, node_name):
        super().__init__(node_name)

        # 发布自定义消息类型到话题 sys_status
        self.status_publisher_ = self.create_publisher(
            SystemStatus, 'sys_status', 10
        )
        # 每 1 秒采集并发布一次
        self.timer_ = self.create_timer(1.0, self.timer_callback)

    def timer_callback(self):
        # psutil 是跨平台系统信息库，直接读本机状态
        cpu_percent = psutil.cpu_percent()            # CPU 使用率(%)，注意首次调用返回 0.0
        memory_info = psutil.virtual_memory()         # 内存信息对象
        net_io_counters = psutil.net_io_counters()    # 网络收发计数器

        msg = SystemStatus()                          # 实例化自定义消息
        # get_clock().now() 取 ROS 时间（不是系统时间），to_msg() 转成 ROS 的 Time 消息
        msg.stamp = self.get_clock().now().to_msg()
        msg.host_name = platform.node()               # 取主机名
        msg.cpu_percent = cpu_percent

        # psutil 返回的单位是「字节」，这里统一换算成 MB
        # 1 MB = 1024 * 1024 字节（注意：这也是为什么硬盘厂商标的容量"偏小"——他们按 1000 算）
        msg.memory_percent = memory_info.percent
        msg.memory_total = memory_info.total / 1024 / 1024
        msg.memory_available = memory_info.available / 1024 / 1024
        msg.net_sent = net_io_counters.bytes_sent / 1024 / 1024
        msg.net_recv = net_io_counters.bytes_recv / 1024 / 1024

        self.get_logger().info(f'发布: {str(msg)}')
        self.status_publisher_.publish(msg)


def main():
    rclpy.init()
    node = SysStatusPub('sys_status_pub')
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```


> 💡 **知识点：为什么 `psutil.cpu_percent()` 第一次调用总是 0.0**
>
> 它算的是"距上次调用**之间**的平均使用率"。第一次调用没有参照点，所以返回 0.0。惯例做法是程序启动时先"热身"调一次、丢弃结果：
>
> ```python
> psutil.cpu_percent()          # 热身，丢弃
> time.sleep(0.1)
> real_value = psutil.cpu_percent()   # 这次才是真实值
> ```
> 因为这里是每秒调用一次，第二秒开始就正常了，所以原代码没处理也没大问题——但你知道原因，排查时就不会困惑。

> 💡 **知识点：`builtin_interfaces/Time` 存 MB 用 `float32` 够吗**
>
> 够。`float32` 能**精确表示所有整数**直到 2²⁴ = 16,777,216。内存总量按 MB 算是几万，远小于这个数，不会有精度损失。
>
> 但更规范的做法是用 `uint64` 直接存**字节数**，既没有精度问题，也不用在两端反复换算单位。这是设计接口时可以留意的细节。

> ⚠️ **原笔记写的是 `ros topic echo`（少了 `2`）**，已修正。
>
> 💡 **为什么"要带着接口一起部署"**：`status_publisher` 依赖 `status_interfaces`，而 ROS 2 在运行时是**按包名去找生成的 Python 模块**的。如果只 source 了 `status_publisher` 而没 source `status_interfaces`（或者后者没编译），`from status_interfaces.msg import SystemStatus` 就会 `ModuleNotFoundError`。**改了 `.msg` 文件后，所有依赖它的包都要重新 `colcon build`**。

### QT 的使用

**第一个 QT 界面**

```python
import sys
from PyQt5.QtWidgets import QApplication, QWidget, QLabel, QVBoxLayout, QPushButton

def main():
    # 创建 QApplication 对象
    # 每个 Qt 程序有且只有一个 QApplication，必须在创建任何控件之前创建
    app = QApplication(sys.argv)

    label = QLabel()
    label.setText('Hello Qt!')     # 注意：是调用方法，不是赋值！
    label.show()                   # show() 才会真正显示窗口

    sys.exit(app.exec_())          # 进入 Qt 事件循环；窗口关闭时返回退出码

if __name__ == '__main__':
    main()
```


> ⚠️ **原笔记有两处会直接报错/失效的问题**（已修正）：
>
> **1. `from pyQt5.QtWidgets` 大小写错误**
> 正确的是 **`PyQt5`**（大写 P、大写 Q）。Python 在 Linux 下**严格区分大小写**，写成 `pyQt5` 会 `ModuleNotFoundError`。
> 顺带一提：PyQt5 是 **GPL 商业双许可**，如果你要做闭源商业项目，可以考虑 `PySide6`（Qt 官方，LGPL），API 几乎一样。
>
> **2. `label.setText = ('Hello Qt!')` —— 这是最经典的 Python 陷阱**
> ```python
> label.setText = ('Hello Qt!')   # ❌ 把 setText 这个方法「替换」成了一个字符串
> label.setText('Hello Qt!')      # ✅ 调用方法
> ```
> 加号 `=` 让它变成了**赋值**：`label.setText` 从此不再是一个函数，而是一个字符串。界面会一片空白，且后续任何调用都会报 `TypeError: 'str' object is not callable`。
> **括号本身不会调用函数，`()` 才是调用运算符。**

**接收并用 QT 显示**

```python
import sys
import threading

import rclpy
from rclpy.node import Node
from status_interfaces.msg import SystemStatus

from PyQt5.QtWidgets import (QApplication, QWidget, QLabel,
                             QVBoxLayout, QGridLayout)
from PyQt5.QtCore import pyqtSignal, QObject, Qt


# ─────────────────────────────────────────────
# 1. ROS2 节点：收到消息后发 Qt 信号
# ─────────────────────────────────────────────
class RosSignalBridge(QObject):
    """把 ROS2 回调的数据通过 Qt 信号转发给界面"""
    # 定义一个信号，参数类型是 object（可以承载任意 Python 对象，这里装 SystemStatus）
    status_received = pyqtSignal(object)


class SysStatusSub(Node):
    def __init__(self, node_name, bridge: RosSignalBridge):
        super().__init__(node_name)
        self.bridge = bridge
        self.subscription_ = self.create_subscription(
            SystemStatus, 'sys_status', self.listener_callback, 10
        )

    def listener_callback(self, msg: SystemStatus):
        # 注意：这里是 ROS2 子线程，不能直接操作 Qt 控件
        # emit 只是「发射信号」，Qt 会自动把它排队投递到界面所在的主线程
        self.bridge.status_received.emit(msg)


# ─────────────────────────────────────────────
# 2. Qt 界面
# ─────────────────────────────────────────────
class StatusWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("系统状态监控")
        self.resize(420, 300)

        # 用网格布局显示各字段：第 0 列是标题，第 1 列是数值
        layout = QGridLayout()
        self.labels = {}     # 保存「字段名 → QLabel 控件」，方便后面更新
        fields = [
            ("host_name",        "主机名"),
            ("cpu_percent",      "CPU 使用率 (%)"),
            ("memory_percent",   "内存使用率 (%)"),
            ("memory_total",     "内存总量 (MB)"),
            ("memory_available", "可用内存 (MB)"),
            ("net_sent",         "发送总量 (MB)"),
            ("net_recv",         "接收总量 (MB)"),
        ]
        for row, (key, title) in enumerate(fields):
            layout.addWidget(QLabel(f"{title}："), row, 0)   # 左列：静态标题
            value_label = QLabel("--")                       # 右列：待更新的数值
            value_label.setAlignment(Qt.AlignRight)          # 右对齐，数字才对得齐
            layout.addWidget(value_label, row, 1)
            self.labels[key] = value_label

        self.setLayout(layout)

    def update_status(self, msg: SystemStatus):
        """在主线程被调用，安全更新界面"""
        self.labels["host_name"].setText(msg.host_name)
        self.labels["cpu_percent"].setText(f"{msg.cpu_percent:.1f}")        # 保留 1 位小数
        self.labels["memory_percent"].setText(f"{msg.memory_percent:.1f}")
        self.labels["memory_total"].setText(f"{msg.memory_total:.0f}")      # 不保留小数
        self.labels["memory_available"].setText(f"{msg.memory_available:.0f}")
        self.labels["net_sent"].setText(f"{msg.net_sent:.2f}")              # 保留 2 位小数
        self.labels["net_recv"].setText(f"{msg.net_recv:.2f}")


# ─────────────────────────────────────────────
# 3. 主程序：ROS2 子线程 + Qt 主线程
# ─────────────────────────────────────────────
def main():
    # 先初始化 ROS2
    rclpy.init()

    # Qt 应用（必须在主线程创建）
    app = QApplication(sys.argv)

    # 信号桥 + 界面
    bridge = RosSignalBridge()
    window = StatusWindow()
    # 关键：连接信号与槽。
    # 因为「发射方」在 ROS 子线程、「接收方」在主线程，Qt 会自动使用
    # QueuedConnection（排队投递），这就等价于把更新操作安全地送回主线程执行。
    bridge.status_received.connect(window.update_status)

    # 创建订阅节点
    node = SysStatusSub('sys_status_gui_sub', bridge)

    # ROS2 放到后台线程 spin
    # 必须放子线程：rclpy.spin 是阻塞的，放主线程的话窗口根本显示不出来
    ros_thread = threading.Thread(target=rclpy.spin, args=(node,), daemon=True)
    ros_thread.start()

    # 显示界面，进入 Qt 事件循环
    window.show()

    try:
        exit_code = app.exec_()      # 阻塞在 Qt 事件循环，直到窗口关闭
    finally:
        # 退出清理：无论正常关闭还是异常，都保证资源被释放
        node.destroy_node()
        rclpy.shutdown()

    sys.exit(exit_code)

if __name__ == '__main__':
    main()
```


> 💡 **知识点：为什么不能直接在 ROS 回调里改 Qt 控件**
>
> Qt 有一条铁律：**所有 UI 控件的操作必须在主线程完成**。ROS 2 的订阅回调跑在 spin 线程里（这里是子线程），直接 `label.setText()` 会出随机崩溃或界面卡死——而且是**偶发**的，最难查的那类 bug。
>
> 这个例子给出的解法是**信号槽 + 自动排队**，这套机制值得完整理解：
>
> | 步骤 | 发生了什么 |
> |---|---|
> | `pyqtSignal(object)` | 在 `QObject` 子类上定义信号 |
> | `signal.connect(slot)` | 把信号连到槽函数 |
> | 子线程 `signal.emit(msg)` | **不直接调用**槽函数，而是把一次调用「打包」投递到接收者所在线程的事件队列 |
> | 主线程事件循环 | 从队列取出，**在主线程**执行 `update_status` |
>
> 条件是：`connect` 时 Qt 发现收发双方**线程不同**，自动选用 `QueuedConnection`。如果两边同线程则是直接调用（`DirectConnection`）——**同一份代码，Qt 自动判断**，这正是信号槽最省心的地方。
>
> 对比一下前面小说朗读用的 `Queue` 方案：Queue 也能跨线程传数据，但**"谁来取、什么时候取"要自己写循环**；信号槽把这件事交给了 Qt 事件循环，代码更短。两种方案都值得掌握。

> 💡 **知识点：ROS 2 + GUI 的标准骨架**
>
> 所有 ROS 2 桌面程序（Qt、Tkinter、Web 后端）都是这个结构，记下来能套用：
>
> ```
> 主线程：GUI 事件循环（app.exec_）
> 子线程：rclpy.spin(node)     ← daemon=True
> 桥接：  信号槽 / Queue / 定时轮询
> 退出：  destroy_node() + rclpy.shutdown() 放在 finally
> ```
>
> 反过来（ROS 在主线程、GUI 在子线程）是**不行**的——Qt 控件必须在主线程创建和操作。

在 `setup.py` 里部署这个节点再运行即可。

> ⚠️ **别忘了两件事**：
> 1. `package.xml` 里要声明 `<depend>python3-pyqt5</depend>`（或 `PyQt5`），否则换台机器装不上。
> 2. Qt 节点**必须在本机图形界面下运行**，通过 SSH 或 Docker 跑会报 `could not connect to display`，需要 `-X` 转发或 Xvfb 虚拟显示。
