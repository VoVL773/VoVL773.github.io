前面讲的都是"数据怎么传"，TF 解决的是另一个问题：**数据在哪个坐标系里**。

### 1、TF 是什么

机器人上每个部件都有自己的坐标系（frame）：

```
        base_link          ← 车体中心
       ┌────┼────┐
   base_laser  imu  camera_link
```


TF 维护的就是这些坐标系之间的**变换关系树**。典型用途：

- 激光雷达测到一个障碍物在 `base_laser` 下的坐标是 (1.0, 0.0)，但导航算法需要知道它在 `base_link`（甚至 `map`）下是哪儿 → 靠 TF 换算
- rviz 里能把机器人模型、点云、地图**对齐显示**，也是靠 TF

> 💡 **知识点：静态变换 vs 动态变换**
>
> | | 静态变换 | 动态变换 |
> |---|---|---|
> | 话题 | `/tf_static` | `/tf` |
> | 变化吗 | 安装好就不动了 | 实时变化 |
> | 例子 | 雷达装在车体上的固定偏移 | 轮子转动、机械臂关节、里程计 |
> | 发布方式 | `static_transform_publisher` 一条命令 | 自己写节点，定时器里持续发 |
>
> 判断口诀：**两个部件的相对位置会不会变？不会就是静态。**

### 2、发布静态变换：`static_transform_publisher`

```bash
ros2 run tf2_ros static_transform_publisher \
  --x 0.1 --y 0.0 --z 0.2 \
  --roll 0.0 --pitch 0.0 --yaw 0.0 \
  --frame-id base_link --child-frame-id base_laser
```


参数说明：

| 参数 | 含义 |
|---|---|
| `--x --y --z` | 平移量，单位**米** |
| `--roll --pitch --yaw` | 旋转量，单位**弧度**（rad） |
| `--frame-id` | **父**坐标系 |
| `--child-frame-id` | **子**坐标系 |

上面这条命令的意思是：**激光雷达装在车体中心前方 0.1 米、上方 0.2 米处**。

实测输出：

```
[INFO] [static_transform_publisher_xxx]: Spinning until stopped - publishing transform
translation: ('0.100000', '0.000000', '0.200000')
rotation: ('0.000000', '0.000000', '0.000000', '1.000000')
```


最后那四个数是四元数 `(x, y, z, w)`，`(0,0,0,1)` 表示**没有旋转**。

> ⚠️ **两处极易踩的坑**
>
> **1. 旋转单位是弧度，不是角度。**
> 想转 90°，得写 `--yaw 1.5708`（= π/2）而不是 `--yaw 90`。
> 记不住就用四元数直接填 `--qx --qy --qz --qw`。
>
> **2. `--` 不能漏。** 少写一个短横线就会报：
> ```
> error parsing command line arguments: Extra unparsed arguments on command-line
> ```

> 💡 **知识点：为什么用 `static_transform_publisher` 不需要写代码**
>
> 它内部就是创建了一个节点，往 `/tf_static` 发**一条**消息，然后一直挂着（latched）。
> 消息只发一次，但因为是 `TRANSIENT_LOCAL` QoS，**后启动的节点也能收到**——这正是"静态"的体现。

> 💡 **知识点：父子方向怎么定**
>
> `--frame-id base_link --child-frame-id base_laser` 读作：
>
> ```
> base_link  ──(x=0.1, z=0.2)──▶  base_laser
>   （父）                            （子）
> ```
>
> **箭头方向 = 从父指向子。** 反过来写（父=laser、子=base_link）会让整棵树颠倒，rviz 里表现就是机器人模型上下颠倒或位置乱飞。
>
> 判断方法：**"子"是那个相对"父"有固定偏移的东西。** 雷达相对车体有偏移，所以雷达是子。

### 3、查询两个坐标系的关系：`tf2_echo`

```bash
ros2 run tf2_ros tf2_echo base_link base_laser
```


持续打印 `base_link` → `base_laser` 的变换，包括平移、旋转（四元数和欧拉角两种表示）。

> 💡 **排查套路**：`tf2_echo` 报错说"找不到某个 frame"时，**第一件事是跑 `view_frames` 看两个坐标系在不在同一棵树上**（见下一节）。

### 4、可视化整棵树：`view_frames`

```bash
ros2 run tf2_tools view_frames
```


它会监听 tf 几秒，然后生成一张**坐标系树状图**的 PDF。

**默认产物落在「当前工作目录」**，文件名带时间戳：

```
frames_2026-09-24_10.49.05.gv     ← Graphviz 源文件
frames_2026-09-24_10.49.05.pdf    ← 最终图
```


**想指定输出位置，用 `-o`：**

```bash
mkdir -p ~/tf图
ros2 run tf2_tools view_frames -o ~/tf图/frames
# 生成 ~/tf图/frames.gv 和 ~/tf图/frames.pdf
```


> ⚠️ **`-o` 后面给的是「不带扩展名的前缀」**，`.gv` 和 `.pdf` 由它自己补上。
> 而且**目录必须事先存在**，它不会自动创建。

**完整参数：**

```bash
ros2 run tf2_tools view_frames --help
#   -t, --wait-time   监听 tf 的秒数（默认 5.0）
#   -o, --output      输出文件名（不带扩展名）
```


坐标系多、广播频率低的时候，5 秒可能收不全，用 `-t 10` 加长。

**依赖与前置条件：**

```bash
sudo apt install graphviz        # 需要 dot 命令才能生成 PDF
sudo apt install ros-jazzy-tf2-tools
```


> 💡 **知识点：为什么会卡在 `service not available`**
>
> `view_frames` 内部调一个叫 `tf2_frames` 的服务。这个服务**不是独立节点提供的**，而是 `tf2_ros.Buffer` 创建时自动注册的。
> 换句话说：**你至少得有一个节点在正常收发 tf**，这个服务才存在。完全没有 tf 活动时会一直等，这是正常的。

#### 图怎么读

生成的 PDF 长这样：

```
                  view_frames Result
          Recorded at time: 1790218145.6626148

                     ╭───────────╮
                     │ base_link │
                     ╰─────┬─────╯
                           │  Broadcaster: default_authority
                           │  Average rate: 10000.0
                           │  Buffer length: 0.0
                           │  Most recent transform: 0.0
                           │  Oldest transform: 0.0
                           ▼
                     ╭────────────╮
                     │ base_laser │
                     ╰────────────╯
```


**箭头方向 = 父 → 子。** 树顶上的是根，往下是各级子坐标系。

四个标注字段的含义：

| 字段 | 说明 |
|---|---|
| `Broadcaster` | 发布者身份。`static_transform_publisher` 没设置这个字段，显示 `default_authority`，**不是错误** |
| `Average rate` | 该变换的发布频率（Hz） |
| `Buffer length` | 缓存了多少秒的历史 |
| `Most/Oldest transform` | 最新/最旧一条变换的时间戳 |

> ⚠️ **静态变换的这几个数字都没有参考价值**
>
> 因为 `/tf_static` 只在启动时发一次，tf2 算不出真实频率，于是给了个占位值：
>
> | 字段 | 静态变换显示 | 说明 |
> |---|---|---|
> | `Average rate` | `10000.0` | 假的，**不是真的 10000 Hz** |
> | `Buffer length` | `0.0` | 静态变换不分时间 |
> | `Most/Oldest transform` | `0.0` | 表示"对所有时间都有效" |
>
> **只有动态变换的这些数字才有意义**——那时 `Average rate` 能告诉你里程计是不是在按预期频率发布。

#### 图的真正用处：看树的「形状」

`view_frames` 最大的价值不是看单个变换，而是**一眼看出整棵树有没有长歪**。健康的树：

```
        base_link
       ┌────┼────┐
   laser  imu  camera
```


两种**有问题**的形态：

| 坏形态 | 症状 | 常见原因 |
|---|---|---|
| **两个独立的根** | 树断成两截，中间没有连线 | 缺少连接两部分的变换（比如忘了发 `base_link → odom`） |
| **出现环** | a→b→c→a | 配置错误，同一个 frame 被两个父节点认领 |

> 💡 **规则：TF 树必须是一棵「树」**——每个坐标系**只能有一个父节点**，但可以有多个子节点。

### 5、`/tf` 和 `/tf_static` 的坑：为什么 echo 出好几条一样的

先看 `/tf_static` 的 QoS：

```bash
ros2 topic info /tf_static --verbose
```


```
Durability: TRANSIENT_LOCAL      ← 关键
Reliability: RELIABLE
```


`TRANSIENT_LOCAL`（俗称 **latched**）的含义是"**晚加入的订阅者也能拿到最后一条**"。而关键在于：

> **这个"最后一条"是每个发布者各自留一份的。**

```
发布者A ──┐
          ├──► /tf_static  (TRANSIENT_LOCAL)
发布者B ──┘

新订阅者接入 → 分别向 A、B 各要一份"最后一条"
            → 收到 2 条，哪怕内容一模一样
```


**所以：`ros2 topic echo /tf_static` 显示几条消息 = 当前有几个发布者**，与内容是否重复无关。

> ⚠️ **这不只是"无害的重复"——内容不同就会出大问题**
>
> ```bash
> # 终端A：雷达在 z=0.2
> ros2 run tf2_ros static_transform_publisher --z 0.2 \
>   --frame-id base_link --child-frame-id base_laser
>
> # 终端B：改了参数，但忘了关终端A
> ros2 run tf2_ros static_transform_publisher --z 0.5 \
>   --frame-id base_link --child-frame-id base_laser
> ```
>
> tf2 会收到两条自称 `base_link → base_laser` 但数值矛盾的变换，它会：
> - 刷 `TF_OLD_DATA` 冲突告警
> - **按到达顺序和时间戳随机采用其中一条**
>
> 表现就是**时好时坏的诡异现象**——位置偶尔跳一下、rviz 里模型闪。每一步单独看都对，极难定位。
>
> **规矩：同一个 `child_frame_id` 只能有一个发布者。** 调试改参数时，一定先 `Ctrl+C` 掉旧的。

**排查方法：**

```bash
ros2 topic info /tf_static        # Publisher count 应该是 1
pgrep -af static_transform_publisher
pkill -f static_transform_publisher   # 一次性全清
```


> ⚠️ **`kill` 要注意杀对进程**
>
> `pgrep` 会同时列出**两个 PID**：`ros2 run` 的 Python 外壳，和真正干活的 C++ 二进制（`/opt/ros/jazzy/lib/tf2_ros/static_transform_publisher`）。
> **只杀外壳，子进程会活下来继续发变换。** 最可靠的是在原终端按 `Ctrl+C`，或者直接 `pkill -f`。

### 6、踩坑记录：Humble 教程 × Jazzy 系统

跟着 **Humble（Ubuntu 22.04）时代的教程**在 **Jazzy（Ubuntu 24.04）**上做，包名对不上是最常见的障碍。

**基本规律：**

```
ros-humble-XXX   →   ros-jazzy-XXX
```


大部分包换个前缀就行。但**少数包被拆分了**，需要单独查：

```bash
apt-cache search --names-only "^ros-jazzy-关键词"
```


**实例：MRPT**

教程里写 `sudo apt install ros-humble-mrpt2`，在 Jazzy 上会报 `E: 无法定位软件包`。原因是：

1. **发行版不同**：`ros-humble-*` 只存在于 `jammy` 源
2. **包被拆分**：MRPT 2.x 已经把一个大包拆成了几十个模块化小包（`mrpt-libcore`、`mrpt-libmaps`、`mrpt-libslam`……），**Jazzy 里根本没有 `mrpt2` 这个名字**

对应关系：

| 教程里的东西 | Jazzy 里装什么 | 路径 |
|---|---|---|
| MRPT 图形工具（含 **3D rotation converter**） | `ros-jazzy-mrpt-apps-gui` | `/opt/ros/jazzy/bin/3d-rotation-converter` |
| MRPT 命令行工具 | `ros-jazzy-mrpt-apps-cli` | — |
| ROS 消息接口 | `ros-jazzy-mrpt-msgs` | — |
| 自己写代码调 MRPT 库 + ROS 桥接 | `ros-jazzy-mrpt-libros-bridge` | — |
| ROS 导航/建图整合 | `ros-jazzy-mrpt-navigation` | — |

```bash
sudo apt install ros-jazzy-mrpt-apps-gui
source /opt/ros/jazzy/setup.bash
3d-rotation-converter
```


> 💡 **`3d-rotation-converter` 是干什么的**
>
> 它负责在 **yaw-pitch-roll / SO(3) 旋转矩阵 / 四元数** 之间互相换算。
>
> 和 TF 配合的用法是：**先用它试出角度，再把数值抄到 `static_transform_publisher` 命令里**。
> 左边调 yaw/pitch/roll，右边实时显示旋转矩阵和四元数——想用四元数写法时直接抄右边的 `(x, y, z, w)` 就行。

> ⚠️ **记住确认发行版**
>
> ```bash
> ros2 --version 2>/dev/null; echo $ROS_DISTRO     # 看当前发行版
> ls /opt/ros/                                      # 看装了哪些
> grep -r "packages.ros.org\|ros2/ubuntu" /etc/apt/sources.list.d/
> ```
>
> 包名的前缀必须和你的发行版一致，否则一律"无法定位软件包"。

### 8、Python 代码中的坐标变换

前面用的都是命令行工具，这一节把整条链路用代码走一遍：**静态发布器 + 动态发布器 + 监听器**，三个节点串成 `base_link → camera_link → bottle_link` 一棵树。

**先安装依赖**（`tf_transformations` 提供欧拉角 ↔ 四元数互转）：

```bash
sudo apt install ros-jazzy-tf-transformations
```


> 💡 **知识点：为什么要用 `tf_transformations`**
>
> ROS 2 的消息里旋转统一用**四元数**（`rotation.x/y/z/w`）表示，但人习惯看**欧拉角**（roll/pitch/yaw）。这个包提供两个方向的转换：
>
> ```python
> quaternion_from_euler(roll, pitch, yaw)   # → [x, y, z, w]
> euler_from_quaternion([x, y, z, w])       # → (roll, pitch, yaw)
> ```
>
> 注意两者**返回值顺序不同**：前者返回列表、顺序是 `x,y,z,w`；后者返回元组、顺序是 `roll,pitch,yaw`。
> 不装这个包就得自己手写三角函数，很容易搞错正负号。

**三个节点的分工：**

| 文件 | 发布器类型 | 负责的变换 | 发布频率 |
|---|---|---|---|
| `static_tf_broadcaster.py` | `StaticTransformBroadcaster` | `base_link → camera_link` | **只发一次** |
| `dynamic_tf_broadcaster.py` | `TransformBroadcaster` | `camera_link → bottle_link` | 1 Hz |
| `tf_listener.py` | （订阅） | 查询 `base_link → bottle_link` | 1 Hz |

static_tf_broadcaster.py

```py
import rclpy
from rclpy.node import Node
from tf2_ros import StaticTransformBroadcaster  # 静态坐标发布器
from geometry_msgs.msg import TransformStamped  # 消息接口
from tf_transformations import quaternion_from_euler  # 欧拉角转四元数函数
import math

class StaticTFBroadcaster(Node):
    def __init__(self):
        super().__init__('static_tf2_broadcaster')
        self.static_broadcaster_ = StaticTransformBroadcaster(self)
        self.publish_static_tf()

    def publish_static_tf(self):
        transform = TransformStamped()
        transform.header.stamp = self.get_clock().now().to_msg()
        transform.header.frame_id = 'base_link'
        transform.child_frame_id = 'camera_link'
        transform.transform.translation.x = 0.5
        transform.transform.translation.y = 0.3
        transform.transform.translation.z = 0.6
        rotation_quat = quaternion_from_euler(math.radians(180), 0.0, 0.0)
        transform.transform.rotation.x = rotation_quat[0]
        transform.transform.rotation.y = rotation_quat[1]
        transform.transform.rotation.z = rotation_quat[2]
        transform.transform.rotation.w = rotation_quat[3]
        self.static_broadcaster_.sendTransform(transform)
        self.get_logger().info(f'发布TF: {transform}')


def main(args=None):
    rclpy.init(args=args)
    static_tf_broadcaster = StaticTFBroadcaster()
    rclpy.spin(static_tf_broadcaster)
    rclpy.shutdown()


if __name__ == '__main__':
    main()

```


dynamic_tf_broadcaster.py

```py
import rclpy
from rclpy.node import Node
from tf2_ros import TransformBroadcaster  # 动态坐标发布器
from geometry_msgs.msg import TransformStamped  # 消息接口
from tf_transformations import quaternion_from_euler  # 欧拉角转四元数函数


class DynamicTFBroadcaster(Node):
    def __init__(self):
        super().__init__('dynamic_tf2_broadcaster')
        self.dynamic_broadcaster_ = TransformBroadcaster(self)
        self.timer_ = self.create_timer(1.0, self.publish_transform)

    def publish_transform(self):
        transform = TransformStamped()
        transform.header.stamp = self.get_clock().now().to_msg()
        transform.header.frame_id = 'camera_link'
        transform.child_frame_id = 'bottle_link'
        transform.transform.translation.x = 0.2
        transform.transform.translation.y = 0.0
        transform.transform.translation.z = 0.5
        rotation_quat = quaternion_from_euler(0.0, 0.0, 0.0)
        transform.transform.rotation.x = rotation_quat[0]
        transform.transform.rotation.y = rotation_quat[1]
        transform.transform.rotation.z = rotation_quat[2]
        transform.transform.rotation.w = rotation_quat[3]
        self.dynamic_broadcaster_.sendTransform(transform)
        self.get_logger().info(f'发布TF: {transform}')


def main(args=None):
    rclpy.init(args=args)
    dynamic_tf_broadcaster = DynamicTFBroadcaster()
    rclpy.spin(dynamic_tf_broadcaster)
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

tf_listener.py

```py
import rclpy
from rclpy.node import Node
from tf2_ros import TransformListener, Buffer
from tf_transformations import euler_from_quaternion

class TfListener(Node):
    def __init__(self):
        super().__init__('tf_listener')
        self.buffer = Buffer()
        self.listener = TransformListener(self.buffer, self)
        self.create_timer(1, self.get_transform)
    def get_transform(self):
        try:
            # lookup_transform(目标坐标系, 源坐标系, 时间, 超时)
            # 返回的是「源坐标系在目标坐标系下的位姿」，即 T_base_link_bottle_link
            result = self.buffer.lookup_transform('base_link', 'bottle_link',  rclpy.time.Time(seconds=0),
            rclpy.time.Duration(seconds=1))
            transform = result.transform       # ⚠️ 原笔记拼成了 tranform（少了个 s）
            rotation_euler = euler_from_quaternion([transform.rotation.x, transform.rotation.y, transform.rotation.z, transform.rotation.w])
            self.get_logger().info(f"平移：{transform.translation}，旋转欧拉角：{rotation_euler}, 旋转四元数：{transform.rotation}")
        except Exception as e:
            self.get_logger().error(f"无法获取变换矩阵: {e}")
def main():
    rclpy.init()
    node = TfListener()
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

setup.py 添加如下

> ⚠️ **必须先补两行 import，否则 `colcon build` 直接失败**
>
> Jazzy 用 `ros2 pkg create` 生成的 `setup.py`，**开头只有一行 import**：
> ```python
> from setuptools import find_packages, setup      # 就这一行，没有 os 和 glob
> ```
> 而下面用到了 `os.path.join(...)` 和 `glob(...)`，所以必须在文件顶部补上：
> ```python
> import os
> from glob import glob
> from setuptools import find_packages, setup
> ```
> 漏掉的报错是这样的（实测）：
> ```
> NameError: name 'os' is not defined. Did you forget to import 'os'?
> Summary: 1 package failed: demo_python_tf
> ```

```python
data_files=[
        ('share/ament_index/resource_index/packages',
            ['resource/' + package_name]),
        ('share/' + package_name, ['package.xml']),
        # 把 launch 目录安装到 share/<包名>/launch/，ros2 launch 才能找到
        (os.path.join('share', package_name, 'launch'), glob('launch/*.launch.py')),
    ],

entry_points={
        'console_scripts': [
            # 可执行名 = 包名.文件名:函数名
            'static_tf_broadcaster = demo_python_tf.static_tf_broadcaster:main',
            'dynamic_tf_broadcaster = demo_python_tf.dynamic_tf_broadcaster:main',
            'tf_listener = demo_python_tf.tf_listener:main',
        ],
    },
```


之后正常 `colcon build --symlink-install`，再 `ros2 launch demo_python_tf demo_tf.launch.py` 即可。

> 💡 **知识点：`os.path.join('share', ...)` 和 `glob` 各自在干什么**
>
> - `os.path.join('share', package_name, 'launch')` → 拼出 `share/demo_python_tf/launch`。用 `os.path.join` 而不是直接写 `'share/demo_python_tf/launch'`，是为了**跨平台**（Windows 会用 `\`）。
> - `glob('launch/*.launch.py')` → 把 `launch/` 下所有匹配的文件**展开成列表**。这样以后加新 launch 文件不用改 `setup.py`。
>
> 这一条对**所有 Python 节点**都适用：**源码目录里放的文件，不在 `data_files` 里登记就不会被装进 `install/`**。图片、yaml、launch 文件都是如此。

### 9、实测结果与一个反直觉的地方

上面三个节点跑起来后，监听器实际输出（已在本机验证）：

```
[tf_listener]: 平移：(0.700, 0.300, 0.100)，旋转欧拉角：(3.1416, -0.0000, 0.0000)
```


**先看这个 `0.1`——它最容易算错。**

直觉上，两段平移直接相加就行：

```
base_link → camera_link : (0.5, 0.3, 0.6)
camera_link → bottle_link: (0.2, 0.0, 0.5)
相加（❌ 错）:              (0.7, 0.3, 1.1)
实际结果（✅ 对）:          (0.7, 0.3, 0.1)
```


x、y 都对，**只有 z 变成了 0.1 而不是 1.1**。原因是中间那个 `camera_link` 有个 **绕 X 轴 180° 的旋转**：

```
      base_link
          │  平移 (0.5, 0.3, 0.6)
          │  旋转 绕X轴 180°   ← 关键在这
          ▼
      camera_link
          │  平移 (0.2, 0.0, 0.5)
          ▼
      bottle_link
```


180° 旋转把 camera_link 的 **z 轴翻了个方向**（同时 y 也翻）。所以 `(0.2, 0, 0.5)` 这段位移到了 base_link 坐标系里变成了 `(0.2, 0, -0.5)`：

```
0.6 + (-0.5) = 0.1     ← z 是减不是加
```


> 💡 **知识点：变换不能简单相加，必须做矩阵乘法**
>
> 坐标系链上的变换要**依次相乘**：
>
> ```
> T_base_link_bottle_link = T_base_link_camera_link  ×  T_camera_link_bottle_link
> ```
>
> 每个 `T` 都是 4×4 齐次变换矩阵（3×3 旋转 + 3×1 平移）。**旋转会影响平移的表示方向**——这就是为什么"看着像加法"的地方经常算错。
>
> 验证公式（用 numpy 手算）：
> ```python
> import numpy as np, math
> def T(x, y, z, rx=0):
>     c, s = math.cos(rx), math.sin(rx)
>     M = np.eye(4)
>     M[:3, :3] = [[1,0,0], [0,c,-s], [0,s,c]]
>     M[:3, 3] = [x, y, z]
>     return M
>
> M = T(0.5, 0.3, 0.6, math.pi) @ T(0.2, 0.0, 0.5)
> print(M[:3, 3])     # → [0.7, 0.3, 0.1]  与实测一致
> ```
>
> **这个坑在实机上代价很大**：静态变换的旋转填错了，整棵树下所有传感器的数据都会偏。所以改完 `static_transform_publisher` 的参数，务必用 `tf2_echo` 或 `view_frames` 确认一下。

> 💡 **知识点：启动后头两秒报错是正常的**
>
> 实测日志开头会看到：
> ```
> [ERROR] [tf_listener]: 无法获取变换: "bottle_link" passed to lookupTransform
>         argument source_frame does not exist.
> ```
> 这是**启动竞态**：三个节点同时起，`tf_listener` 比 `dynamic_tf_broadcaster` 先就绪，那一刻 `bottle_link` 这个坐标系还没被发布出来。
>
> 等动态发布器发第一条（最多 1 秒）之后，日志就正常了。**所以代码里那个 `try/except` 不是多余的**——它就是为了扛过这段空窗期，而不是掩盖 bug。
>
> 如果想连这两秒的报错都不想看到，可以把监听器的定时器周期设长一点，或者先 `time.sleep(1)` 再开始查询。

> ⚠️ **一个可以改进的写法：`Buffer()` 建议传 node**
>
> ```python
> self.buffer = Buffer()                      # 能跑，但不带时钟
> self.buffer = Buffer(node=self)             # ✅ 推荐
> ```
>
> 构造签名是 `Buffer(cache_time=None, node=None)`，`node` 是可选参数，所以不传也能跑。但**不传 node 时 buffer 拿不到时钟**——一旦你开了仿真时间（`use_sim_time`），查询就会因为时间对不上而失败。
> 传上 node 是零成本的保险。
