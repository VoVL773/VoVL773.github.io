一个面向供应链场景的物联网平台：设备通过 MQTT over TLS 上报数据，网页端按四种角色做数据隔离，授权精确到「哪家公司的哪台设备，给哪个客户看」。

## 项目定位

不是又一个「大屏演示」，而是一套能真正把板子接进来、把数据落到库里、把权限管住的完整闭环：

- **设备侧**：每台设备独立凭证，连接时 `client_id = username = 设备 ID`，密钥只存 SHA-256 摘要，比较时用 `hmac.compare_digest`。
- **平台侧**：内嵌 `amqtt` broker 校验身份和 Topic，设备只能往自己的 `rd/devices/<设备 ID>/telemetry` 发布。
- **网页侧**：采样上报、实时读数、趋势曲线、历史查询、阈值告警，全部来自真实消息，不用模拟数据冒充实测。
- **权限侧**：平台管理员、公司管理员、开发者、客户四级角色，公司、场景、邀请码、设备授权四层隔离。

前后端、MQTT 接入、TLS 证书、部署脚本、自动化测试和中文文档都在一个仓库里，没有 Web 框架，也没有云服务依赖。

## 核心能力

- **设备接入**：MQTT over TLS（8883），每台设备独立凭证与专属 Topic。
- **四级权限**：`admin`、`company_admin`、`developer`、`customer`，全部在服务端判定，不靠隐藏按钮。
- **实时与历史**：采样上报、实时读数与曲线、历史查询、阈值告警。
- **多公司隔离**：公司、场景、成员邀请码、设备授权四层，客户不自动获得公司全部设备。
- **双模式**：后端正式平台与纯静态演示共用一套前端；正式模式禁用演示账号。
- **一键安装**：`install.py` 交互式安装，自动建虚拟环境、生成 TLS 证书与启动脚本。

## 技术栈

- **后端**：Python 3.11+ 标准库 `http.server`。零 Web 框架，部署即一个进程，依赖面最小。
- **实时通信**：`amqtt`（内嵌 broker）+ `paho-mqtt` over TLS。设备侧协议统一，断线可重连。
- **存储**：SQLite。单文件、免运维，便于整库备份与迁移。
- **前端**：原生 HTML / CSS / JavaScript。无构建步骤，改完刷新即可。
- **部署**：systemd + Nginx + Certbot（或内置 HTTPS）。一键安装与标准服务器部署两条路径。
- **测试**：`unittest` + Node 前端契约测试。覆盖权限边界与接口契约。

## 工程规模

- 约 **2600 行核心代码**，8 个前端模块。
- **7 组自动化测试**：6 个 Python 测试 + 前端契约测试。
- **4 份中文文档**：零基础使用手册、项目交接指南、AI 协作规范、云端部署说明。

## 快速开始

```bash
python3 install.py        # 交互式安装：建 venv、装依赖、生成证书与启动脚本
./start-platform.sh       # 启动平台
```

只需要 Python 3.11+ 和 OpenSSL。Ubuntu 缺依赖时执行：

```bash
sudo apt install python3 python3-venv openssl
```

安装器会依次询问部署位置（本机 / 服务器）、安装目录、访问地址、HTTPS 与 MQTT TLS 端口、证书来源，最后设置平台管理员账号。本机模式只监听回环地址，服务器模式监听所有 IPv4 接口；证书同时用于网页和 MQTT。

## 设备接入流程

1. 公司管理员或开发者在「设备接入」页创建设备，填写名称、类型、安装位置和预期上报周期。
2. 平台生成设备密钥并下载 `secrets.h`，填入 Wi-Fi 名称和密码后烧录到 ESP8266 / Mega 桥接板。
3. 板子上电联网，用设备 ID 与密钥连接 MQTT over TLS，往自己的 Topic 发布真实串口数据。
4. 平台自动把「待激活」变为在线，实时值、趋势和历史记录随之出现。

密钥只在创建或重置时显示一次；重置后旧密钥立即失效，设备需要更新配置。

## 说明

- 仓库只保留 `config/*.example.json` 模板，真实域名、IP、证书与数据库路径留在各自服务器上，不随仓库分发。
- 正式模式禁用演示账号，MQTT 强制 TLS；不建议用 `curl -k` 或关闭证书校验来「先跑通」。
- 历史数据默认保留 90 天，按设备分页查询，时间以服务器接收时间为准。
